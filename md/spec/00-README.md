## 📌 TL;DR

把 **qwerty-learner**（23k+ star 的开源打字练习站）从「外语单词打字练习」扩展为「**中文输入法打字练习**」：V1 支持**全拼**与**小鹤双拼**（**先只针对音码**，音形码/五笔留口不做），在原有功能上扩展、**复用项目原来的打字体验**，但把练习内容从「学外语」换成「**输入法练习**」——**不是原先语言学习那种词库，而是可以逐步提高难度的打字**：字 → 词语 → 成语 → 句子 → 诗句 → 文章。

核心设计三句话：
1. **双轨输入判定**——对码学习轨（`code-match`，绕过系统 IME 校验编码，练字/词/成语）+ 上屏实战轨（`ime`，用真实输入法练句/诗/文章），**两套指标口径分开定义、分开标注、分开存储，不得混算，不得出现「综合分」**
2. **构建期离线预计算编码**——编码烘进词典 JSON 的 `name` 字段，**运行时零拼音库依赖**；这与日语 romaji 词典**完全同构**，是同一条数据抽象的**第三次复用**（山人码 fork 已实证：校验引擎、DB、WPM 公式**一行未动**，核心改动 <30 行）
3. **完整学习路径是唯一差异化**——韵母分组渐进课表 + 30% 已学混入（防伪掌握）+ 薄弱韵母专项队列 + 掌握度双门槛 + 反应时相对门槛 + 无提示毕业模式 + J 形曲线定位卡 + 固定文本每日复测

**核心人群 = U1 双拼迁移者（P0，唯一核心）**——`07` 的核心洞察修正了其动机：**P0 用户不是「想打快的人」，而是「想弃坑的人」**（他们已经在双拼上，问题是撑不过前 30 天，故 V1-a 的全部设计目标是「别让我放弃」而非「让我更快」）。**P0 内含三个子画像**：P0-α 理性优化者（需「解释而非激励」）/ P0-β 社区跟随者（需「渐进课表 + 掌握度可视化」）/ 🆕 **P0-γ 回流重试者（= U1-γ，需「定位测 + 跳过已掌握」，竞品全空白能力，置信度 C 待验证）**。详见 `01` §3.1。
**指标体系（✅ 已按裁定 D 分三层）**：**产品价值层北极星 = 60 天毕业率**（`08`，季度看，V1.2 才可观测）｜**V1.0 阶段门禁 = D3 当日留存率**（日看，**用「本地连续打卡日数分布」作代理指标，只能看相对趋势**）｜**能力达标口径 = Net CPM + 首次命中率**（`05`，周看，产品目标带「准确率 ≥95% 下稳定 60~90 字/分」）。
> ⚠️ **析客先前建议「D3 留存为唯一北极星」未被采纳**。主理人裁定理由：`08` 警告「若以留存为北极星，产品会被激励去优化『让用户第 4 天回来』而非『让用户学会后不再需要它』」——**这恰好构成最大产品治理风险**。析客认同此裁定，并承认自己先前的建议存在治理盲区（详见 §10.2）。

**一句话价值主张：「一个网址，从零到超越全拼」——monkeytype 不做中文输入法练习，小鹤官方没有现代 Web 练习器，我们做。**

V1 分三层共 **66 条功能**（V1-a 学习闭环内核 33 / V1-b 实战与长文 13 / V1-c 考试与专业扩展 20），**用户要求全部纳入 V1，故为内部分层而非范围裁剪**。⚠️ **`10` v3 实测该全量需 339~529 人日 / P50 约 16 个月**，**已裁定重构为 V1.0（2027-06-11）/ V1.1（2027-09-28）/ V1.2（2028-02-16）三次发布**（见 §10.3）。**前置阻塞项 2 个**：既有 `inputAccuracy` 括号 Bug（CN-J1，✅ **已裁定：修复而非删除**，PR 话术用 `10` v3 更正版）与按键捕获兼容性 Spike S1（CN-A1a）。

## 1. 项目一句话定位

> **在 qwerty-learner 现有打字体验之上，构建一个「免费、开源、纯本地、带完整学习路径」的中文输入法（全拼 / 双拼音码）练习器。**

**四个关键词的展开**：

| 关键词 | 含义 | 对应决策 |
|---|---|---|
| **免费** | 竞品收费锁定的三项能力（**错词本 / 数据报告 / 自定义文本**）**恰是 qwerty-learner 已免费开源的既有资产** → **任何功能付费墙都是自废武功**（NG-12） | D8 / `01` §7 |
| **开源** | GPL-3.0；方案表与语料均可被社区低成本扩展（**「支持新方案」= 加一份方案表 + 重跑构建脚本，不改代码**；**「贡献语料」= 只写汉字**） | D4 / D3 |
| **纯本地** | 无账号、无后端、数据全在 IndexedDB；**自定义语料导入全过程本地完成，不上传用户文本到任何服务器**（隐私红线） | `01` §9.1 TC-1 |
| **带完整学习路径** | **这是唯一差异化，不可砍**：韵母分组渐进课表 + 30% 已学混入 + 薄弱项专项队列 + 掌握度双门槛 + 无提示毕业模式 + J 形曲线定位卡 + 固定文本每日复测 | **D2** |

### 2.2 monkeytype 明确拒绝中文（生态位空缺）

**monkeytype Issue #4673**（中文输入支持）状态 **closed as not planned**，根因是其**输入校验架构与 IME composition 不兼容**，用户实测：「**This makes typing in Chinese basically impossible on Monkeytype.**」

→ **monkeytype 生态位的中文空缺至今无人填补。传播话术现成：「monkeytype 不做中文输入法练习，我们做。」**

### 2.3 小鹤官方没有现代 Web 练习器（工具分散 5 个渠道）

小鹤双拼官方生态 = **网盘里的 .NET 4.0 exe 练习器** + **QQ 群发文** + **飞扬版敲 `orm`/`oqm` 隐藏命令查文档** + **微信小程序** + **论坛贴吧**。**工具分散在 5 个渠道，无单一入口。**

→ **「一个网址，从零到超越全拼」**

### 2.4 现有竞品的结构性缺口（六个差异化机会）

| # | 机会 | 依据 |
|---|---|---|
| 1 | **monkeytype 生态位中文空缺** | Issue #4673 closed as not planned |
| 2 | **小鹤官方没有现代 Web 练习器** | 5 个渠道无单一入口 |
| 3 | **付费墙错位** | KeySpell VIP 锁错词本/数据报告/自定义文本；ulpb.app 词组与文章练习必须下客户端 + ¥69 买断挑战；TypingClub 免费版数据仅留 30 天 —— **这三项恰是 qwerty-learner 已免费开源的既有资产** |
| 4 | **开源双拼练习器的完整度与许可缺口** | `Return7-T/Shuang`（20+ 方案但**许可禁止商用**、无语料分级、UI 老旧支持 IE9）；`z1803406304/shuangpin-practice`（2026-09 首发，**功能最完整**、Vue3、892KB 单文件 HTML、81 单测 + 官方码表交叉验证 **99.649%** 一致，**但只支持小鹤一种方案、无章节/关卡体系、无游戏化、成语与诗句语料缺失**）；`HKAHYIN/PinyinType`（React 栈但定位轻） |
| 5 | **中文原生指标体系（击键/码长/回改）在 Web 产品上完全缺位** | 添雨跟打器 = 中文打字圈事实标准、小鹤官方推荐，但**Web 端无人实现** → 我方采纳即成标准制定者 |
| 6 | **「字→词→成语→句→诗→文章」六级渐进 + 章节化，无人占位** | ulpb 三层且后两层要下客户端；Shuang 两层且是割裂入口；shuangpin-practice 模式并列无章节；中文测速工具群只有 12~24 段固定范文，无分级无进度 |

### 2.5 冷启动优势：不需要拉新

qwerty-learner 存量用户画像（**程序员 / 键盘工作者 / 开源社区 / 本地隐私优先**）与双拼学习者**高度同构**——两者的讨论都集中在 **V2EX / Linux DO / 少数派**。

- **不需拉新**，只需在词典选择页点亮新入口（新增「中文·输入法练习」分类，**从首页到开始第一次中文练习点击路径 ≤3 次**，CN-I6）
- 预估吃到现有 MAU 的 **3-8%**
- 第三方评测列出的 qwerty-learner 缺点**第一条**就是「**仅限英语输入练习**」→ 本次扩展直接消除该短板

## 8. 术语表

### 8.1 双轨与判定

| 术语 | 定义 |
|---|---|
| **对码学习轨（`code-match`）** | 绕过系统 IME，捕获**原始按键**（`KeyboardEvent.code` 物理键位），按方案码表**逐字符校验编码**。无候选窗、无选词，**打对自动进下一字**。适用语料：**字 / 词 / 成语**。DB 标记 `track: 'code'` |
| **上屏实战轨（`ime`）** | 用户用**真实输入法**在输入框打字，从 `compositionend` 取 `e.data` 得到上屏文本，与目标文本做 **diff**。适用语料：**句子 / 诗句 / 文章**。DB 标记 `track: 'ime'` |
| **上屏** | 输入法把候选词提交到文本框的动作（`compositionend`）。「已上屏的字」才计分，**拼音还在组字框里时不计分** |
| **编码** | 用户为输入某个字/词实际需要敲的键序列。全拼「中」= `zhong`（5 键）；小鹤双拼「中」= `vs`（2 键） |
| **零声母** | 全拼中无声母的韵母音节（啊/哦/额/爱/恩/欧/昂…）在双拼中的补齐规则。小鹤 = **零声母方案**：单字母韵母重复（`啊=aa`）、**双字母韵母保持全拼**（`爱=ai`）、三字母韵母首字母 + 韵母键（`昂=ah`）。微软双拼不同：**O 前缀**（`爱=OI`、`昂=OH`） |
| **音码 vs 音形码** | **音码** = 只依赖读音的编码方案（全拼、双拼）。**音形码** = 音 + 字形（字根）的方案（小鹤音形、五笔）。**本项目 V1 只做音码**（边界 = 定长 2 键 + 不需拆字知识 + 不需「提笔不忘字」） |
| **`inputMode`** | 词典级新增字段，取值 `'code-match' \| 'ime'`，**可选，缺省推导为 `'code-match'`** → 现有 380 个词典零改动、零影响 |
| **依赖提示率** | 使用过提示（键位闪烁 / 看答案）的题目占比。⭐ **这是最好的学习进度指标**——应从 ~100%（Day 1）逐步降到 0%（Day 14+）。**提示过的题不计入「独立正确率」** |
| **独立正确率 / 按键正确率 / 依赖提示率** | **三分口径**，分开展示，**不得合并为「综合正确率」** |
| **IME 辅助上屏数** | 输入法纠错后上屏了正确的字的次数。**判正确，但单独计入**，与「零辅助上屏数」分开展示。⚠️ **近似统计，UI 须标注「尽力统计，仅供参考」** |

### 8.2 中文原生指标（添雨跟打器 = 中文打字圈事实标准，小鹤官方推荐）

| 术语 | 定义 | 权威参考值 |
|---|---|---|
| **击键** | **平均每秒按键次数**（范围 0~20） | **未专门练习过 0~4；爱好者 6 为入门、8 为中等、10 以上「你用什么输入法都可以秒杀普通人」** |
| **码长** | **平均每字按键次数**（总击键数 / 输入字符数，一般 2~4） | **码长越短效率越高** |
| **回改** | **退格修正次数** | — |
| **CPM（字/分）** | **每分钟打对（正确上屏）的字数** | **只计已上屏的字**；**计时从按下第一个键的瞬间开始**（不是第一个字上屏时）；**漏打或多打一个字只算一个错误，后面的字不会因此错位**；准确率 = 正确字符数 / 总输入字符数 |
| **中英换算** | **1 汉字 ≈ 2/3 英文单词** | 故 **60 字/分 ≈ 40 WPM** 的内容量（**不是除以 5 得出的 12**） |
| **速度衰减率** | `(前半程字/分 − 后半程字/分) / 前半程字/分 × 100%` | 🟢 **竞品全空白的差异化耐力指标**，需 ≥10 分钟连续练习；**<10% 给「耐力优秀」反馈** |
| **有效字数** | 考试计分口径：**打错/删除重打的字符不计入成绩** | 例：3 分钟上屏 360 字含 3 错字 → 有效速度 `(360 − 3×5)/3 = 115 字/分`（**错一罚五**，惩罚系数考场实际 5-10） |
| **击键→速度换算**（小鹤官方公式） | 全拼 `1击键×15=15字/分`（字均用键 4）｜双拼 `×20`（字均用键 3）｜音形 `×25`（字均用键 2.4） | 例：每秒击键 4 → 全拼 60 字/分、双拼 80、音形 100 |
| **核心心法**（小鹤官方原文） | 「**低码长与高击键，才能让你打出傲人的速度。只有击键高于码长的时候，你才算入门了。**」 | — |
| **指标自校验** | `字/分 ≈ 击键 × 60 / 码长` | **误差 <5%**，超出则说明埋点丢失 |

### 8.3 语料层级

| 术语 | 定义 | `inputMode` |
|---|---|---|
| **L0** | 声母 / 韵母 / 整体认读音节（**全拼才需要**，双拼跳过） | code-match |
| **L0'**（机器值 `L0p`） | ⭐ **韵母分组**（**双拼独有，核心差异点**）。6-8 组，每组 4-6 个韵母，**每组配 ≥20 个真实字词**（练 `uang` 用「黄/光/王/双」，**不是 `aaaa uuuu`**） | code-match |
| **L1** | 高频单字。**《通用规范汉字表》一级字表（3500 字，2013 年发布）**，切 **500 / 1000 / 3500** 三档（🆕 裁定 G-1：原《现代汉语常用字表》为 1988 旧表，构成不同且与 A2:611 生僻字检测不同源，已统一改口径）。**每章 10 字**（官方「10 字一组、击键过 6 换组」） | code-match |
| **L2** | 双字词组 ≥1000 条。「现代输入法 80% 以上输入动作是词组，**词组速度才是拼音打字速度的真正决定因素**」 | code-match |
| **L3** | 四字成语 ≥500 条。训练「**中途不能停**」的连续输入节奏，「最接近打真实文章的状态」。**用 code-match 的理由：成语用真 IME 会被自动补全，反而失去练习意义** | code-match |
| **L4** | 短句 ≥200 条（10-30 字）。句读节奏 + 标点入门。**短句及以上不得回滚整段** | **ime** |
| **L4-C** | ⭐ 增补：**日常聊天短句层**（口语化）。社区证明「水群、高强度真实使用」比刷题更有效。**非主力，情绪调节定位** | **ime** |
| **L5** | 古诗 / 词 ≥100 首（**公版**）。⭐ **留存利器**：「很多诗词都押韵，打起来比较爽快」。**UI 入口建议前置到 S2 阶段**。按句分行逐句输入 | **ime** |
| **L6a** 🆕 | **文言短篇 ≥12 篇（80-300 字，公版）**（裁定 G-3 新增：《陋室铭》81 字 ~《黄生借书说》200 字，A2 已给候选）。⚠️ **短篇通常一次打完，分段续打非必需** | **ime** |
| **L6b** | 文章 / 散文 ≥30 篇（**300-1500 字**，公版，须核对作者卒年 + 50 年）。长文分段续打 + 性能达标 | **ime** |
| **L6EX** | 公文 / 法律文书 ≥20 篇。标注来源与版权状态，**不得直接搬运真实未公开文书** | **ime** |
| **L7** | 标点 / 数字 / 中英混输专项。**`isChineseSymbol()` 在此模式下必须反转逻辑** | **ime** |

> 🔴 **裁定 G-3 / G-4 对本表的三条硬约束**：
> 1. **`level` 枚举共 12 档，以 `04` §2.0 总览表为唯一真源**：`L0` / `L0p`(L0') / `L1` / `L2` / `L3` / `L4` / `L4C`(L4-C) / `L5` / `L6a` / `L6b` / `L6EX` / `L7`
> 2. **序列化约定**：`L0'`→`L0p`、`L4-C`→`L4C`、`L6-a`→`L6a`、`L6-b`→`L6b`、`L6-EX`→`L6EX`（**撇号与连字符在 JSON 与 Dexie 索引里都是麻烦源，不写清实现必出 bug**）
> 3. 🔴 **`level` ≠ 难度**：`level` 只定「文体类型 / UI 展示分组」，**实际出题顺序由 `codeComplexity`（C1~C6）主导**。反例：《陋室铭》81 字（**L6a**）含大量文言虚词与生僻码元，其 `codeComplexity` **很可能高于部分 L6b 白话散文** → **不能假设「L6a 比 L6b 简单」**。同理 L6EX 公文的高频虚词密度可能低于日常散文
>
> ⚠️ **另：`L0` / `L0p` 不参与「通过率」统计**（这两档「练完即可、无强制门槛」，**无门槛就无通过率**），只有 `L1`~`L7` 共 **10 档**进入 `05` §7.2 的指标分母。
> ⚠️ **第 3 条目前存在未裁决冲突**：`codeComplexity` 的字段命名与取值被 `05` v2 反向实现，详见 **§10.7 冲突 5**（🔴 阻塞构建管线与 Dexie schema 定稿）。

| 术语 | 定义 |

| **S5 速度反超** | Day 60+。速度 **130-150%** |
| **D3 当日留存率** | ⭐ **北极星指标**。首次完成中文练习的用户中，在第 3 个自然日（±1 天窗口）再次完成至少 1 次练习的比例。**目标 ≥40%**。选 D3 的理由：**Day 3 是情绪谷底（1.5/10）+ 速度谷底（40-50%）+ 放弃峰值的三重重合点** |

| **U2 文字工作者** | 写手/编辑/程序员/文书。**P1**。诉求：长文耐力、速度衰减率、词组速度、标点混输 |

| **伪掌握陷阱（I4）** | 用户原话：「重复同键位练习时**大脑通过逻辑判断预测出了将要出现的键位**……产生了学会双拼的错觉，**真实使用时又会抓瞎**」。**解法 4 条**：新组强制混入 ≥30% 已掌握项、随机化语料不固定顺序、**反应时作为核心指标**（正确率 100% 但反应时 >2× 中位数仍算未掌握）、提供无提示模式作毕业考核 |
| **target-key 自适应** | keybr 式算法：**选出打字速度最差的键作为 target，每一个生成的练习题都必须包含它**，达标后切换下一个。迁移到双拼：**最弱韵母键必须出现在每一个练习题中** |
| **四向单键专项** | 韵母→键 / 声母→键 / 音节→声母键 / 音节→韵母键。设计理由：「完整音节练习里一个字的错误**分不清是声母想不起来还是韵母记错了**，这个模式把两部分拆开」 |
| **J 形学习曲线定位卡** | 显示标注 S1~S5 的曲线 + **用户当前所在点** + 社区经验值区间 |
| **固定文本每日复测** | 社区最推荐方法：「**同一份文本每天测 10 分钟，曲线自己看得见，比任何鸡汤都安心**」 |
| **全拼基线** | 入学前的全拼测速结果（`baselineKeystroke` / `baselineCPM`）。**小鹤官方指引第一步**。之后所有进度相对基线展示「当前双拼速度 = 基线的 62%（第 4 天，正常）」，**直接解决「比全拼还慢」的挫败流失** |
| **易错音归因 / 拼音盲区报告** | 自动识别 **8 组南方易错音**：`zh↔z`、`ch↔c`、`sh↔s`、`an↔ang`、`en↔eng`、`in↔ing`、`n↔l`、`f↔h`。**双重价值：既练键位又纠普通话** |
