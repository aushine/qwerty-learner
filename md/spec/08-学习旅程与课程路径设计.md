## 0. 一句话设计目标

> **让用户在 Day 3 不离开，在 Day 7 不误判自己，在 Day 30 知道自己毕业了。**

这三件事构成了本产品的全部体验目标。它们分别对应旅程中三个可测量的失败点（§2 情绪曲线的三个谷），也对应三组必须交付的功能（§3、§4、§5）。**除此之外的任何体验设计，都是这三件事的支撑，不是目的。**

## 1. 旅程总览：六阶段与情绪曲线

### 1.1 六阶段划分

| 阶段 | 时间轴 | 名称 | 用户的核心任务 | 对应学习阶段（07 §5.2） | 主导指标 |
| --- | --- | --- | --- | --- | --- |
| **J0** | Day −1 ~ 0 | 决策与定位 | 选对方案、定好起点、知道要多久 | S0 决策期 | onboarding 完成率 |
| **J1** | Day 1–3 | 键位冲击 | 记住 26 个键位，活过速度腰斩 | S1 键位期 | 击键、已学韵母数 |
| **J2** | Day 4–7 | 伪掌握陷阱 | 分清"我会了"和"我在猜" | S2 巩固期 | 掌握韵母数、反应时 |
| **J3** | Day 8–14 | 提速爬坡 | 把掌握变成速度 | S3 提速期 | 编码正确率、码长 |
| **J4** | Day 15–30 | 基线回归与停滞 | 追平全拼，看见结构性变化 | S3 提速期 | 速度/基线比、打词率 |
| **J5** | Day 31–60 | 毕业与实战迁移 | 从"练习"过渡到"真实输入" | S4 实战期 | 实战轨达标、长文耐力 |
| **J6** | Day 60+ | 专业化 / 考试冲刺（可选分支） | 用行业语言自我诊断，或按考试规则模拟 | S5 专业/考试期 | 六项专业指标、有效字数 |

**J6 是可选分支，不是必经阶段**。多数用户在 J5 结束后就自然离开学习闭环——**这是产品的成功，不是流失**（见 §8 北极星）。

## 2. 逐阶段体验地图

> 每阶段包含六项：**触点 / 用户目标 / 情绪状态 / 必备 UI 元素 / 反模式（禁止） / 验收指标**。
> 反模式一栏是**硬约束**，与 07 §7 的 Won't have 同源；任何设计若命中反模式，需在 01 中降级或移除。

### J0 · 决策与定位（Day −1 ~ 0）

| 项 | 内容 |
| --- | --- |
| **触点** | ① GitHub README / 社区帖（进入前）② onboarding 决策树（CN-I1）③ 方案选择页 ④ 定位测（CN-C2）⑤ 首次进入练习页 |
| **用户目标** | 「帮我决定用哪个方案、从哪里开始、大概要多久——**别让我自己做我没依据的决定**」 |
| **情绪状态** | 期待 + **决策焦虑**（四个陌生方案名词）+ 部分用户带着上次失败的阴影（P0-γ） |
| **必备 UI 元素** | ① Q1–Q4 决策树（可跳过，完整文案见 07 §6.2）② **考场兼容提示卡**（CN-F5，选小鹤且 3 年内可能机考时**强制展示 + 二次确认**）③ **可挽回性说明**（必须放在方案选择页底部）④ J 形曲线**全景预告**（在 Day 0 就让用户看见 Day 3 会掉到 40–50%——**预先告知的困难不会导致弃坑，突然出现的困难才会**）⑤ 30 秒定位测入口（可跳过）⑥ 每日时长选择 → 功能解锁分流 |
| **反模式（禁止）** | ❌ 罗列方案参数对比表（增加决策瘫痪，用户看不懂 `zeroMap` 差异）<br>❌ 强制完成问卷才能开始练习（P0-γ 会直接离开）<br>❌ **不提示考场兼容性**（用户练三周后发现考场用不了小鹤 → 产品信誉归零，这是唯一"不做的代价高于做的代价"的文案）<br>❌ 把长文耐力模块默认展示给选择"5 分钟"的用户（压迫感，见 07 洞察 7）<br>❌ 任何需要注册/登录才能开始的流程（违反 W7） |
| **验收指标** | onboarding 完成率 ≥ 70%；跳过率 ≤ 30%；**考场兼容提示卡二次确认后的方案改选率**（用于验证 CN-F5 是否真的改变了行为，目标 ≥ 30%）；定位测使用率（P0-γ 占比的代理指标） |

### J1 · 键位冲击（Day 1–3）★★★ 弃坑峰

| 项 | 内容 |
| --- | --- |
| **触点** | ① L0' 韵母表课程 ② L0 单韵母对码 ③ L1 声母+韵母组合 ④ 虚拟键盘（CN-C3）⑤ 每日结算页 ⑥ **J 形曲线定位卡**（CN-C4）⑦ **低谷期干预卡**（CN-I4）⑧ 阶段徽章（CN-I5） |
| **用户目标** | 「让我记住这 26 个键位，并且**让我相信现在的慢是正常的**」 |
| **情绪状态** | Day 1 新鲜 → Day 2 吃力 → **Day 3 谷底**：速度只有基线的 40–50%，工作/学习里被自己嫌弃，开始搜索"双拼值得学吗" |
| **必备 UI 元素** | ① **虚拟键盘实时高亮下一键位**（CN-C3，全提示状态）② **韵母渐进课表**（CN-C1，按区分组，每批 ≤5 个韵母，见 §5.2）③ **J 形曲线定位卡必须在结算页与统计页首屏可见**，显示：我的当前速度 / 我的全拼基线 / 当前进度百分比 / **文献预期带**（Day 3 ≈ 40–50% 标注为"正常区间"）④ **学习期速度衰减率**（由 **CN-C4** 承载；⚠️ 勿与 CN-E5「耐力衰减率」混淆，后者是 P1-a 的长文前后半程指标，属 J5/J6）以「与预期带的偏差」呈现，**不以「与基线的差距」呈现** ⑤ 击键（键/秒）作为**主视觉指标**——它在学习期单调向好，是唯一能给正反馈的速度分量 ⑥ 轻打卡与阶段徽章（CN-I5，本地连续天数，无社交）⑦ **Day 3 干预卡**（CN-I4，文案见 §3） |
| **反模式（禁止）** | ❌ **速度数值使用红色/警示色/下降箭头**（学习期速度必然下降，红色 = 亲手制造流失）<br>❌ 结算页第一行是"本次速度 XX 字/分"<br>❌ 整篇文章练习（认知过载，P0-β 的主要弃坑诱因）<br>❌ 任何排名、百分比位次、他人对比（W1）<br>❌ "你已经落后了""还差 X 才能达标"类文案<br>❌ **在 Day 3 推送难度更高的内容**（此时应降难 + 解释，不是加压）<br>❌ 用「连续打卡中断」制造焦虑（打卡中断的文案必须是"回来就好"，不是"你断了 N 天"） |
| **验收指标** | **Day 3 留存率**（本阶段唯一关键指标）；击键（键/秒）D1→D3 单调上升比例 ≥ 80%；已学韵母数 D3 ≥ 15/35；**定位卡在 Day 3 的曝光→查看时长**（验证用户是否真的读了预期带）；Day 3 干预卡的"我知道了"点击率 |

### J2 · 伪掌握陷阱（Day 4–7）★★ 二次门槛

| 项 | 内容 |
| --- | --- |
| **触点** | ① L2 双字词 ② 30% 混排复训（CN-C1a）③ 掌握度双门槛判定（CN-C2a）④ 提示分级衰减（CN-C3）⑤ 弱点韵母靶向（CN-C2）⑥ 韵母热力图（CN-E3）⑦ **Day 6–7 干预卡**（CN-I4） |
| **用户目标** | 「让我知道哪些是真的会了、哪些是我在猜，然后只练我不会的」 |
| **情绪状态** | Day 4–6 **假高点**（同批韵母重复练习，正确率高、反应快 → "我会了"）→ Day 6–7 **真谷**（遇到新词组立刻卡住 → 比 Day 3 更严重的挫败，因为落差来自自己的误判） |
| **必备 UI 元素** | ① **韵母掌握热力图**（CN-E3，35 格，三态：未学 / learning / 已掌握）② **30% 混排复训**（CN-C1a，每章新内容 ≤70% + 已掌握韵母复训 ≥30%，**这是对抗伪掌握的结构性手段**）③ **提示分级衰减**（CN-C3：虚拟键盘全高亮 → 仅高亮下一键 → 仅显示韵母名 → 无提示；**由掌握度驱动自动衰减，不由用户手动切换**）④ **弱点韵母靶向**（CN-C2）+ 从热力图**一键进入**弱点专项 ⑤ **双门槛判定的用户语言呈现**（不显示阈值，只显示"这个韵母你的反应明显偏慢"）⑥ **Day 6–7 干预卡**（文案见 §4）⑦ 易错音归因面板（CN-C7，八组错误独立统计，**明示"这不是键位问题"**） |
| **反模式（禁止）** | ❌ **过早宣告掌握**（"你已掌握 30 个韵母！"在伪掌握状态下是有害的正反馈，会导致用户跳过复训）<br>❌ 允许用户手动关闭提示（"逞强关提示 → 错一片 → 挫败 → 弃坑"是可预测的路径）<br>❌ 把易错音错误混入键位热力图（会导致弱点靶向指向错误的键位，用户反复练不会的东西）<br>❌ 只按关卡/章节记录进度，不按韵母粒度记录（P0-γ 的定位测与弱点靶向都依赖韵母粒度）<br>❌ 在 Day 6–7 显示"你的正确率下降了"（真实情况是**题目变新了**，不是用户退步了——必须解释成因） |
| **验收指标** | **Day 7 留存率**；掌握韵母数 D7 ≥ 18/35（07 §3 的 P0-β 成功定义）；**提示依赖度**（看键位图次数/词）D7 较 D3 下降 ≥ 30%；**换新词组时的正确率落差 ≤ 15pp**（伪掌握是否被有效识别的**直接验证指标**，对应假设 H3）；30% 混排池的实际命中率 |

### J3 · 提速爬坡（Day 8–14）

| 项 | 内容 |
| --- | --- |
| **触点** | ① L3 成语/四字格 ② L4 短句 ③ 弱点专项模式（CN-C2）④ 趋势线（CN-C5）⑤ 结算页专业指标首露（CN-E4，**术语 + 用户语言双呈现**） |
| **用户目标** | 「把已经记住的键位变成不用想的速度」 |
| **情绪状态** | 稳步回升，"快追上了"。**这是全旅程情绪最健康的阶段，也是最容易被产品忽视的阶段**——没有危机，因此没有干预设计，但用户此时最需要的是**看见自己的进步轨迹** |
| **必备 UI 元素** | ① **趋势线**（CN-C5，击键 ↑ / 反应时 ↓ / 正确率 ↑ 三条，**不含速度**）② 码长指标 + **官方关系式 `速度 = 击键 × 60 ÷ 码长`**（这是唯一能让用户理解"为什么我手速不慢却还是打不快"的公式）③ 字均用键对照锚点（全拼 4 / 双拼 3 / 音形 2.4）④ 弱点专项模式入口（CN-C2）⑤ **专业指标的用户语言文案**（07 §5.3 洞察 9 全表，9 项 × 鼓励句 + 低谷期句，可直接引用）⑥ 无提示毕业模式的"毕业"标记（CN-C3a） |
| **反模式（禁止）** | ❌ 只显示术语与裸数字（P0/P1-a 看不懂 → 功能无效；见 07 洞察 9）<br>❌ 速度成为主视觉（此阶段速度仍在基线之下，显示它只会削弱回升期的信心）<br>❌ 在这个阶段引入新方案/音形码的推荐（分散注意力；音形码 V1 不做，见 07 W6 / 洞察 8）<br>❌ 用"再练 N 天就能超过全拼"的承诺式文案（若 H2 预期带不准，承诺会变成失信） |
| **验收指标** | **Day 14 留存率**；速度 ≥ 全拼基线的 75%（P0-α 成功定义）；掌握韵母数 D14 ≥ 30/35；提示依赖度 ≤ 0.2 次/词；码长趋近 2.1 键/字；击键 ≥ 3.8 键/秒 |

### J4 · 基线回归与停滞（Day 15–30）

| 项 | 内容 |
| --- | --- |
| **触点** | ① L5 实战轨句子（`inputMode: 'ime'`，真实上屏）② 打词率指标 ③ J 曲线定位卡的**右端预告** ④ 30 天小结报告 |
| **用户目标** | 「我速度回到全拼了，那我这三周图什么？」→ 需要被回答 |
| **情绪状态** | **危险的持平期**。速度回到 100% 基线，用户产生"白练了"的错觉 → **Day 30 前后出现第二个流失小峰**（比 Day 3 温和，但同样致命，因为这批用户已经投入了 30 天） |
| **必备 UI 元素** | ① **码长下降曲线**（4 → 3 的结构性变化，这是"图什么"的答案）② **打词率上升曲线**（提速的真正来源是词组而非手速）③ J 曲线定位卡显示**右端**（Day 60+ 的 130–150% 区间，给用户一个继续的理由）④ **30 天小结报告**（本地生成，可导出为分享卡 CN-I7✚，**默认不生成、需用户点击**）⑤ 实战轨入口引导（从"练习"过渡到"真实输入"） |

## 3. Day 3 弃坑峰：成因、干预与文案

### 3.1 成因分析（为什么是第 3 天）

**三重叠加**：

| 层面 | Day 3 发生了什么 |
| --- | --- |
| **客观能力** | 速度跌至全拼基线的 **40–50%**（J 形曲线最低点）。击键（手速）没有下降，但**认知停顿**吃掉了全部收益 |
| **主观归因** | 用户无法区分「我在退步」和「我在正常的学习曲线上」→ 归因为「**我不适合双拼 / 我执行力有问题**」（P0-α 的自我效能崩塌） |
| **环境压力** | Day 1–2 可以用"我在学新东西"向自己解释工作里的低效；**Day 3 这个借口失效了**——已经练了三天还是慢，工作和邮件开始积压 |

**关键判断（本研究最重要的一条产品结论）**：
> Day 3 的速度下降**不是产品的问题，也不是用户的问题，它是学习正在发生的证据**。产品在这一天的唯一任务是**改变用户的归因**，而不是提升用户的速度。任何试图在 Day 3 提升速度的设计（加练、加难、加激励）都会加剧流失。

### 3.2 干预设计（三层，缺一不可）

**第一层：预先告知（Day 0，成本最低、收益最高）**

在 onboarding 的最后一步展示 **J 形曲线全景图**，明确标出 Day 3 的 40–50% 区间，并配文案：

> **接下来三天，你会变慢。这是正常的。**
>
> 双拼的学习曲线不是直线上升，是先降后升的 J 形。第 3 天左右，你的速度会掉到全拼的一半上下——**每一个学会双拼的人都经历过这一段**。
>
> 我们会在第 3 天把这张图再给你看一次，告诉你现在在曲线的哪个位置。
>
> 〔 我知道了，开始 〕

**为什么预先告知有效**：**预先告知的困难不会导致弃坑，突然出现的困难才会。** 这是全旅程性价比最高的一个设计（成本 = 一张图 + 三句话）。

**第二层：当日解释（Day 3 结算页，强制首屏）**

J 形曲线定位卡（CN-C4）在 Day 3 的结算页**首屏展示**，且必须包含四个元素：① 我的当前速度 ② 我的全拼基线 ③ 我在曲线上的位置（高亮 Day 3 节点）④ **文献预期带**（40–50% 区间标注为"正常区间"，用中性色而非红色）。

**Day 3 干预卡文案（可直接引用，析客可整段抄进 02）**：

> **你正好在曲线的最低点。**
>
> 今天你的速度是 **{当前速度} 字/分**，是你全拼水平（{基线} 字/分）的 **{百分比}**。
>
> 这不是退步。双拼学习曲线在第 3 天的正常区间是 **40%–50%**——**你在区间里。**
>
> 更重要的是：**你的手没有变慢。** 你的击键速度是 {击键} 键/秒，比第一天还快。慢下来的是"想键位"这一步——而这一步正在变成不用想。
>
> 按现在的进度，**第 7 天你会回到 60% 左右，第 14 天到 75%–85%，第 30 天追平全拼，第 60 天超过它。**
>
> 〔 继续练 〕　〔 看看我的曲线 〕

**文案设计的四条规则（本文所有文案都遵守）**：
1. **永远不说"你退步了"**，说"这在这个阶段是正常的"
2. **永远给出一个仍在向好的分量**（击键 / 码长 / 掌握数三者在学习期至少有一个单调向好）
3. **永远给出下一步的具体动作**，不停留在安慰
4. **不承诺具体日期能达标**，只给区间和趋势（若 H2 预期带不准，承诺会变成失信）

**第三层：降难而非加压（Day 3 的课程编排）**

- Day 3 的课程**不引入新韵母批次**，改为**已学韵母的 30% 混排复训 + 高频单字**（CN-C1a）
- 提示强度**回调一档**（若已开始衰减，Day 3 暂停衰减，见 CN-C3）——**在谷底撤掉脚手架是设计错误**
- 每日目标量**自动下调**（若用户设定 20 分钟，Day 3 建议 10 分钟）：**完成一个缩短的目标，好过完不成一个完整的目标**

### 3.3 Day 3 的反模式清单（禁止项，硬约束）

| # | 禁止 | 原因 |
| --- | --- | --- |
| 1 | 速度数值使用红色 / 警示色 / ↓ 箭头 | 把正常学习误报为退步 |
| 2 | 结算页第一行是"本次速度 XX 字/分" | 让最差的指标占据最高注意力 |
| 3 | "你已落后于计划""还差 X 才能达标" | 直接触发自我效能崩塌 |

## 4. Day 6–7 二次门槛：伪掌握干预与文案

### 4.1 成因分析（为什么它比 Day 3 更难发现）

| 维度 | Day 3 | **Day 6–7** |
| --- | --- | --- |
| 难的性质 | **预期内的难**（用户知道自己刚开始学） | **以为会了却不会**（落差来自自己的误判） |
| 数据表现 | 速度、正确率**都差** → 数据能发现 | **同批练习的正确率是好的** → **数据发现不了** |
| 触发条件 | 时间到了就会发生 | 遇到**新词组**才发生 |
| 挫败强度 | 高 | **更高**（因为先有了假高点） |
| 流失可预测性 | 高（指标恶化） | **低**（指标良好但用户正要离开） |

**机制**：当练习集中在同一批韵母上时，用户形成的是**逻辑预测**（"上一个键是 A，这个大概是 S"）而非**肌肉记忆**。表现为：同批练习正确率高、反应快；**换新词组立刻崩塌**。

**这是全旅程最危险的一段，因为产品在数据上看不到它。** 唯一的先行指标是：**换新词组时的正确率落差**（J2 验收指标，目标 ≤ 15pp）。

### 4.2 干预设计（四层）

**第一层：结构性预防 —— 30% 混排复训（CN-C1a，Must）**

每章内容配比：**新内容 ≤ 70% + 已掌握韵母的复训 ≥ 30%**，且复训部分**必须打散插入**（不能集中在章末），目的是**打破"同键连续重复"的条件**——伪掌握的形成条件正是连续重复。

**这是对抗伪掌握的根本手段，其余三层都是补救。**

**第二层：识别 —— 双门槛判定（CN-C2a，Must）**

```
未掌握 = 正确率 < 95%
       OR 该韵母平均反应时 > (该用户全部韵母反应时中位数 × 2)
                                    ↑
                          反应时门槛为相对判定（详见 05）
```

配套三条约束（方向明已裁决，全部生效）：
- **冷启动保护（CN-C2a）**：累计样本 < 200 条 **OR** 已出现韵母 < 10 个 → **不做掌握判定，全部标记 `learning`**
- **单韵母样本 < 10 不参与判定**
- **绝对上限兜底**（待数析评估具体规则）：若用户全部韵母的中位数整体偏高（人人都在慢速推导），相对阈值会出现"人人达标"假象 → 触发则整体判为 **S1/S2 阶段，不宣告任何韵母掌握**
- **UI 只暴露相对判定结果**（如「这个韵母你的反应明显偏慢」），**不暴露"待定"或阈值数字**；绝对门槛一律标 `[待标定]`，**禁止在任何文档写死毫秒数**

**为什么必须是双门槛而不是只看正确率**：只看正确率，伪掌握用户会被判为"已掌握"（他同批练习的正确率确实 ≥95%），从而**被移出复训池**——产品亲手把他推进 Day 7 的崩塌。反应时是唯一的破绽：**逻辑预测的反应时显著长于肌肉记忆**。

**第三层：呈现 —— 热力图三态 + 用户语言（CN-E3）**

韵母热力图 35 格，三态：**未学（灰）/ learning（中性色，不是黄色警告）/ 已掌握（正向色）**。

⚠️ **`learning` 态不得使用警示色**。它的语义是"正在形成肌肉记忆"，不是"你还没学会"。在 Day 6–7 这个敏感期，颜色本身就会造成挫败。

**Day 6–7 干预卡文案（可直接引用）**：

> **有几个韵母，你可能是在"猜"，不是在"打"。**
>
> 你在这批练习里的正确率是 {正确率}%，看起来很好。但我们发现，你对 **{韵母列表}** 这几个键的反应明显偏慢——**慢到不像已经记住的样子。**
>
> 这不是你没学会。这是**双拼学习第 7 天最典型的状态**：连续练同一批键位时，大脑会用"上一个键是什么"来推测下一个键，推测得很准，但那不是肌肉记忆。**一换成新词就会露出来。**
>
> 我们已经把这几个韵母加进了你的专项练习，并且**从明天开始，每章会掺入 30% 你 previously 学过的内容**——打散着练，推测就用不上了。
>
> 〔 现在练这几个 〕　〔 看看我的热力图 〕

> **（若用户正确率确实下降了，用这一版）**
>
> **你的正确率掉了，但这是好消息。**
>
> 今天掉到 {正确率}%，是因为**题目换成新词组了**，不是因为你退步了。前几天的好成绩里，有一部分是"猜对的"——现在它们暴露出来了。
>
> **暴露出来才能练。** 这 {数量} 个韵母已经进了你的专项，练完这一轮，你的正确率会带着真实的掌握度一起回来。
>
> 〔 开始专项 〕

**第四层：出口 —— 弱点靶向一键直达（CN-C2 + CN-C2）**

从热力图的 `learning` 格、从干预卡、从结算页的错字列表，**三个入口都能一键进入弱点专项模式**。用户在 Day 7 最需要的是"现在就能做点什么"，**任何需要他自己去配置练习的路径都会流失他**。

### 4.3 Day 6–7 的反模式清单（禁止项，硬约束）

| # | 禁止 | 原因 |
| --- | --- | --- |
| 1 | **过早宣告掌握**（"你已掌握 30 个韵母！"） | 在伪掌握状态下是有害的正反馈，会导致用户跳过复训，直接走向 Day 7 崩塌 |
| 2 | 允许用户**手动关闭提示** | "逞强关提示 → 错一片 → 挫败 → 弃坑"是可预测路径；提示强度必须由掌握度驱动自动衰减 |
| 3 | `learning` 态使用**警示色（黄/橙/红）** | 语义是"正在形成"，不是"没学会"；颜色本身在敏感期造成挫败 |
| 4 | 把**易错音错误混入键位热力图** | 会导致弱点靶向指向错误的键位，用户反复练不会的东西（见 07 洞察 4） |
| 5 | 只按**关卡/章节**记录进度，不按韵母粒度 | 伪掌握识别、定位测、弱点靶向全部依赖韵母粒度 |
| 6 | 显示"你的正确率下降了"**而不解释成因** | 真实情况是题目变新了；不解释 = 让用户自己归因为能力问题 |
| 7 | 显示阈值数字或"待定"字样 | 方向明裁决：UI 只暴露相对判定结果 |
| 8 | 新内容占比 > 70% | 连续同键重复是伪掌握的形成条件 |

**三条编排规则（硬约束）**：

1. **30% 混排复训（CN-C1a）**：L1 起，每章 = 新内容 ≤70% + 已掌握韵母复训 ≥30%，**复训部分打散插入**（不集中在章末）。这是对抗伪掌握的结构性手段，**不是可选的增强**。
2. **掌握度驱动选词**：L2 起，词表**不按静态顺序出题**，而是由 M8 学习路径引擎按当前掌握度动态选词（03 §6.2：M8 提供动态个性化序列，产出与 M3 同形状的 `WordWithIndex[]`，复用 `reviewModeInfoAtom.reviewRecord.words` 通道，**无需新表**）。
3. **⚠️ 出题池排除项（受 A1 待核对项约束）**：在 A1 的 C-1（`er` 第二键）、C-2（`ün` 第二键）、C-4（零声母双字母音节口径）**核对完成前**：
   - 「儿、二、耳」类字（er）**暂不进入 L0/L1 出题池**
   - 「军、群、云、均」类字（ün）**暂不进入出题池**
   - 零声母双字母音节（爱、安、恩、欧、欸、熬）按**双口径兼容判定 + α 为主口径**执行，**统计需分离**（记录用户主用口径，用于后续个性化出题）

### 5.2 韵母渐进课表（35 个韵母的批次编排）

**编排原则**（四条，缺一不可）：
1. **按区分组**，不按字母序——同一手指区域的键位一起学，减少跨区搜索
2. **每批 ≤ 5 个韵母**——控制认知负荷（P0-β 的弃坑诱因是"26 个键一次性压过来"）
3. **先高频后低频**——让用户尽早能打出真实的字
4. **一键多韵母的键放在后面**，且**必须与已学的同键韵母同批或相邻批复现**（如 `K = ing/uai`、`L = iang/uang`、`S = ong/iong`、`R = uan/er`、`T = ue/üe`、`Y = un/ün`、`X = ia/ua`、`O = uo/o`）

| 批次 | 韵母 | 键位（小鹤） | 频率依据 | 教学要点 | 对应级别 |
| --- | --- | --- | --- | --- | --- |
| **批 1** | a / o / e | A / O / E | 单韵母，最高频 | **零声母重复规则**：啊=aa、哦=oo、饿=ee（A1 §3.1） | L0'–L0 |
| **批 2** | i / u | I / U | 单韵母，最高频 | ⚠️ **I 键同时承载声母 ch，U 键同时承载声母 sh** → **判定必须按位置解释**（第一键=声母语义，第二键=韵母语义），不能用单一"键→音"反查表（A1 §2.1 关键设计点） | L0'–L0 |
| **批 3** | ai / ei / ao / ou | D / W / C / Z | 高频复韵母 | ⚠️ **零声母双字母音节存在口径 α/β 冲突**（爱=AI 还是 AD）→ 按**双口径兼容 + α 为主**判定（A1 C-4） | L0 |
| **批 4** | an / en / ang / eng | J / F / H / G | 高频鼻韵母 | **前后鼻音是易错音第一组**（an/ang、en/eng）→ 必须与 §5.3 的易错音归因联动，**错误分开统计** | L0–L1 |
| **批 5** | ia / ie / iu / in | X / P / Q / B | 高频 i 系 | `X = ia/ua` 一键双韵母 → **ua 必须在批 8 与 ia 同批复现对照** | L1 |
| **批 6** | ao(已) / iao / ian / ing | C / N / M / K | i 系续 | `K = ing/uai` 一键双韵母；**in/ing 是易错音第二组** | L1 |
| **批 7** | uo / ue / ui / un | O / T / V / Y | u 系 | ⚠️ **`V = zh(声母) / ui / ü` 一键三义**，是全表最难的键，必须单独一批；`Y = un/ün`（⚠️ ün 属 A1 C-2 待核对） | L1–L2 |
| **批 8** | ua / uai / uan / uang | X / K / R / L | u 系续 | **与批 5/6 的同键韵母对照复现**（X: ia/ua；K: ing/uai）；`R = uan/er`（⚠️ er 属 A1 C-1 待核对） | L2 |
| **批 9** | ong / iong / iang | S / S / L | 后鼻音系 | `S = ong/iong` 一键双韵母；`L = iang/uang`；**ang/iang/uang 三形对照** | L2 |
| **批 10** | ü / üe / üan / ün | V / T / R / Y | ⚠️ 特殊 | **ü 书写简写陷阱**：`j q x y` 后的 ü 书写为 u，但**编码严格按实际韵母**（举=JV、学=XT、卷=JR、云=YY）。**题面必须明示拼音**，避免歧义（A1 §3.3 / C-5） | L2 |

### 5.3 易错音归因课程（八组，独立统计）

> **依据**：07 §5.1 洞察 4（A 级）。**键位映射错误与拼音盲点错误必须分开统计**，否则热力图指向错误的键位、弱点靶向失效、用户反复练不会的东西。

| # | 易错音组 | 错误性质 | 训练处方 | 为什么键位训练无效 |
| --- | --- | --- | --- | --- |
| 1 | **zh / z** | 拼音盲点（翘舌 vs 平舌） | 拼音辨析 + 对照字组练习 | 用户不知道该按 V 还是 Z，**不是按不准** |
| 2 | **ch / c** | 拼音盲点 | 同上 | 同上（I vs C） |
| 3 | **sh / s** | 拼音盲点 | 同上 | 同上（U vs S） |
| 4 | **an / ang** | 拼音盲点（前 vs 后鼻音） | 鼻音辨析 + 对照练习 | J vs H，**问题在耳朵/语言习惯，不在手** |
| 5 | **en / eng** | 拼音盲点 | 同上 | F vs G |
| 6 | **in / ing** | 拼音盲点 | 同上 | B vs K |
| 7 | **n / l** | 方言盲点（南方方言区高发） | 声母辨析 | 与韵母无关，键位训练完全无效 |
| 8 | **f / h** | 方言盲点（湘、赣、闽方言区高发） | 声母辨析 | 同上 |

**产品要求（CN-C7，Must）**：
1. 八组错误**独立计数**，不与键位错误混合
2. 诊断面板必须**明示"这不是键位问题"**，并给出对应的辨析训练入口
3. 数据来源零成本：`letterMistake`（`Word/index.tsx:220-224`）已提供逐位置错字（07 F5）
4. **主要服务人群**：P1-b（方言区/初学者）与 P0-β（会把失败归因到错误原因的人）

### 5.4 提示强度分级与毕业机制

**四级提示（CN-C3，由掌握度驱动自动衰减，不由用户手动切换）**：

| 级别 | 提示内容 | 触发条件 | 存储载体 |
| --- | --- | --- | --- |
| **P1 全提示** | 虚拟键盘高亮**当前应按键 + 下一键**，并显示韵母名 | 该韵母 `learning` 且样本 < 10 | 复用 `wordDictationConfigAtom.hideAll = false`（07 F16） |
| **P2 半提示** | 仅高亮**下一键位**，不显示韵母名 | 该韵母正确率 ≥ 90% 且样本 ≥ 10 | `hideVowel` / `hideConsonant` 组合 |
| **P3 弱提示** | 仅在**错误后**显示正确键位（事后提示，不事前提示） | 该韵母达到双门槛掌握 | `randomHide` |
| **P4 无提示** | 无任何键位提示 | 该韵母**毕业** | `hideAll = true` |

**毕业判定（CN-C3a）**：某韵母在无提示（P4）状态下**连续 N 次正确**（N `[待标定]`）→ 标记"毕业"，从主课程中降频，**进入 30% 混排复训池**（不删除——防止遗忘）。

**整体毕业（J5 毕业面板）**：35 个韵母全部毕业 + 实战轨达标 → 显式宣告毕业，并**主动引导用户离开学习闭环、进入实战轨**（07 洞察 6：毕业是产品的显式概念，成功指标不是 DAU 时长）。

⚠️ **Day 3 的特例**：若用户已进入 P2/P3，**Day 3 暂停衰减并回调一档**——在谷底撤掉脚手架是设计错误（§3.2 第三层）。

### 6.3 专业指标的用户语言文案（9 项 × 3 句）

> 完整表格见 **07 §5.3 洞察 9**（击键 / 码长 / 韵母掌握 / 反应时 / 编码正确率 / 键准率 / 键法 / 选重率 / 打词率，每项含：用户语言解释 + 鼓励句 + 低谷期句）。**本文不重复定义，只登记引用关系**：CN-E4（专业指标）与 CN-E3/E2/E3 的所有 UI 呈现**必须同时挂载 07 §5.3 的对应文案**，不得只显示术语与裸数字。

## 8. 验收指标与北极星

### 8.1 ⭐ 北极星指标（1 个）

> **60 天毕业率** = 在首次练习后 60 天内达成「35 个韵母全部毕业（无提示连续达标）+ 实战轨达标」的用户占同队列用户的比例。

**为什么是毕业率而不是 DAU / 时长 / 留存**（07 洞察 6，D 级研究者判断，但由 §1 曲线结构支撑）：

1. **双拼学习是一段有明确终点的能力获得过程**，不是一种长期状态。用户在 Day 60+ 自然毕业，毕业后**不再需要学习闭环**。
2. 若以 DAU 或时长为北极星，产品会被激励去**延长用户的低效练习**（更多关卡、更多游戏化、更多提示依赖）——**这与用户的利益直接冲突**，且会摧毁社区信誉。
3. **毕业不等于流失**：毕业用户会迁移到 J5/J6（实战轨、长文耐力、标点专项、专业指标），这正是 P1-a 场景，也是口碑传播的来源。因此毕业率与长期活跃**不矛盾**，而留存率与长期活跃**在本产品中是矛盾的**。

**⚠️ 这条北极星与常规增长逻辑相反，必须在 05 中明确写入并锁定**，否则后续会被"提升留存/时长"的需求反向侵蚀（这是本研究识别出的**最大产品治理风险**）。

**目标值**：`[待标定]`。无一手基线数据（H2/H3 未验证）。**建议 V1 上线后以首个完整队列（60 天）的实测值作为基线，V1.1 设定相对提升目标，禁止在 V1 阶段写死绝对数字。**

### A1.1 打分方法

**三个维度，各 1–5 分**：

| 维度 | 定义 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- | --- |
| **频率（F）** | 目标用户**多久会用到一次** | 一次性 / 极少数用户 / **用户不直接接触** | 每周数次 | 每次练习都用 |
| **影响度（I）** | 对**核心 JTBD 与弃坑风险**的作用强度 | 锦上添花 | 有明确价值但非关键 | 缺失则核心 JTBD 无法完成，**或其缺失会让其他功能的输出不可信** |
| **成本反向（1/C）** | 实现与维护成本的**倒数**（成本越低分越高） | 极高成本 / 需法务 / 需重写引擎 | 中等改造 | 复用现有资产，近零成本 |

**价值分 = (F × 0.3) + (I × 0.5) + (1/C × 0.2)**，满分 5.0，保留一位小数。**66 行算术已脚本逐行复核，零误差。**

**权重理由**：影响度权重最高（0.5），因为本研究的核心结论是「**P0 的第一价值是解释而非练习**」（07 §1）——一个低频但能阻止弃坑的功能，价值高于一个高频的锦上添花功能。频率权重次之（0.3）。成本权重最低（0.2），因为**成本高不构成不做的理由，只构成排期的理由**。

**⚠️ F 维度对基础设施类功能存在结构性惩罚**（本表最重要的方法论局限，详见 A1.5 局限④）：门禁型功能（CN-A1a / CN-A3 / CN-B1 / CN-D0 / CN-D1 / CN-E6 / CN-G2 / CN-J1 / CN-J3 / CN-J5 / CN-J6）**用户不直接接触，F 值天然为 1–2**，即使 I 与 1/C 都给满分，总分上限也只有 `1×0.3 + 5×0.5 + 5×0.2 = 3.8`，**永远进不了 Top 21**。因此**门禁型功能的分数不可与用户可见功能横向比较**，须按 A1.2 规则① 单独锁定。

**⚠️ 打分时最容易犯的错误（供后续维护者警惕）**：门禁型功能的价值是「**防止坏事发生**」而非「**产生好处**」，因此在评 I 值时极易被低估为 3 分（"有明确价值但非关键"）。**一旦 I 被低估，门禁型项目会跌到尾部并被误砍**——而砍掉它们的后果是让高分项目集体失效。评 I 值时必须问：「**如果这一项不做，哪些高分项的输出会变得不可信？**」若答案非空，I = 5。

**⑤ 四条取舍总结**

1. ⚠️ **门禁型功能必须锁 Must 且不参与分数排序，作为前置任务排期。** 11 项门禁型功能的名次分布在 28–55 名，**看起来像可砍项，实际是不可砍的前置项**——它们的 F=1–2 是「用户不直接接触」造成的，**不是「用户不需要」**。F 维度对基础设施类功能存在结构性惩罚（总分上限 3.8，永远进不了 Top 21）。**后续若有人以「分数低」为由提议砍 CN-J1/J3/J5/J6/A3/A1a/B1/D0/D1/E6/G2，须先读本条。**

2. **真正可砍/可延的只有 7 项**（CN-I5、CN-C8、CN-H3、CN-F4、CN-H1、CN-E7、CN-D9），外加 1 项应挂灰（CN-F3）。**簇分布：Ⅳ 簇 4 项、Ⅲ 簇 3 项、Ⅰ 簇 1 项（CN-I5 阶段徽章）、Ⅱ 簇 0 项**——**Ⅱ 簇（实战与长文）无一项进入尾部**，量化印证「Ⅱ 簇不可切」；可延项集中在 Ⅲ/Ⅳ 簇，量化印证「Ⅲ/Ⅳ 可后延」。**这与 D1 裁决（考试模式降级交付、CN-F3 挂灰、CN-D9 法务前置）完全一致，是独立于裁决的量化验证。**

3. **CN-F5 是全表最反直觉的一项：频率 1 分（全表最低）却排进第 26 名。** 原因是 I=5 + 1/C=5（纯文案、成本近零）。这量化证明了一条判断：**「练了三周才发现考场用不了小鹤」是本项目唯一一处「不做的代价高于做的代价」的风险**，因此它虽属 Ⅲ 簇（考试相关），却必须**破例锁在 V1-a**（方向明裁决）。⚠️ 但结论④ 分歧 #1 指出：**CN-F5 目前指向的「微软双拼」在 V1-a 并不存在**——这条提示在解决分歧 #1 之前是**无法闭环的**。

4. **「低分」有两种完全相反的含义，分数不能替代对成因的判断。** CN-D9（1.5 分）低分是**「不该做」**（法务风险 + 未 clearance）；CN-H3（2.7 分）低分是**「低频但必须做」**（无校验的导入会让用户练错编码，与 W8 拒绝 AI 生成语料同源理由）；CN-J1（3.8 分）中分是**「用户看不见但一切的前提」**。→ 这是打分表的第二个结构性缺陷（第一个见结论 1）。

5. **打分表不能作为分期依据，只能作为分期内的排期依据。** 分期由**原子簇约束 + 门禁依赖 + 合规前置**决定（详见 01 与 10）；打分表只在同一分期内部回答「先做哪个」。**若路线图与本表排序冲突，以原子簇约束为准；若本表与 01 的 MoSCoW/分期冲突，以 01 为准，分歧按结论④ 走裁决流程。**

## 9. 本文档的核心结论（8 条）

1. **旅程有三个可测量的失败点，产品的全部体验设计都是在对抗它们**：Day 3 弃坑峰（速度腰斩 → 归因错误）、Day 6–7 二次门槛（伪掌握 → 落差崩塌）、Day 30 停滞（速度持平基线 → "白练了"错觉）。其中 **Day 6–7 最危险，因为数据上看不到它**——同批练习的正确率是好的，唯一的先行指标是「换新词组时的正确率落差 ≤ 15pp」。

2. **Day 3 的速度下降不是产品的问题，也不是用户的问题，它是学习正在发生的证据**。产品在这一天的唯一任务是**改变用户的归因，而不是提升用户的速度**。任何试图在 Day 3 提速的设计（加练、加难、加激励）都会加剧流失。三层干预中，**成本最低、收益最高的是 Day 0 的预先告知**——预先告知的困难不会导致弃坑，突然出现的困难才会。

3. **对抗伪掌握靠结构，不靠识别**：30% 混排复训（新内容 ≤70% + 已掌握复训 ≥30%，**打散插入**）是根本手段，双门槛判定是补救手段。只用正确率单门槛会把伪掌握用户判为"已掌握"并**移出复训池**——产品亲手把他推进 Day 7 的崩塌。反应时是识别伪掌握的唯一破绽（逻辑预测的反应时显著长于肌肉记忆），**反应时门槛为相对判定（详见 05）**，绝对门槛一律 `[待标定]`，**禁止写死毫秒数**。

4. **课程路径 L0'–L7 的编排有四条硬约束**：① 每批 ≤5 个韵母（控制认知负荷）；② 一键多韵母的键（V=zh/ui/ü 一键三义最难）必须单独成批，且同键韵母必须相邻批复现对照；③ **在 A1 的 C-1（er）/C-2（ün）/C-4（零声母双字母）核对完成前，对应字不进出题池**；④ L2 起选词由掌握度动态驱动，不按静态词表顺序（复用 M8 与 `reviewRecord.words` 通道，**无需新表**）。

5. **北极星是「60 天毕业率」，不是 DAU / 时长 / 留存率**。双拼学习是一段有明确终点的能力获得过程；若以时长为北极星，产品会被激励去延长用户的低效练习，**这与用户利益直接冲突**。⚠️ 这条与常规增长逻辑相反，**必须在 05 中锁定**，并配四条护栏（伪掌握率 ≤15% / 提示依赖度 ≤0.2 / 数据本地性 =100% / 存量无回归 =100%）。**若毕业率下降而时长上升，这是产品变坏的信号，不是变好。**

6. **31 条反模式为硬约束（A 级 14 条 / B 级 17 条）**。14 条 A 级中，**8 条为合规与价值观底线**（不写死考试合格线、不内置未 clearance 语料、不内置官方口诀、不复制纸砚代码、不做儿童拼音教学、不做移动端对码优先、不做账号云同步、不自动弹出分享卡与全站排行榜），**6 条为数据正确性底线**（不写死反应时毫秒阈值、不按关卡粒度记录进度、不把易错音混入键位热力图、学习期速度不用警示色、结算页首行不放速度）。**命中任一条的设计需在 01 中降级或移除。**

7. **附录① 三维打分表（66 条，编号与 01 §6 逐条对齐）的核心结论是"Ⅰ 簇不可切"的量化证据**：**按纯分数排序，前 21 名（≥4.0）100% 落在 Ⅰ 簇（学习闭环），Ⅱ/Ⅲ/Ⅳ 簇零席**；而尾部 8 项（≤2.9）的簇分布是 **Ⅳ 簇 4 项、Ⅲ 簇 3 项、Ⅰ 簇 1 项（CN-I5 阶段徽章）、Ⅱ 簇 0 项**——**Ⅱ 簇无一项进入尾部**，量化印证"Ⅱ 簇不可切、Ⅲ/Ⅳ 可后延"，与 D1 裁决独立一致。但**打分表不能单独作为裁决依据**，它有两个结构性缺陷：① **F 维度对基础设施类功能存在系统性惩罚**（11 项门禁型功能 F 上限 = 2 → 总分上限 3.8，永远进不了 Top 21，实际名次散布在 28–55 名，**看起来像可砍项，实际是不可砍的前置项**）；② **"低分"有两种完全相反的含义**（CN-D9 的 1.5 分是"不该做"——法务未 clearance；CN-H3 的 2.7 分是"低频但必须做"——无校验的导入会让用户练错编码）。→ **门禁型功能锁 Must 且不参与分数排序，作为前置任务排期；打分表只用于同一分期内部排先后，若与原子簇约束冲突以原子簇约束为准，若与 01 的 MoSCoW/分期冲突以 01 为准并按 A1.4 结论④ 走裁决流程。** ⚠️ 打分表的 1/C 成本分为研究者估计，**Spike S1/S2/S3 结论出来后必须重算**；若 S1 判 NO-GO，**Top 21 中 15 席直接失效**（CN-A1、CN-A1b、CN-B3、CN-C1、CN-C1a、CN-C2、CN-C2a、CN-C3、CN-C3a、CN-C7、CN-D2、CN-D3、CN-D4、CN-E1、CN-E3），仅 6 席（CN-B2、CN-C4、CN-I1、CN-I4、CN-I6、CN-J4）可迁移到纯实战轨。

8. ⭐ **附录① A1.4 结论④ 登记了 9 处与 01 现状的分歧，这是本次落盘最具行动价值的产出，其中 5 处属排期硬伤，必须在 10-路线图定稿前解决**：
   - **① CN-B2 内部自相矛盾（最严重）**：01 的 CN-F5（Must/V1-a）提示文案是「**改用微软双拼**」，但 CN-B2 的 V1 方案只有「全拼 + 小鹤双拼」，微软双拼仅"架构预留"→ **用户点了按钮无处可去，提示无法闭环**。二者取一：把微软双拼提进 V1-a，或把 CN-F5 文案改为「考场建议直接用**全拼**」。
