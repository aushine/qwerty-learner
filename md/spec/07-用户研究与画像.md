## 1. 核心结论：P0 用户不是"想打快的人"，而是"想弃坑的人"

这是本研究最重要的一条判断，它决定了整个产品的形态。

**表层需求**（用户自己会说的）：「我想学双拼」「我想打字更快」「我要考打字证」。

**真实 P0 需求**（数据支撑的）：**正处于双拼迁移期第 3–14 天、速度跌到全拼的 40–60%、正在认真考虑放弃的人。**

三条支撑：

1. **这是一段有明确起点和终点的旅程**，不是一种长期状态。用户会在 30–60 天内自然毕业（J 形曲线右端，速度达全拼的 130–150%），毕业后不再需要练习器。**产品价值集中在这 30–60 天里**，而这恰好是现有工具集体失效的区间。
2. **现有工具的失效点高度一致**：全部竞品（含开源的 `shuangpin-practice`、纸砚、Shuang、ulpb）都提供键位表和练习文本，**没有一个提供"你现在处于 J 形曲线哪个位置"的定位**。用户在第 3 天看到自己速度腰斩，无法区分"我在退步"和"我在正常的学习曲线上"，于是归因为"我不适合双拼"并弃坑。
3. **这个人群的痛感是可测量的**：速度衰减率（详见 05）。它不是一个模糊的"体验不好"，而是一个能在 Day 3 精确读数、并能在 Day 14 精确验证产品是否起效的数字。

**推论（决定产品形态的三条）**：

- **P0 的第一价值不是"练"，是"解释"**。J 形曲线定位卡（CN-C4）在用户价值排序上高于任何练习模式增强——它是唯一能直接对抗弃坑归因错误的设计。
- **学习期必须以过程指标为主，速度指标必须降级**。D3–D30 期间速度**必然**下降，任何以速度为主色的红/绿指示都会系统性地把"正常学习"误报为"退步"，**亲手把 P0 用户推走**。这是 CN-A3（双轨口径分离）与 CN-C4（J 形曲线定位卡，含速度衰减率的预期带对照）必须为 Must 的根本原因。
- **产品要有"毕业"概念**。练习器的成功指标不是 DAU 时长，而是**用户多久能不再需要它**。这一条与常规增长逻辑相反，需在 05 的北极星定义中明确写入，否则后续会被"提升留存"的需求反向侵蚀。

## 2. 用户分层与优先级

### 2.1 分层总表

| 层级 | 人群 | 规模判断 | 痛感强度 | 付费/传播意愿 | V1 服务程度 | 置信度 |
| --- | --- | --- | --- | --- | --- | --- |
| **P0** | 双拼迁移期用户（Day 0–30，主要卡在 Day 3–14） | 中（社区活跃、聚集度高） | **极高**（正在经历速度腰斩） | 中（愿分享，不願付费） | **完整服务，是 V1 的验证对象** | B |
| **P1-a** | 办公提速人群（全拼熟练，想突破 60–80 字/分瓶颈） | **大** | 中（无痛点则不行动） | 低 | 部分服务（实战轨 + 长文耐力） | B |
| **P1-b** | 拼音初学者 / 海外中文学习者 / 学生 | 中大 | 中高 | 低 | 部分服务（L0' 起步路径，但**不教拼音**） | C |
| **P2** | 打字考试备考者（事业单位工勤、书记员听打、速录） | 小（但需求刚性、有明确 deadline） | **极高**（考试不过=实际损失） | **高**（唯一有付费意愿的群体） | 降级服务（V1-c，合格线判定挂灰） | C |
| **P3（不服务）** | 儿童拼音启蒙家长 | — | — | — | **明确排除**，见 §7 | A |

**为什么 P2 痛感极高、付费意愿最高，却排在 P0 之后？**

三个理由（此判断已由方向明裁决：考试模式**留在 V1**，但按 V1-c 分期 + 降级交付）：

1. **考场输入法可用性是硬约束**：考场机房普遍只预装 **全拼、微软双拼、五笔**，小鹤双拼在部分考点**无法使用**。这意味着考试人群的方案选择被外部限定，产品对他们的主要价值是"计时 + 计分 + 语料"，而非"键位教学"——**与 P0 的价值主张几乎不重叠**。
2. **它依赖法务前置而非工程**：考试语料（公文、法律文书）需 clearance。语料未到位则合格线判定无法验收（见 CN-F3 挂灰、CN-D9 法务前置标注）。
3. **它与学习闭环零技术复用**：计时模式、禁退格统计、有效字数计分都要绕过现有 `bannedKeys`（`src/utils/index.ts:6-37`）与 `isLegal`（`:39-42`）结构，并行开发会拖慢 V1-a。

**但必须保留的两条**（方向明已裁为硬性约束）：

- **CN-F5「机考输入法可用性提示」必须在 V1-a 上线**。它是纯文案、成本近零，作用是**防止用户在考前才发现小鹤不可用而导致对整个产品的信任崩塌**。这条不因考试模式降级而后置。
- **微软双拼必须在 V1-a 内置**（⚠️ 01 的 CN-B2 现为「V1 = 全拼 + 小鹤双拼，微软/自然码/搜狗仅架构预留」，与 CN-F5「改用微软双拼」的提示自相矛盾，已上报方向明裁决），否则考试人群从 onboarding 第一步就流失。

### 2.2 P0 画像：双拼迁移期用户（3 个变体）

> P0 不是一个人，是三个人。他们进入产品的路径不同，弃坑的诱因也不同，**必须分别设计干预**。

#### 画像 P0-α｜「理性优化者」

| 维度 | 内容 |
| --- | --- |
| **典型身份** | 25–35 岁，程序员 / 设计师 / 内容工作者，日均中文输入 2000+ 字 |
| **触发动机** | 看到双拼的**码长论证**（全拼字均 4 键 → 双拼 3 键 → 音形 2.4 键），算了一笔账，决定迁移 |
| **进入路径** | 先读教程 → 记住键位表 → **立刻在真实工作里硬切** → 第 2–3 天效率崩塌 → 搜索"双拼 练习" |
| **核心 JTBD** | 「当我在工作里因为双拼变慢而被自己嫌弃时，我需要一个**能证明这是暂时的、并告诉我还要多久**的东西，好让我不要切回全拼。」 |
| **现有替代方案** | 键位表图片贴在显示器边、纸砚/ulpb 在线练习、`shuangpin-practice`、直接硬扛 |
| **未满足需求** | ① 无法定位自己在曲线上的位置；② 练习文本与工作用词无关；③ **没有"退步是正常的"这句话的权威来源** |
| **弃坑诱因** | **自我效能崩塌**——"我算得出收益，却做不到，说明我执行力有问题" |
| **有效干预** | J 形曲线定位卡 + 速度衰减率的**预期值对照**（"Day 3 打到全拼的 45% 属于正常区间"） |
| **无效干预** | 游戏化、排行榜、连续打卡——**他不需要激励，需要解释** |
| **置信度** | B（V2EX 一手案例 + 双拼社区讨论） |

#### 画像 P0-β｜「社区跟随者」

| 维度 | 内容 |
| --- | --- |
| **典型身份** | 20–30 岁，学生 / 初入职场，因社区氛围（V2EX、少数派、贴吧、B 站教程）入坑 |
| **触发动机** | 「大家都在说双拼好」，**动机来自身份认同而非算账** |
| **进入路径** | 看一个视频/帖子 → 直接下载练习工具 → **没有系统过键位表** → 靠提示硬打 |
| **核心 JTBD** | 「当我记不住 26 个键位、每次都要看提示时，我需要一个**能让我按顺序、有节奏地记住键位，并且让我看见自己在记住**的东西。」 |
| **现有替代方案** | 视频教程、键位口诀、练习网站 |
| **未满足需求** | ① 没有**渐进课程**（现有工具一上来就是整篇文章）；② 不知道哪些韵母自己已经掌握、哪些没有；③ **提示依赖无法毕业**（一直看着键位图打，形成"伪掌握"） |
| **弃坑诱因** | **认知负荷过载**——26 个键位一次性压过来，没有分解，第 3 天记不住就放弃 |
| **有效干预** | 韵母渐进课表（CN-C1）+ 虚拟键盘实时高亮（CN-C3）+ **提示分级衰减**（CN-C3）+ 掌握度可视化（CN-C2a） |
| **无效干预** | 只给键位表、只给整篇文本练习 |
| **置信度** | B |

#### 画像 P0-γ｜「回流重试者」

| 维度 | 内容 |
| --- | --- |
| **典型身份** | 30–45 岁，曾经学过双拼但中途放弃，现在想再试一次 |
| **触发动机** | 上次失败的**未完成感**；或换了设备/输入法后重新接触 |
| **进入路径** | 搜索 → 直接找练习工具 → **不愿意从头学** → 期望"捡起来" |
| **核心 JTBD** | 「当我已经认识大部分键位、只是不熟时，我需要一个**能测出我到底会哪些、跳过我已经会的、只练我薄弱的那几个**的东西，别让我从『啊哦鹅』重头练一遍。」 |
| **现有替代方案** | 无——**现有工具全部没有水平定位能力**，一律从零开始 |
| **未满足需求** | ① 定位测（CN-C2）；② 弱点韵母靶向（CN-C2）；③ 掌握度按韵母而非按关卡记录 |
| **弃坑诱因** | **被当成新手的羞辱感 + 时间浪费感**——"这些我早会了" |
| **有效干预** | 30 秒定位测 + 跳过已掌握韵母 + 弱点专项模式（CN-C2） |
| **无效干预** | 强制线性课程、无法跳关 |
| **置信度** | C（由 P0-α/β 的失败案例反推，需一手验证 → 列入 H4） |

**三个变体的共性（即 P0 的最小公倍数需求）**：

1. 都需要**知道自己在曲线上的位置**（→ CN-C4）
2. 都需要**按韵母粒度的掌握度反馈**，而非按关卡（→ CN-C2a + CN-E3）
3. 都**排斥社交竞争与重度游戏化**（→ §7 反洞察）
4. 都在**Day 3 与 Day 6–7 两个节点**面临弃坑风险（→ 08 §3、§4）

### 2.3 P1-a 画像：办公提速人群

| 维度 | 内容 |
| --- | --- |
| **典型身份** | 25–45 岁，行政 / 客服 / 编辑 / 律师助理 / 记者，日均中文输入 3000–8000 字 |
| **核心动机** | 已经全拼熟练（50–70 字/分），**遇到瓶颈**：想再快，但全拼的码长上限卡住了 |
| **典型场景** | ① 长文档录入（会议纪要、笔录、稿件）；② 需要连续输入 10–30 分钟不疲劳；③ 标点、数字、中英混排频繁 |
| **JTBD** | 「当我每天要录入几千字、手已经开始酸时，我需要一个**能让我在不改变输入法习惯的前提下，把耐力和标点/数字/混排的准确率练上去**的东西。」 |
| **现有替代方案** | 金山打字通、巧手打字通等老牌软件（**UI 陈旧、无数据、需安装**）、在线打字网站（**多为英文或儿童向**） |
| **未满足需求** | ① 长文耐力训练（现有工具全是 20 词一章）；② **标点专项**（全角/半角、中英混排——这是办公场景的真实错误源，但**没有任何工具单独训练它**）；③ 专业指标（击键/码长/键准/键法/选重/打词率——**这是速录行业的标准语言，办公人群用它能自我诊断**）；④ 断点续练（工作间隙的碎片练习） |
| **与 P0 的关键差异** | **他不迁移方案**。他可能一直用全拼，或已用双拼多年。因此他**不需要学习闭环（Ⅰ 簇）**，只需要实战轨 + 长文 + 标点 + 专业指标（Ⅱ 簇 + Ⅳ 簇）。 |
| **产品含义** | **P1-a 是 Ⅱ 簇的唯一验证对象**。若把 Ⅱ 簇砍掉只留学习闭环，会丢失整个存量最大的市场；反之若为 P1-a 优先做实战轨而砍学习闭环，会丢失 P0。**这就是"Ⅰ+Ⅱ 都不可切"的用户侧依据。** |
| **置信度** | B |

### 2.4 P1-b 画像：拼音初学者 / 海外中文学习者 / 学生

| 维度 | 内容 |
| --- | --- |
| **典型身份** | 三类混叠：① 海外华人子女 / 中文学习者（会用拼音但不熟练）；② 方言区成年人（n/l、f/h、前后鼻音不分）；③ 中小学生（信息技术课打字要求） |
| **核心动机** | 「拼音我会读，但**打不出来**」或「我打出来的字**经常选错**」 |
| **JTBD** | 「当我不确定一个字该怎么拼时，我需要一个**能告诉我正确编码、并让我反复练到我不用想**的东西。」 |
| **现有替代方案** | 学校机房的老打字软件、输入法自带的手写/语音（**绕过了问题而非解决问题**） |
| **未满足需求** | ① **易错音归因**（zh/z、ch/c、sh/s、an/ang、en/eng、in/ing、n/l、f/h 八组）——这些不是"打字问题"是"拼音问题"，但**会在打字练习中暴露，且必须分开统计**，否则错误归因会指向错误的训练；② 从字→词的极缓起步（L0'/L1） |
| **⚠️ 边界（必须守住）** | **本产品不教拼音**。它只练"字 → 编码 → 上屏"的输入映射。若滑向拼音教学（发音、声调、儿童动画），会：① 与 Issue #784 的社区决议冲突（Closed as not planned）；② 让产品定位从"输入法练习器"变成"拼音课程"，两边都做不好；③ 引入儿童用户 → 触发隐私合规（COPPA/个保法）成本 |

| **P1-b 拼音初学者** | 告诉我正确编码，让我练到不用想 | **八组易错音的错误占比 D14 下降 ≥ 30%**；L1→L2 通关率 ≥ 70% | 高 | 无 | C |
| **P2 考试备考** | 按考试规则模拟，告诉我差多少 | **有效字数 ≥ 岗位线**（因岗位而异）；**正确率 ≥ 95%（书记员）/ ≥90%（一般文职）**；模拟成绩与真实考试成绩偏差 ≤ 10% | **最高**（错一罚五使正确率成为主导变量） | **有**，且 `[待标定]` | C |

**关键推论：正确率优先级的分层决定了指标设计的分叉**

- P0（学习期）：**过程指标优先**，正确率是"掌握度"的输入而非考核项。若在此期以正确率红线警告用户，会加速弃坑。
- P1-a / P1-b：**正确率是主指标**，速度是次指标。
- P2：**正确率是决定性变量**——错一罚五意味着 95% 与 90% 的正确率在有效字数上的差距远大于速度差距。**考试模式的成绩单必须以正确率为主视觉，速度为辅。** 这一条必须写入 05 与 01 的 CN-F2 验收标准。

## 4. 用户故事（8 条）

> 格式：`作为 <角色>，当 <情境> 时，我想要 <能力>，以便 <价值>`。**每条附验收要点**，可直接被 01 的 Given/When/Then 引用。

### US-1｜第一次打开：我不知道该选哪个方案（P0-β / P2）

**作为**一个刚决定学双拼的人，**当**我打开产品看到"小鹤 / 微软 / 自然码 / 搜狗"四个陌生名词时，**我想要**产品根据我的实际用途替我推荐一个，并告诉我选错了怎么办，**以便**我不必在第一步就做一个我完全没有判断依据的决定。

**验收要点**：
- onboarding Q1–Q4 决策树（§6）必须在**首次进入时**触发，且**可跳过**
- 「未来 3 年内是否可能参加打字机考」为 **Q2 必问项**；答"是/不确定"→ 推荐微软双拼
- 用户选择小鹤但答"是/不确定"时，**强制展示考场兼容提示卡**，需二次确认才能跳过
- 选择页底部必须有**可挽回性说明**：「选错了随时能改。方案配置是可插拔的，你的练习记录不会丢；但韵母掌握度会按新方案的键位重新计算。」
- **跳过 onboarding 的默认值**：小鹤双拼 + L0' 起点 + 每日 15 分钟 + 不做定位测（全部韵母按未掌握处理）

### US-2｜Day 3：我的速度腰斩了，我想切回全拼（P0-α）★核心故事

**作为**一个刚开始练双拼第 3 天的人，**当**我发现自己打字速度只有原来的一半、工作邮件写到一半想切回全拼时，**我想要**有一个地方能告诉我"这个速度是正常的、我还要多久能追回来"，**以便**我不要在这个时候放弃。

**验收要点**：
- **J 形曲线定位卡（CN-C4）**必须在结算页与统计页**首屏可见**，不得藏在二级页
- 卡片必须显示：① 我的当前速度；② 我的**全拼基线**（onboarding 或首次练习时采集）；③ 当前进度百分比；④ **文献预期带**（Day 3 ≈ 40–50%、Day 7 ≈ 60%、Day 14 ≈ 75–85%、Day 30 ≈ 100%、Day 60+ ≈ 130–150%）
- **速度数值在学习期（D0–D30）不得使用红色/警示色**，即使低于基线（详见 08 §3 反模式）
- **学习期速度衰减率**以「与预期带的偏差」呈现，而非以「与基线的差距」呈现；此能力由 **CN-C4** 承载（⚠️ 勿与 CN-E5「耐力衰减率」混淆，后者是 P1-a 的长文前后半程指标，属 J5/J6）

### US-3｜Day 6–7：我以为我会了，其实我只是在猜（P0-β）★核心故事

**作为**一个练到第 7 天的人，**当**我在重复练习同一批韵母时打得很快、但一换成新词就卡住时，**我想要**产品能识别出我这是"假会"，并把我真正没记住的韵母挑出来单独练，**以便**我不在虚假的进度感里浪费时间。

**验收要点**：
- **伪掌握识别**：双门槛判定（CN-C2a）——`未掌握 = 正确率 < 95% OR 该韵母平均反应时 > 该用户全部韵母反应时中位数 × 2`
- **反应时门槛为相对判定，禁止在任何文档写死毫秒数**（详见 05）
- **冷启动保护（CN-C2a）**：累计样本 < 200 条 OR 已出现韵母 < 10 个 → 不做掌握判定，全部标记 `learning`；单韵母样本 < 10 不参与判定
- **绝对上限兜底**（方向明追加，待数析评估）：若用户全部韵母的中位数整体偏高（人人都在慢速推导），相对阈值会出现"人人达标"假象 → 触发则整体判为 S1/S2 阶段，**不宣告任何韵母掌握**
- UI 只暴露相对判定结果（如「这个韵母你的反应明显偏慢」），**不暴露"待定"或阈值数字**
- 弱点韵母靶向（CN-C2）+ 弱点专项模式（CN-C2）必须能从判定结果**一键进入**
- **30% 混排复训（CN-C1a）**：每章新内容 ≤70%，已掌握韵母的复训 ≥30%，防止"练过就忘"

### US-4｜我一直看着键位图打，什么时候能不看（P0-β）

**作为**一个依赖键位图提示的学习者，**当**我已经能打出大部分韵母、但手离开键位图就没信心时，**我想要**提示能自动逐步减少、并在我不看提示也能打对时告诉我"你可以毕业了"，**以便**我能真正脱离提示独立输入。

**验收要点**：
- **提示分级衰减（CN-C3）**：虚拟键盘高亮（全提示）→ 仅高亮下一键位（半提示）→ 仅显示韵母名（弱提示）→ 无提示
- 衰减必须**由掌握度驱动，不由用户手动切换**（用户手动切换会导致"逞强关提示 → 错一片 → 挫败 → 弃坑"）
- **无提示毕业模式（CN-C3a）**：某韵母掌握后，该韵母在无提示状态下连续 N 次正确 → 标记"毕业"，可从课程中降频（不删除，进入 30% 混排池）
- 复用现有 `wordDictationConfigAtom`（`src/store/index.ts`：hideAll / hideVowel / hideConsonant / randomHide）作为提示强度的存储载体

### US-5｜我是老手，别让我从头练（P0-γ）

**作为**一个学过双拼但中断了半年的人，**当**我重新开始练习时，**我想要**用 30 秒测出我到底还记得哪些键位，跳过我已经会的，**以便**我不必重练"啊哦鹅"这类我早已掌握的内容。

**验收要点**：
- **30 秒定位测（CN-C2）**：10 个韵母样本，覆盖高频键位
- 定位测结果 → 已掌握韵母直接标记，课程从 L1（词语）起步，而非 L0'
- 定位测**可跳过**，跳过后走默认值（全部韵母按未掌握处理）
- 定位测的掌握判定**同样受冷启动保护约束**（10 个样本 < 200 条 → 仅作起点参考，不作最终掌握宣告）
- 文案：「开始之前，先做 30 秒小测。我们会看你哪几个韵母已经形成肌肉记忆，把它们跳过——不用从『啊哦鹅』重头练一遍。」

### US-6｜我每天要打 5000 字，手很累（P1-a）

**作为**一个每天录入大量中文的办公人员，**当**我连续打字 20 分钟后明显感到速度和准确率同时下降时，**我想要**有专门的长文耐力训练和标点/数字/中英混排专项，**以便**我能把"后半程衰减"和"标点错字"这两个真实错误源分别解决。

**验收要点**：
- **长文耐力（CN-G3）**：10–30 分钟连续输入，1000–1500 字量级；需分段渲染（CN-G2）与断点续练（CN-G1，进度保存后可恢复）
- **标点专项（CN-G4）**：必须区分**全角/半角**，且必须**反转**现有 `isChineseSymbol()`（`src/utils/index.ts:44-47`）的拦截逻辑——在 `zh+ime` 下全角标点是合法输入，在 `code-match` 下仍需拦截
- **数字与中英混排（CN-D10）**：独立统计错误率，不混入汉字正确率
- 耐力指标：末 5 分钟速度衰减 ≤ 10%（详见 05）
- ⚠️ 长文渲染性能未验证（03 R8），依赖 Spike S3

### US-7｜我三周后要考书记员听打（P2）

**作为**一个三周后参加书记员打字考试的人，**当**我需要按考试的计分规则（有效字数、错一罚五、不许退格）模拟练习时，**我想要**一个能还原考试条件、用我自己的语料、并告诉我当前有效字数成绩的模拟器，**以便**我能准确评估自己离合格线还差多少。

**验收要点**：
- **计时考试模式（CN-F1）**：脱离 `CHAPTER_LENGTH = 20`（`src/constants/index.ts`）的章节结构，按时间而非词数结束
- **有效字数计分（CN-F2）**：`有效字数 = 正确字数 − 5 × 错误字数`；**成绩单以正确率为主视觉，速度为辅**
- **禁退格统计（CN-F4）**：需绕过 `bannedKeys` 对 `Backspace` 的拦截与 `Word/index.tsx` 的硬编码回滚（`setTimeout` 300ms 清空 `inputWord`）及 `wrongCount >= 4 → SET_IS_SKIP`
- **合格线判定（CN-F3）在法务语料未 clearance 前挂灰**，标注「待官方语料与门槛复核后开放」
- **语料来源**：降级形态下**仅支持用户自导入**（CN-H2）；CN-D9 公文/法律语料标注「法务前置，未 clearance 前不内置」
- **CN-F5 机考输入法可用性提示为 V1-a Must**，不因考试模式降级而后置

### US-8｜我想知道我的"打词率"是多少（P1-a / P2）

**作为**一个想专业地自我诊断的熟练用户，**当**我只看到"字/分"这一个数字时，**我想要**看到速录行业的标准指标（击键、码长、键准、键法、选重、打词率），**以便**我能判断我的瓶颈到底在"手速"、"编码习惯"还是"词组使用率"上。

**验收要点**：
- **专业指标（CN-E4）**：击键（键/秒）、码长（键/字）、键准、键法、选重、打词率，定义与公式详见 05
- **官方关系式必须在 UI 中呈现**：`速度 = 击键 × 60 ÷ 码长`。这是**唯一能让用户理解"为什么我手速不慢却还是打不快"的公式**（答案通常是码长过长或打词率过低）
- **字均用键对照**：全拼 4 / 双拼 3 / 音形 2.4——作为码长指标的参照锚点
- **每项专业指标必须配用户语言文案**（见 §5.3），**不得只显示裸数字与行业术语**
- ⚠️ **禁止复用现有 `wpm` getter**（`src/utils/db/record.ts`：`Math.round((this.wordCount / this.time) * 60)` 是"词/分"口径，中文需要"字/分"，详见 CN-E2）

## 5. 关键洞察（10 条）

### 5.1 洞察 1–4：双拼学习的阶段结构

#### 洞察 1｜双拼学习是一条 J 形（U 形）曲线，不是单调上升线（A 级）

**事实**：迁移期的速度轨迹为 **先降后升，且终点高于起点**。文献预期带：

| 时间点 | 相对全拼基线的速度 | 用户主观感受 | 弃坑风险 |
| --- | --- | --- | --- |
| Day 0 | 100%（全拼） | 「我要开始优化了」 | 低 |
| **Day 3** | **40–50%** | **「我是不是做错了决定」** | **★★★ 峰值** |
| Day 7 | ≈60% | 「有点起色但还是很慢」 | ★★ 次高 |
| Day 14 | 75–85% | 「快追上了」 | ★ |
| Day 30 | ≈100% | 「回到起点了」 | 低（但易在此停滞） |
| Day 60+ | 130–150% | 「值了」 | 极低（已毕业） |

**产品含义**：
- **Day 3 的速度下降是产品最容易被误判为"用户流失"的时刻，而它其实是学习发生的证据**。若数据看板把它报成红色退步，产品就在亲手制造流失。
- **J 形曲线定位卡（CN-C4）是 V1 唯一不可降级的"解释类"功能**。它不提升速度，它防止用户因为误解速度而离开。
- **30 天是一个危险的节点**：速度回到基线时，用户会想"那我图什么"。此时必须展示**码长下降**与**打词率上升**，让用户看到"虽然速度持平，但我的输入结构已经变了"，否则 Day 30 会出现第二个流失小峰。

#### 洞察 2｜学习期必须以过程指标为主，速度指标必须降级（D 级，研究者判断，但由洞察 1 支撑）

**四类过程指标（学习期主指标）**：
1. **已掌握韵母数 / 35**（双门槛判定，CN-C2a）
2. **击键（键/秒）↑**——手部速度，不受编码知识影响，学习期**持续上升**
3. **平均反应时 ↓**——认知检索速度，学习期**持续下降**
4. **编码正确率 ↑**——键位记忆准确度，学习期**持续上升**

**为什么这四个在学习期都单调向好、而速度不**：速度 = 击键 × 60 ÷ 码长，学习期码长虽然从 4 降到 3（有利），但**击键因认知停顿被拖累**（不利），后者占主导 → 速度下降。**而击键本身、反应时、正确率三个分量都在改善**。

**产品含义（这是本研究对产品最重要的一条约束）**：
- D0–D30 期间，**主视觉必须是过程指标**，速度只出现在「与自己的历史对比」视图中
- **速度数值在学习期不得使用红色/警示色/下降箭头**
- 结算页的第一行不得是"本次速度 XX 字/分"

#### 洞察 3｜"同键重复练习"会制造伪掌握，必须用双门槛识别（B 级）

**机制**：当练习集中在同一批韵母上时，用户会形成**逻辑预测**（"上一个键是 A，这个大概是 S"）而非**肌肉记忆**。表现为：同批练习正确率高、反应快；换新词立刻崩塌。

**这是 Day 6–7 二次门槛的成因**：用户在 Day 5–6 感觉"我会了"（同批练习成绩好），Day 7 遇到新词组发现不会，产生比 Day 3 更严重的挫败——因为 Day 3 是"预期内的难"，Day 7 是"以为会了却不会"。

**双门槛判定（CN-C2a）**：
```
未掌握 = 正确率 < 95%
       OR 该韵母平均反应时 > (该用户全部韵母反应时中位数 × 2)
```
**为什么用相对阈值而非绝对毫秒数**：无一手标定数据，任何绝对阈值都是猜的。相对阈值自适应每个用户的整体水平，**但会产生"人人达标"假象**（若用户全部韵母都在慢速推导，中位数本身很高）→ 因此需**绝对上限兜底**（方向明已裁，待数析评估具体规则）：触发则整体判为 S1/S2 阶段，不宣告任何韵母掌握。

**冷启动保护（CN-C2a）**：累计样本 < 200 条 OR 已出现韵母 < 10 个 → 不做判定，全部标 `learning`；单韵母样本 < 10 不参与判定。

**配套设计**：30% 混排复训（CN-C1a）是**对抗伪掌握的结构性手段**——强制每章掺入已学内容，打破"同键连续重复"的条件。

#### 洞察 4｜错误必须分两类归因，混在一起会导致错误训练（A 级）

| 错误类型 | 定义 | 训练处方 | 现有产品是否区分 |
| --- | --- | --- | --- |
| **键位映射错误** | 知道读音，按错键（如 `ang` 该按 H 却按了 G） | 键位复训、虚拟键盘高亮 | ❌ 全部竞品都不区分 |
| **拼音盲点错误** | 不知道正确读音（zh/z、ch/c、sh/s、an/ang、en/eng、in/ing、n/l、f/h 八组） | **拼音辨析**，键位训练无效 | ❌ |

**为什么必须分开**：对一个 `an/ang` 不分的用户，做 100 次键位复训也不会改善——**他的问题不在手上，在耳朵/语言习惯里**。混在一起统计会导致：① 热力图指向错误的键位；② 用户反复练不会的东西 → 挫败 → 弃坑；③ 产品的"弱点靶向"功能失效。

**产品含义（CN-C7，本研究判 Must；⚠️ 01 现为 Should/V1-c，分歧已上报方向明）**：八组易错音必须**独立统计**，并在诊断面板中**明示"这不是键位问题"**。这一条同时服务 P1-b（方言区/初学者）与 P0-β（把失败归因到错误原因的人）。

**数据来源零成本**：`Word/index.tsx:190` 的 `letterTimeArray.push(Date.now())`（逐字符时间戳 → 反应时）与 `:220-224` 的 `letterMistake[len-1].push(inputChar)`（逐位置错字 → 韵母级归因）**已经存在**，无需新增埋点。

### 5.2 洞察 5–7：工具在每个阶段应该提供什么

| 阶段 | 用户的真实障碍 | 工具应提供 | 工具**不应**提供 | 对应功能 |
| --- | --- | --- | --- | --- |
| **S0 决策期**（Day −1 ~ 0） | 不知道选哪个方案、不知道要多久 | 决策树推荐、可挽回性说明、J 曲线全景预告 | 一堆方案参数对比表（增加决策瘫痪） | CN-I1、CN-B8✚ |
| **S1 键位期**（Day 1–3） | 26 个键一次性压过来，认知过载 | 韵母分组渐进课表、虚拟键盘全提示、单韵母对码 | 整篇文章练习、速度数字、任何排名 | CN-C1、CN-C3、CN-D2 |
| **S2 巩固期**（Day 4–10） | 伪掌握、提示依赖 | 30% 混排、双门槛判定、提示分级衰减、弱点靶向 | "你已经掌握 X 个"的过早宣告 | CN-C1a、CN-C2a、CN-C3、CN-C2 |
| **S3 提速期**（Day 11–30） | 速度回到基线后停滞、动力衰减 | 码长/打词率指标、词组练习、J 曲线右端预告 | 与他人的对比 | CN-E1、CN-E4、CN-C4 |
| **S4 实战期**（Day 30+） | 练习文本与真实输入脱节 | 实战轨上屏、长文耐力、标点/数字/混排专项 | 继续做韵母练习（已毕业） | CN-A2、CN-G3、CN-G4、CN-D10 |
| **S5 专业/考试期** | 需要行业语言与考试规则 | 六项专业指标、计时考试、有效字数计分、自导入语料 | 学习期的鼓励文案（语境不符） | CN-E4、CN-F1、CN-F2、CN-H2 |

**洞察 5｜提示必须"衰减"而不是"开关"**（B 级）
现有竞品（含纸砚、ulpb）的键位提示是**用户手动开关**。手动开关的后果是可预测的：用户为了"挑战自己"关掉提示 → 错一片 → 挫败 → 关掉产品。**提示强度必须由掌握度驱动自动衰减**（CN-C3），且用户不应感知到"我在被降级提示"这件事。

**洞察 6｜"毕业"必须是产品的显式概念**（D 级，研究者判断）
所有现有练习器的设计目标是"让用户一直练"。但双拼学习的正确终点是**不再需要练习器**。产品必须显式定义毕业（CN-C3a 无提示毕业模式 + 35 个韵母全部掌握 + 实战轨达标），并在毕业时**主动引导用户离开学习闭环、进入实战轨**。这不会损失用户——**它会换来 P1-a 场景的用户（长文/标点/专业指标）和口碑传播**。反之，若产品在用户毕业后仍推送韵母练习，会被判定为"不懂双拼"，直接损失社区信誉。

**洞察 7｜碎片练习（5 分钟）与深度练习（20 分钟）是两个产品，不是一个滑杆**（C 级 → H5）
- 5 分钟用户的成功定义是**连续打卡不断**，主指标是 streak
- 15–20 分钟用户的成功定义是**14 天见效**，主指标是韵母掌握进度
- 30 分钟以上用户才需要长文耐力模块
**含义**：onboarding Q4 不是"设置每日目标"，而是**功能解锁的分流开关**。把长文耐力默认展示给 5 分钟用户会造成压迫感。

### 5.3 洞察 8–10：边界与文案

#### 洞察 8｜"声码"与"音形码"的边界必须在 V1 明确划死（A 级）

| 类型 | 代表方案 | 字均用键 | V1 是否支持 | 理由 |
| --- | --- | --- | --- | --- |
| **全拼** | 各输入法默认 | ≈4 | ✅ 支持（CN-B2） | 作为基线对照 + P1-b 起点 + 考场可用 |
| **声码（双拼）** | 小鹤、微软、自然码、搜狗 | ≈3 | ✅ **V1 核心** | P0 的全部价值都在这里 |
| **音形码** | 小鹤音形、自然码辅助码 | ≈2.4 | ❌ **V1 不做** | 需额外的形码拆字规则库，复杂度是双拼的 3 倍以上，且用户量远小于双拼 |
| **形码** | 五笔 | ≈2–4 | ❌ **V1 不做** | 与双拼的心智模型完全不同（拆字形而非拼读音），属另一个产品 |

**为什么必须现在划死**：音形码是双拼社区的高频话题（"学完双拼下一步是音形"），**若 V1 不表态，会被社区反复追问，消耗维护精力**；若表态含糊，会有贡献者提交音形方案 PR，而引擎并不支持形码拆分 → 返工。**建议在 spec 与 README 中显式声明"V1 仅支持声码（全拼 + 双拼），音形/形码不在路线图上"，并说明技术原因（形码需要拆字规则库，与 `{keyMap, zeroMap}` 抽象不同构）。**

**同时需明确**：**CN-B1 的可插拔方案格式与 CN-H1 的方案 JSON 导入**均**只接受声码方案**。导入格式必须在 schema 层面拒绝形码字段，而不是"允许导入但行为未定义"。

#### 洞察 9｜专业指标必须翻译成用户语言，否则等于没有（D 级）

速录行业指标（击键/码长/键准/键法/选重/打词率）对 P2 是**母语**，对 P0/P1-a 是**天书**。若只显示术语与裸数字，会产生两种失败：① P0 看不懂 → 忽略 → 功能无效；② P0 看懂了但数字在恶化 → 挫败。

**因此每项专业指标必须同时提供：术语名（给 P2）+ 用户语言解释（给 P0/P1-a）+ 鼓励句 + 低谷期句。**

**完整文案表（交付三，可直接被 02/05 引用）**：

| 指标 | 示例读数 | 用户语言解释 | 鼓励句（正常/向好时） | 低谷期句（数字恶化时） |
| --- | --- | --- | --- | --- |
| **击键** | 4.2 键/秒 | 你的手有多快 | 「你的手已经跟上了——每秒 4.2 次按键，这个手速足够打出 100 字/分。现在缺的不是手，是键位的熟练度。」 | 「击键 4.2 键/秒说明你的手没退步。速度慢下来是因为大脑在找键位——**这正是双拼学习第 3 天的正常状态**，手部数据是好的。」 |
| **码长** | 2.1 键/字 | 打一个字要按几次键 | 「平均每字 2.1 键，已经接近双拼的理论下限（2 键）。全拼是 4 键——**你的输入结构已经变了**。」 | 「码长 2.1 已经很接近双拼的理论值了。这说明你不是打得慢，是**还在想**——想清楚了，速度自然回来。」 |
| **韵母掌握** | 18 / 35 | 有多少个键位已经不用想了 | 「35 个韵母你已经掌握了 18 个，超过一半。剩下的 17 个里有几个是天生就难的（比如 iang/uang、ong/iong）。」 | 「18/35 看起来没过半太多，但**掌握度不是匀速增长的**——前 10 个最难，后面会快。你现在正处在最陡的那一段。」 |
| **反应时** | `[待标定]`（相对判定） | 看到字到按下键的犹豫时间 | 「你对这些韵母已经不用犹豫了，手是直接过去的。」 | 「这个韵母你的反应明显偏慢——**不是你不会，是它还没变成条件反射**。它会进你的专项练习。」 |
| **编码正确率** | 96% | 键位按对的比例 | 「96% 的编码正确率意味着你的键位记忆已经稳了，接下来只是提速。」 | 「正确率暂时掉下来很正常——**你刚开始练新的韵母组合**。等这批韵母进入掌握，正确率会一起回来。」 |
| **键准率** | — | 每个键按得准不准（含误触邻键） | 「你的键准很稳，误触很少，说明指法是对的。」 | 「误触多了一点，可能是手累了。**长文练习后半程的键准下降是普遍现象**，不是你的问题。」 |
| **键法** | — | 指法是否规范（哪根手指按哪个键） | 「你的指法分配很合理，这是能长期提速的基础。」 | 「有几个键你在用不顺手的手指按。**现在改比以后改容易得多**——键位图会提示正确的手指。」 |
| **选重率** | — | 需要选候选词的比例（实战轨） | 「选重率低说明你的词组打得好，输入法能直接给你想要的字。」 | 「选重率高通常是因为在打单字。**试着打词组而不是逐字打**，速度会立刻不一样。」 |
| **打词率** | — | 输入中词组（而非单字）的占比 | 「你的打词率在上升——**这是提速最有效的一条路**，比练手速收益大得多。」 | 「打词率还偏低。双拼的真正提速来自词组，不是单字。L3（成语）和 L4（句子）会帮你把这个数字拉上来。」 |

**通用低谷期原则（三条，适用于所有文案）**：
1. **永远不说"你退步了"**，说"这在这个阶段是正常的"
2. **永远给出一个仍在向好的分量**（击键、码长、掌握数三者中至少有一个在学习期单调向好）
3. **永远给出下一步的具体动作**，不停留在安慰

#### 洞察 10｜隐私与本地化是这个社区的价值观底线，不是功能偏好（A 级）

`qwerty-learner` 的全部练习数据存在本地 IndexedDB（Dexie），无账号体系。这不是技术偷懒，是**产品的价值主张**（README 与社区讨论反复强调）。

**因此以下设计一律禁止**（详见 §7）：
- 全站排行榜（需要上传数据）
- 账号体系与云同步
- 任何形式的"与他人的对比"

**允许的替代**：**本地生成的分享卡（CN-I7✚，Could）**——用户主动截图分享，数据不上传，**且默认不生成、需用户点击**。这与排行榜的本质区别是：**用户掌握披露的主动权**。

## 6. onboarding 决策树（含机考判定）

### 6.1 设计原则

1. **可跳过**——强制问卷会流失 P0-γ（老手不想回答新手问题）
2. **每个问题必须改变后续行为**，不问无法执行的问题
3. **必须处理"选错方案"的焦虑**——可挽回性说明是降低决策瘫痪的关键
4. **必须主动拦截考场兼容风险**——这是唯一一条"不提示的代价高于提示的代价"的信息

### 6.3 跳过 onboarding 时的默认值

**默认值**：小鹤双拼 + L0' 起点 + 每日 15 分钟 + 不做定位测（全部韵母按未掌握处理）。

**理由**：小鹤是社区教程最多、GitHub 上呼声最高的方案；跳过 onboarding 的用户多为社区来的双拼意向用户；L0' 起点对老手有轻微冗余，但**冗余的代价（多练几分钟）远小于跳过基础的代价（键位记不牢）**。

### 6.4 考场兼容提示卡（强制展示，需二次确认才能跳过）

**触发条件**：Q1 选 C，**或** Q2 答"是/不确定"但用户仍选择了小鹤双拼。

> ⚠️ **考场可能用不了小鹤双拼**
>

## 10. 本文档的核心结论（8 条）

1. **P0 不是"想打快的人"，是"卡在 Day 3–14 想弃坑的双拼迁移者"**。产品价值集中在这段有明确起点和终点的旅程里，而这恰好是全部现有工具集体失效的区间——**它们都提供键位表和练习文本，没有一个告诉用户"你现在在曲线的哪个位置"**。

2. **P0 的第一价值不是"练"，是"解释"**。J 形曲线定位卡（CN-C4）在用户价值上高于任何练习模式增强——它是唯一能直接对抗"把正常学习误归因为个人能力不足"这一弃坑主因的设计。

3. **学习期必须以过程指标为主，速度指标必须降级**。D0–D30 速度必然下降，任何以速度为主色的警示都会系统性地把"正常学习"误报为"退步"，亲手推走 P0。这是 CN-A3（双轨口径分离）与 CN-C4（J 形曲线定位卡，含学习期速度衰减率的预期带对照）为 Must 的根本原因，也是 05 必须遵守的口径约束。

4. **P0 内部有三个变体（理性优化者 / 社区跟随者 / 回流重试者），弃坑诱因分别是自我效能崩塌、认知负荷过载、被当成新手的羞辱感**——三者需要**不同的干预**（解释 / 渐进课程 / 定位测），不能用一套设计覆盖。这是 CN-C1、CN-C2、CN-C4 三者都不可省的用户侧依据。

5. **P1-a（办公提速）是 Ⅱ 簇的唯一验证对象，P2（考试）是 Ⅳ 簇的唯一验证对象，两者与 P0 的价值主张几乎不重叠**。这构成了"Ⅰ 簇 + Ⅱ 簇都不可切"的用户侧依据：砍 Ⅱ 丢存量最大的市场，砍 Ⅰ 丢痛感最强的市场。

6. **两条硬约束来自外部而非用户偏好**：① 考场只预装全拼/微软双拼/五笔 → **CN-F5 可用性提示必须 V1-a 上线**（纯文案、成本近零、防信任崩塌），微软双拼必须 V1-a 内置；② **本产品不教拼音**（Issue #784 已 Closed as not planned），L0' 是"韵母表 + 单韵母对码"，不是拼音启蒙。

7. **12 条 Won't have 中有 8 条是 A 级证据**（W1 排行榜 / W3 儿童拼音 / W4 移动端对码 / W6 五笔音形 / W7 账号云同步 / W10 官方口诀 / W11 输入法联动 / W12 纸砚代码），**任何后续需求若要推翻，必须提供 A/B 级新证据**。其中 W1 与 W7 不是功能取舍，是**社区价值观底线**（全部数据存本地 IndexedDB 是产品的价值主张）。
