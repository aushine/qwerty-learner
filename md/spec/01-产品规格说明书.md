## 📌 TL;DR

把 qwerty-learner 从「外语单词打字练习」扩展为「**中文输入法（全拼 / 双拼音码）打字练习**」：复用现有逐字符打字引擎与本地记录体系，新增**双轨输入判定**（对码学习轨 `code-match` 绕过系统 IME 校验编码；上屏实战轨 `ime` 用真实输入法做句/诗/文章练习）、**可插拔方案引擎**（V1 内置全拼 + 小鹤双拼，架构预留微软/自然码/搜狗）、**L0'~L7 九级语料体系**（韵母分组 → 单字 → 词 → 成语 → 句 → 诗 → 文章 → 公文 → 标点混输），以及**竞品全空白的学习深度**（韵母分组渐进课表、薄弱项专项队列、掌握度双门槛、反应时防伪掌握、J 形曲线定位、固定文本每日复测）。

核心人群是 **U1 双拼迁移者**（全拼→双拼第 0-60 天）。🔴 **v1.2 更正（回填 `07` §1）：其核心动机不是「想打快」，而是「想不弃坑」**——他们已经在双拼上，问题是撑不过前 30 天，因此 V1-a 的全部设计目标是「别让我放弃」而非「让我更快」。U1 内含三个子画像（**P0-α 理性优化者**需「解释而非激励」/ **P0-β 社区跟随者**需「渐进课表 + 掌握度可视化」/ 🆕 **P0-γ 回流重试者 = U1-γ** 需「定位测 + 跳过已掌握」，是竞品全空白能力），详见 §3.1。**指标体系已按裁定 D 分三层**：产品价值层北极星 = **60 天毕业率**（`08`，季度，V1.2 可观测）/ V1.0 阶段门禁 = **D3 当日留存率**（日，`〔代理指标，无后端〕`）/ 能力达标口径 = **Net CPM + 首次命中率**（`05`，周）。V1 **已裁定拆三次发布**（V1.0-alpha 2027-02-19 / V1.0 2027-06-11 / V1.1 2027-09-28 / V1.2 2028-02-16；共 66 条 = V1-a 33 / V1-b 13 / V1-c 20，**无一条被砍**；`10` v3 实测全量 339~529 人日），**前置阻塞项 2 个**：既有 `inputAccuracy` 括号 Bug（CN-J1，✅ 裁定修复）与按键捕获兼容性 Spike S1（CN-A1a）。

一句话价值主张：**「一个网址，从零到超越全拼」——monkeytype 不做中文输入法练习，小鹤官方没有现代 Web 练习器，我们做。**

## 1. 问题陈述

### 1.1 要解决什么问题

**问题一句话**：想学/在学中文双拼（或其他音码方案）的人，**没有一个「一站式、免费、现代 Web、带学习路径」的练习工具**；同时 qwerty-learner 的 23k+ star 存量用户中，有相当比例的人其真实练习需求（中文输入法）**在本产品内完全无法满足**。

拆解为三个子问题：

| # | 子问题 | 现状证据 |
|---|---|---|
| **P-1** | 双拼学习者的工具**分散在 5 个渠道且无单一入口** | 小鹤官方生态 = 网盘里的 .NET 4.0 exe 练习器 + QQ 群发文 + 飞扬版敲 `orm`/`oqm` 隐藏命令查文档 + 微信小程序 + 论坛贴吧。**没有现代 Web 练习器**（详见 `06`） |
| **P-2** | 现有 Web 竞品存在**结构性缺口**：要么单一方案、要么付费墙、要么无学习路径、要么许可不允许复用 | `z1803406304/shuangpin-practice`（功能最完整、81 单测、码表交叉验证 99.649% 一致）**但只支持小鹤一种方案、无章节/关卡体系、成语与诗句语料缺失**；`Return7-T/Shuang`（20+ 方案）**许可禁止商用、无语料分级、UI 支持到 IE9**；`KeySpell` VIP 锁错词本/数据报告/自定义文本；`ulpb.app` 词组与文章练习**必须下客户端**且 ¥69 买断挑战；`TypingClub` 免费版数据仅留 30 天（详见 `06`） |
| **P-3** | 中文打字练习的**指标体系与语料分级在 Web 产品上完全缺位** | 击键 / 码长 / 回改（添雨跟打器 = 中文打字圈事实标准、小鹤官方推荐）在 Web 端无人实现；「字→词→成语→句→诗→文章」六级渐进 + 章节化，**无人占位**（详见 `06`） |

### 1.2 这是谁的问题

**主问题人群 = U1 双拼迁移者**（详见 `07`）。其痛点不是「不会打字」，而是：

1. **速度倒退的挫败**：学习期速度会掉到全拼的 **60%**，Day 3 达到放弃峰值（情绪 1.5/10，速度 40-50%），Day 6-7 是第二道坎「值不值得」（2.5/10，速度 ~60%）
2. **伪掌握陷阱**：用户原话——「重复同键位练习时**大脑通过逻辑判断预测出了将要出现的键位**……产生了学会双拼的错觉，**真实使用时又会抓瞎**」
3. **反馈缺失**：分不清「是声母想不起来还是韵母记错了」；不知道「我错在哪、该练什么」
4. **选型焦虑 + 方案不一致**：「练习工具与系统输入法方案必须一致」是双拼练习第一大故障源（「双拼越练越废」）

**次问题人群 = U2 文字工作者 / U3 考试备考者**：前者需要长文耐力与速度衰减率，后者需要限时模考 + 有效字数计分 + 合格线判定（NCRE 一级 20~30 字/分且准确率≥90%、书记员看打 70~80 字/分且≥90-95%）。

### 1.3 这个问题有多大

| 维度 | 量化 |
|---|---|
| **社区诉求存在时长** | **3 年**。上游 Issue #1009 / #726 / #348 / #230 / #763 / #744 反复出现中文练习诉求，PR #348（2023-03 开、2023-05 关）**评论区仅 vercel[bot] + stale[bot] 两条机器人发言，零条人类 review** → 死因是无人承接，不是技术否决 |
| **同类竞品的拒绝** | monkeytype Issue #4673（中文输入支持）状态 **closed as not planned**，根因是其输入校验架构与 IME composition 不兼容，用户实测「This makes typing in Chinese basically impossible on Monkeytype」→ **该生态位至今空缺** |
| **中文打字练习市场规模（间接证据）** | 打字鸭 **500 万用户**、TypeFun **200 万用户**（均为儿童/通用市场，非双拼）；说明「中文打字练习」作为品类有真实体量，只是**双拼细分**被现有工具服务得极差 |
| **我方可触达规模** | qwerty-learner 23k+ star、存量 MAU 中程序员/键盘工作者占比高，与双拼学习者**高度同构**，讨论都集中在 V2EX / Linux DO / 少数派。预估转化 **3-8% 现有 MAU**，且**无需拉新成本**（只需在词典选择页点亮新入口） |
| **付费墙错位空间** | KeySpell / ulpb / TypingClub 收费锁定的三项能力（**错词本、数据报告、自定义文本**）**恰是 qwerty-learner 已免费开源的既有资产** → 我方「免费 + 完整」即构成差异化，无需价格战 |

### 1.4 为什么是现在、为什么是我们

- **为什么是现在**：`shuangpin-practice`（2026-09 首发）证明该需求真实且可被单人实现；但它只支持一种方案、无章节体系 → **窗口期内可超越**。
- **为什么是我们**：数据抽象已被验证两次（日语 romaji 词典 = `name` 罗马音 / `notation` 假名；山人码 fork = `name` 编码 / `notation` 汉字），**中文双拼是同一条抽象的第三次复用**；打字引擎、记录体系、错题本、热力图基建、发音（`zh` 已在 `LanguagePronunciationMap`）、分享图**全部现成**（F1/F4/F6/F14/F17/F18/F20）。

## 2. 产品目标

三个目标必须**正交**（互不替代、各自可独立衡量）：

| # | 目标 | 一句话定义 | 衡量方式 | 反目标（不要误读为） |
|---|---|---|---|---|
| **G1** | **让双拼新手在 14 天内不放弃** | 用学习路径 + 阶段化 UI + 低谷干预，把「Day 3 放弃峰值」这道坎变成产品能力 | **V1.0 阶段门禁 = D3 当日留存率 `〔代理指标，无后端：用本地连续打卡日数分布，只能看相对趋势〕`**；辅助 = D7/D14 留存、依赖提示率下降曲线。（⭐ 注：产品价值层北极星是 `08` 的 **60 天毕业率**，见 §5.1 裁定 D；G1 是「接住弃坑峰」的过程目标，不等于产品成败的最终裁决） | ❌ 不是「让用户打得快」——S1-S3 阶段速度**必然**下降，追求速度会杀掉留存 |
| **G2** | **让练习数据可信、可归因、可行动** | 双轨指标口径分离 + 韵母级掌握度 + 错因归因，把「我错在哪、该练什么」变成确定性输出 | 韵母掌握度覆盖率、专项队列点击率、指标自校验误差（`字/分 ≈ 击键 × 60 / 码长`，误差 <5%） | ❌ 不是「做 AI 自适应算法」——用户只需要一条确定性统计 + 队列规则 |
| **G3** | **让方案与语料可被社区低成本扩展** | 「支持一个新方案」= 加一份方案表 + 重跑构建脚本，**不改代码**；「贡献一份语料」= **只写汉字**，编码/注音/多音字检测全部自动生成 | 新增方案的代码改动行数（目标 ≤1 行注册）、语料贡献者无需本地环境的 PR 占比、CI 校验通过率 | ❌ 不是「内置尽可能多的方案」——V1 只做全拼 + 小鹤，其余留口 |

**非目标（产品层面）**：不做账号体系、不做云同步、不做社交、不做商业化收费墙。理由见 §7。

**关键洞察（I5）**：速度指标在学习期是**反向的**——越努力练，短期内数字越难看。因此 S1-S3 必须用「掌握度」而非「速度」作为主指标，且**必须紧跟社区经验值对照**（「第 4 天，当前速度 = 全拼基线的 62%，属正常区间」），绝不能孤立显示数字。

### 3.3 边界声明：只做音码（I2）

**「只做音码」的边界定义** = 定长 2 键 + 不需要拆字知识 + 不需要「提笔不忘字」。

守住这条线：工程量减半、用户门槛减半。破了这条线：产品滑向五笔地狱难度，且社区反证明确（「别学五笔快跑」「提笔忘字一票否决」）。**一旦做音形码，用户立刻会要五笔，产品定位从「打字练习」滑向「输入法教学软件」**。

### US-2 · 打对自动前进的对码练习（U1）

> **作为** 双拼学习者，**我想** 用「打对就自动进下一字」的方式练单字与词组，**以便** 不被系统输入法的候选窗和选词动作打断节奏。

**验收标准**：
- Given 我在 L1（单字）或 L2（词组）或 L3（成语）语料下练习，When 我敲入的键序列与目标字在当前方案下的编码**逐字符匹配**，Then 每敲对一个键即时高亮为正确态，**敲完最后一键自动进入下一个字，无需按空格**
- Given 目标字「快」在小鹤双拼下编码为 `kk`，When 我依次按下 `k`、`j`，Then 第 1 键标绿、**第 2 键标红**，且 `letterMistake[1] === 'j'` 被记录（F4 现有埋点直接复用）
- Given 我在对码轨，When 我的系统输入法处于中文态，Then **按键仍被正确捕获为原始字母**（因 `input type="password"` 在浏览器/OS 层强制关闭 IME），**不弹出任何阻塞式 alert**
- Given 练习进行中，When 我按下 `Esc`，Then 进入暂停态：不接收输入、不计入用时、不触发卡住提示
- [ ] 对码轨输入字符集**仅接受字母 `a-z` 与半角分号 `;`**（分号用于微软双拼 `ing`），其余按键不产生输入但也不报错

### US-3 · 用真实输入法练句子与文章（U2 / U1-S4+）

> **作为** 已度过键位学习期的用户，**我想** 用我自己的真实输入法（含候选窗、词组联想、纠错）练习句子、诗句和文章，**以便** 练到的是「真实打字场景」而不是「实验室场景」。

**验收标准**：
- Given 我在 L4（短句）/ L5（诗）/ L6（文章）语料下练习，When 我用系统输入法选词上屏，Then 系统在 `compositionend` 取 `e.data` 作为**唯一可信数据源**，与目标文本做 diff，**不依赖 `input` 事件的 `isComposing` 时序**（Chrome/Safari/Firefox 三浏览器事件顺序不同，详见 `02` §3）
- Given 我一次上屏多个字（如「今天」），When 校验执行，Then **本次上屏的每一个字都被逐一校验**（现有引擎只比对末位字符，属必须修复的 Bug，见 `02` §3.4）
- Given 目标句含全角标点 `，。`，When 我上屏全角标点，Then 判定为正确（`isChineseSymbol` 在 `zh+ime` 下**反转逻辑**）；Given 我上屏半角 `,.`，Then 判定为错误并**单独归类为「标点格式错误」，不与错字混算**（CN-G4）
- Given 我的输入法开启了纠错，When 我打错拼音但输入法上屏了正确的字，Then **判定为正确**，但单独计入 **`IME 辅助上屏数`**，与「零辅助上屏数」分开展示（CN-A2a）
- Given 我在实战轨且当前为英文态，When 我上屏了纯拉丁字符而目标是汉字，Then 系统给出**非阻塞提示「请切换到中文输入法」**，**不直接判错**

### US-4 · 长文分段续打（U2）

> **作为** 需要练耐力的文字工作者，**我想** 打一篇 1500 字的文章时能中途关闭页面、下次接着打，**以便** 不必一次性坐 30 分钟。

**验收标准**：
- Given 我在 L6 文章练习中打到第 400 字，When 我关闭页面后再次打开，Then 系统提示「上次练到第 400 字，是否继续？」，且**已完成部分的成绩被保留**

- [ ] （CN-G2，**阻塞**）Given 1500 字长文 + 已练 10 分钟累计 5000+ 按键记录，When 我持续输入，Then **输入到屏幕反馈延迟 <50ms、滚动无掉帧、10 分钟内存涨幅 <50MB**（中端笔记本 Chrome 实测）。这是竞品明确翻车点，必须在 CI/性能测试中固化
- Given 我完成 10-30 分钟连续练习（CN-G3），When 结算，Then 显示**速度衰减率** = `(前半程字/分 − 后半程字/分)/前半程字/分 × 100%`；<10% 时给出「耐力优秀」反馈

### 5.1 指标体系（✅ v1.2 已按主理人**裁定 D** 重构为三层）

> ### ⚠️ v1.2 重大修订说明
> 本文档 v1.0 把 **D3 当日留存率**定为唯一北极星。**主理人裁定 D 不予采纳此归属**，改为三层分工（析客的「时间尺度」划分被采纳，但唯一北极星归属 = `08` 的 60 天毕业率）。
> **裁定理由（析客认同，并承认自己先前的建议存在治理盲区）**：`08` 明确警告「**60 天毕业率与常规增长逻辑相反，必须锁定，否则后续会被『提升留存/时长』的需求反向侵蚀——这是本研究识别出的最大产品治理风险**」；`07` 同源（「练习器的成功指标不是 DAU 时长，而是**用户多久能不再需要它**」）。🔴 **若把 D3 留存定为唯一北极星，恰好构成了瑞思警告的那种侵蚀**——产品会被激励去优化「让用户第 4 天回来」，而非「让用户学会后不再需要它」。

| ⭐ **产品价值层北极星** | **60 天毕业率**（35 个韵母全部无提示毕业 + 实战轨达标） | **季度**（🔴 **V1.2 才可观测**，因毕业需 60 天且依赖完整 L0'~L7 语料） | `08` | `[待标定]`（`08` 明确要求「**禁止在 V1 阶段写死绝对数字**」） |

> **D3 当日留存率的定义（作为 V1.0 阶段门禁保留）**
> **定义**：首次完成中文练习（任意一条对码轨题目）的用户中，**在第 3 个自然日（D+3，允许 ±1 天窗口）再次完成至少 1 次练习**的比例。
> **为什么是 D3 而不是 D7/D30**：`08` 的新手旅程数据显示 **Day 3 是情绪谷底（1.5/10）+ 速度谷底（40-50%）+ 放弃峰值**的三重重合点。**D3 留存是整个学习曲线的唯一咽喉**——过了 D3，D6-7 是第二道坎（`08` §1.2 的「假高点后的真谷」，2.5/10），但强度更低；过了 D14（入门线，7/10），流失基本停止。
> **它为什么只能是「门禁」而非「北极星」**：它是 **V1.0 唯一可观测的上线判据**（毕业率需 60 天 + 完整语料，V1.0 阶段根本量不到），但**产品成败仍由毕业率裁决**。

> ### 🔴 `〔代理指标，无后端〕` 标注说明（主理人硬性要求，不得省略）
> **本项目无账号、无后端、纯本地 IndexedDB**，因此 D3 留存**无法做全站聚合统计**。主理人裁定采纳析客方案：**用「本地连续打卡日数分布」作代理指标**。
>
> | 项 | 说明 |
> |---|---|
> | **代理口径** | 本机 IndexedDB 的练习时间戳序列 → 计算「连续打卡日数」的分布（P25/P50/P75），而非跨用户的 D3 留存率 |
> | **🔴 能力边界** | **只能看相对趋势，不能看绝对留存率**。可用于：① 版本前后对比（同一批用户的打卡分布是否变好）② 小样本调研（问卷/GitHub Discussion/社区回帖的自述口径） |
> | **🔴 禁止行为** | **不得把代理值当作真实 D3 留存率对外宣称**（例如不得写「我们的 D3 留存率是 42%」）。所有对外沟通必须写明「本地连续打卡日数分布」这一代理口径 |
> | **不可用于** | A/B 实验指标（无全站聚合能力）；任何需要跨用户统计显著性的结论 |
> | **若要真实留存** | 必须先决策是否引入匿名自愿上报——但这与「本地隐私优先」基因冲突（NG-9），**析客不建议** |

|---|---|---|
| **G-1 伪掌握率** | ≤15% | 防止「同批练习正确率虚高」掩盖真实掌握度（`08` §1.2 的 Day6-7 真谷） |
| **G-2 提示依赖度** | 毕业时 ≤0.2 次/词 | 防止「靠提示刷完课程」的假毕业 |
| **G-3 数据本地性** | = **100% 硬约束** | 任何上报行为都是违约 |
| **G-4 存量用户无回归** | = **100% 硬约束** | 380 个既有词典不受影响 |

| # | 要求 | 说明 |
