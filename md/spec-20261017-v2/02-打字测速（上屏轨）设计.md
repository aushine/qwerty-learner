**日期**：2026-10-17（第二批）

**基线依据**：`基线 02` §3（上屏实战模式详细设计，CN-A2 / A2a）、§4（错误处理策略）、§1.3（口径纪律）

## 1. 背景与目标

### 1.1 与现有两种输入方式的根本区别

| | 全拼 / 双拼（对码轨 `code-match`） | **打字测速（上屏轨 `ime`）** |
|---|---|---|
| 判定对象 | **击键序列**是否符合目标编码 | **最终上屏的汉字**是否符合目标文本 |
| 关心用户用什么输入法吗 | 不关心，但**必须关掉 IME**（password 强制英文态） | ✅ **完全不关心**——用户可以用搜狗、微软拼音、五笔、双拼，只要能打出正确的字 |
| 候选窗 | ❌ 无 | ✅ 有（用户真实的候选窗） |
| 练的是 | 键位记忆（「这个韵母在哪」） | **真实打字速度**（「我能多快把这段话打出来」） |
| 典型语料 | 字 / 词 / 成语 | **句 / 文章** |
| 指标 | 击键、码长、编码正确率 | **字/分（CPM）**、字准确率、回改次数 |

> **一句话**：全拼/双拼练「怎么按」，打字测速测「打得多快」。

### 1.2 目标

| # | 目标 |
|---|---|
| G1 | 在中文的二级选择里，与「全拼」「双拼」**并列**出现「打字测速」 |
| G2 | 选中后，练习页**切换到上屏轨**：普通输入框、可用任何输入法、有候选窗 |
| G3 | 以**字/分（CPM）**为主指标；打错只标红，**不回滚整句** |
| G4 | 英语 Tab 本身就是打字测速（不重复给「打字测速」按钮） |
| G5 | 对码轨（全拼/双拼）**完全不受影响** |

### 1.3 非目标

- ❌ 不做「IME 辅助上屏数」的精确统计（基线 §3.4 已判定不可精确，本批次**不做近似**，直接不显示）
- ❌ 不做速度衰减率（需要 ≥10 分钟连续练习的数据，后续批次）
- ❌ 不做考试模考
- ❌ 不做中英态自动切换（Web 无 API）

## 2. 位置与选择结构（SPEED2-01 / SPEED2-02）

### 2.1 二级按钮行

```
中文 Tab：
  [全拼]  [双拼 ▾]  [打字测速]
```

| 项 | 行为 |
|---|---|
| **全拼** | `scheme = 'quanpin'`，对码轨 |
| **双拼 ▾** | `scheme = 'flypy'`，对码轨，hover 展开二级（小鹤） |
| **打字测速** | `inputTrack = 'ime'`，上屏轨 |

**SPEED2-01（数据结构）**：引入一个新的维度 `inputTrack: 'code' | 'ime'`，**与 `schemeId` 并列**，不混用：

```ts
export type TypingInputTrack = 'code' | 'ime'
```

| 组合 | 含义 |
|---|---|
| `track='code'`, `scheme='quanpin'` | 全拼对码 |
| `track='code'`, `scheme='flypy'` | 小鹤对码 |
| `track='ime'`, `scheme='quanpin'`（**取值固定为 quanpin，无意义**） | 中文上屏测速 |
| 英语（`schemeId='en'`） | 恒为上屏轨（英语本来就是打字母上屏，无需 IME；但**走同一套 `ime` 判定**以保证指标同口径） |

> 🔴 **SPEED2-01-1（不得复用一个字段）**：「全拼/双拼/打字测速」是三个**互斥选项**，但内部是两个正交维度。若把三者塞进一个 `scheme` 枚举（如 `'quanpin' | 'flypy' | 'ime'`），后续「用小鹤方案做上屏测速」就无法表达。**必须拆成 `inputTrack + scheme`。**

**SPEED2-02（互斥与状态）**：

| 操作 | `inputTrack` | `scheme` |
|---|---|---|
| 点「全拼」 | `code` | `quanpin` |
| 点「双拼」 | `code` | `flypy` |
| 点「打字测速」 | `ime` | 保持原值（不重置，回到双拼时仍是上次的小鹤） |
| 从英语切回中文 | 保持上次的 `inputTrack` | 保持 |

- 选中态的**高亮归属**：`inputTrack==='code' && scheme==='quanpin'` → 高亮「全拼」；`code && flypy` → 高亮「双拼」；`ime` → 高亮「打字测速」。
- 「双拼」在 `inputTrack==='ime'` 时**不高亮**（即使 `scheme==='flypy'`）——避免两个按钮同时高亮。

## 3. 上屏轨的交互（SPEED2-03 ~ SPEED2-08）

### 3.1 输入元素与事件（**必须直接监听 `compositionend`**）

```
<input/textarea>（普通元素，非 password）
  compositionstart  → 置 isComposing=true；★ 不 alert、不 return
  compositionupdate → 仅用于「候选回显」（把当前拼音串以浅灰显示），不参与校验
  compositionend    → ★ 唯一可信数据源：取 e.data = 本次上屏的完整文本
                      → 整串提交给 diff 校验
  input             → ★ 不用于校验（Chrome 会补发 isComposing:false 的 input，Safari 顺序不同）
                      仅用于兜底：非 IME 直接输入（粘贴、英文态敲字母）
```

**SPEED2-03（硬约束）**：**禁止**使用 `isComposing` 在 `input` 事件里做判定（基线 §3.1 已给出三浏览器时序差异表；现有 `TextAreaHandler:23` 就是这个错误）。

**SPEED2-04（输入元素选择）**：

| 场景 | 元素 | 理由 |
|---|---|---|
| 中文上屏 | `<textarea>`（`h-0 w-0 opacity-0` 隐藏，聚焦管理同 `TextAreaHandler`） | password 与 IME 互斥；textarea 支持多行与换行 |
| 英语上屏 | 同上（**同一个组件**，只是 `lang` 与判定字典不同） | 统一实现，减少分支 |

> ⚠️ **SPEED2-04-1（不能用 `contenteditable`）**：`contenteditable` 在部分输入法下会产生额外的 `compositionend` 碎片与不可控的 DOM 结构，且难以取到稳定的 `e.data`。**必须用 `<textarea>`。**

### 3.2 文本 diff 判定（SPEED2-05）

> 基线 §3.2 已指出当前 `Word/index.tsx:180` 的缺陷：**一次上屏多字只校验末位字符**。上屏轨必须实现正确的区间 diff。

```
输入：prevLen（本次上屏前已提交长度）、newText（本次 compositionend 的 e.data）、target（目标文本）
1. 取区间 [prevLen, prevLen + newText.length) 与 target 同区间逐字符比对
2. 全部相等 → 该区间全部标记 correct，推进游标
3. 首个不等的位置 p → target[p] 标记 wrong，记录实际字符（用于「最常错的字」）
                   → 其后的字符**仍继续比对**（markOnly），不因为一个错字而全部标错
4. 长度溢出（newText 超出剩余目标长度）→ 多余部分丢弃并计入「多打」1 次
5. 漏打（`e.data` 比预期短）→ 不补偿；游标按实际提交长度前进，允许多次上屏补齐
```

**SPEED2-05-1（标点口径，**这是最容易踩的坑**）**：

| 目标字符 | 用户输入 | 判定 | 理由 |
|---|---|---|---|
| 汉字 | 相同汉字 | ✅ 正确 | — |
| 汉字 | 不同汉字 | ❌ 标红，继续 | markOnly |
| 全角标点 `，。！？；：、` | 相同全角 | ✅ 正确 | — |
| 全角标点 `，` | 半角 `,` | 🔴 **视为错误，但归类「标点格式」**，与错字分开计数 | 基线 §3.3 |
| **换行** `\n`（文章分段） | 不输入 | ✅ **自动跳过，不计错、不要求用户打** | 见下 |
| **空格**（英文词间） | 空格 | ✅ 正确；英文必须打空格 | — |
| 中文词间空格（文章排版用） | 不输入 | ✅ 自动跳过 | — |

> 🔴 **SPEED2-05-2（换行必须自动跳过）**：文章素材的 `notation` 含 `\n`（分段）。若要求用户「打回车」，会与「上屏即校验」冲突（回车不是上屏事件），且中文输入法下回车常被候选窗吃掉。**因此：`\n` 与中文排版空格在游标推进时自动跳过**（实现：在 `target` 预处理时把它们标记为 `skippable`，游标前进时遇到即跳过）。

**SPEED2-05-3（中文标点用全角还是半角）**：目标文本里的标点**保持素材原文**（多为全角）。用户如果打半角，判错并归入「标点格式」。**这是刻意设计**：真实打字场景下中文就该用全角。UI 需在首次出现标点错误时给一次非阻塞提示（见 SPEED2-11 文案）。

### 3.3 错误处理：`markOnly`（SPEED2-06）

| 方式 | 行为 | 采用 |
|---|---|---|
| `rollbackAll`（对码轨行为） | 打错 → 整题清空重打 | ❌ 句/文章级会把节奏毁掉 |
| **`markOnly`** | **打错 → 该字标红，游标继续前进** | ✅ 句 / 段落 / 文章 |
| `rollbackChar` | 打错可退格 | ❌ 本批次不开放退格（与对码轨一致） |

**SPEED2-06-1**：`markOnly` 下**不拦截后续输入**，也不做 300ms 清空。错误只影响最终准确率统计。

### 3.4 计时与指标（SPEED2-07 / SPEED2-08）

| 指标 | 口径 | 显示位置 |
|---|---|---|
| **时间** | 从**第一次合法输入（首个 keydown，不是首次上屏）**开始计时；暂停不计 | 指标条第 1 项（复用 `TypingSpeed`） |
| **字/分 CPM** | `正确字数 / 用时(分钟)`，其中「正确字数」= 已提交且判定正确的**汉字数**（英文按单词数） | 第 2 项，主指标 |
| **输入字数** | 已提交的字符总数（含错误） | 第 3 项 |
| **正确率** | `正确字数 / 已提交字数` | 第 4 项 |
| **回改次数** | 本批次**不统计**（不开放退格与回改） | — |

> 🔴 **SPEED2-07-1（不显示 WPM）**：中文场景基线明确「不显示 WPM」。英文场景显示 `WPM`（现有 `TypingSpeed` 已按 `isChinese` 分叉，沿用）。

**SPEED2-08（计时起点，硬约束）**：**按下第一个键的瞬间**开始计时，**不是**第一个字上屏时。理由（基线 §1.2）：上屏前用户可能在打很长的拼音，那段时间同样是「打字时间」，漏掉会高估速度。

**实现要点**：上屏轨需要一个 `keydown` 监听（仅用于「首键启动计时」与「记录击键数」，不参与判定）。

### 3.5 UI 差异（相对对码轨）

| 元素 | 对码轨 | 上屏轨 |
|---|---|---|
| 键盘 `TypingKeyboard` | ✅ 显示（标注韵母） | ❌ **隐藏**（用户用真实输入法，键位提示无意义，且会泄漏答案） |
| 题面 | 「拼音行 + 汉字行」交替 | **只显示目标文本**（汉字/英文），逐字高亮绿/红；**不显示拼音行**（显示拼音 = 告诉用户怎么读，反而是干扰） |
| 汉字提示开关 `Tab` | 有用（编码 vs 汉字） | ❌ 无意义（**禁用**；`Tab` 恢复浏览器默认焦点行为） |
| 候选回显 | 无 | ✅ 在目标文本下方用浅灰显示当前输入的拼音串（`compositionupdate.data`），**仅回显，不校验** |
| IME 提示 | 「请切换到英文输入法」 | ❌ 不提示（上屏轨**就是要**用中文输入法） |
| 「按任意键开始」覆盖层 | 有 | 有（不变） |
| 输入法状态误判 | — | 若上屏内容是**纯拉丁字符**而目标是汉字 → 提示「**请切换到中文输入法**」，**不判错、不计时**（沿用基线 §3.4） |

**SPEED2-09（键盘隐藏后的布局）**：键盘隐藏后题面区会多出约 220px 高度，**必须**让题面自动占用（`flex-1` 居中），**不得**留下空洞或让指标条上浮。同时**允许**上屏轨显示更多行（`windowLines` 从 6 提升到 10）。

## 4. 英语 = 打字测速（SPEED2-10）

用户原话：「中文和英语下面的**拼音输入法 / 文章打字**文案删掉」「打字测速就是需要打出来的字上屏」。

**SPEED2-10（英语不分「输入方式」）**：

| 项 | 规格 |
|---|---|
| 英语 Tab 下的二级按钮行 | ❌ **整行不出现**（当前第一批只在 `tab==='zh'` 时渲染，符合） |
| 英语素材的判定轨 | **恒为 `ime`**（打字母、空格上屏；不做「编码校验」） |
| 英语的判定方式 | 逐字符比对 `e.data`（英文 IME 通常不触发 composition，走 `input` 兜底路径） |
| 英语的指标 | `WPM`（词/分）+ 正确率 |
| 英语的键盘 | ❌ 隐藏（与上屏轨一致） |

> ⚠️ **SPEED2-10-1（英文的 `keydown` 兜底）**：英文输入通常**不触发 composition**（除非开了自动更正）。因此英文必须同时监听：
> - `input` 事件（取 `e.data` 增量），用于普通字母输入
> - `compositionend`，用于某些输入法的联想/自动更正
>
> 两者需**去重**（用一个「已提交长度」游标，只处理新增部分），避免重复追加。

## 5. 文案（SPEED2-11）

| 位置 | 文案 |
|---|---|
| 二级按钮 | `打字测速` |
| 键盘隐藏处的替代提示（题面下方一行小字） | `用你自己的输入法打字，测的是真实上屏速度` （`text-xs text-gray-400`，**仅首次进入该素材时显示 3 秒**，之后淡出） |
| 首次标点格式错误 | 非阻塞提示：`中文标点请用全角（，。？），当前被判为标点格式错误` |
| 输入法处于英文态 | `检测到英文输入，请切换到中文输入法`（非阻塞，3 秒消失，不判错） |
| 结算页标题下副标题 | `打字测速 · 字/分 {CPM}` |

> **SPEED2-11-1（文案纪律）**：不得出现「你的速度超过了 xx% 用户」这类与他人比较的表述（基线 UI-HC-1/3）。

## 6. 数据与实现（SPEED2-12）

| 项 | 内容 |
|---|---|
| 新增字段 | `TypingMaterialResource.inputTrack?: TypingInputTrack`（可选，缺省 `'code'`）——**注意**：打字测速**不新建素材**，它复用同一批素材，只是判定轨不同 |
| 新增 atom | `typingInputTrackAtom`（持久化，`'code' \| 'ime'`，缺省 `'code'`） |
| 新增组件 | `src/pages/TypingLearner/components/UpstreamInputHandler/`（上屏轨输入捕获）<br>`src/pages/TypingLearner/components/UpstreamTarget/`（上屏轨题面：无拼音行、逐字绿红、候选回显） |
| 改动组件 | `TypingSchemeSwitcher`（加第三项）、`TypingPanel`（按 `inputTrack` 分支：渲染 `UpstreamTarget` + 隐藏键盘）、`TypingSpeed`（上屏轨口径） |
| 不新建素材 | ✅ 复用 `zh-*-zi/ci/chengyu/duanju/wenzhang` 全部素材；**同一素材既能用对码轨也能用上屏轨** |

**SPEED2-12-1（素材可见性）**：中文 Tab 下，**所有素材在三种输入方式下都可见**。理由：
- 字/词用上屏轨打，是「用真实输入法打单字」，有效（虽然意义不如句/文章大，但不该禁止）；
- 文章用对码轨打，是「逐字按编码打长文」，也很有效（练耐力）。
- **只做提示，不做限制**：当选「打字测速」且素材是「字/词/成语」时，卡片右上角加一条 `text-xs text-gray-400` 的「建议搭配短句/文章」。

**SPEED2-12-2（判定轨与素材解耦）**：`inputTrack` 属**全局选择**，不写在素材元数据里。这样「同一篇文章，昨天用双拼练编码，今天用搜狗练速度」都成立。

## 8. 验收标准

| # | Given / When / Then |
|---|---|
| **ACC2-02-01** | Given 中文 Tab，When 查看二级按钮行，Then 依次为「全拼 / 双拼 ▾ / 打字测速」，且仅一个为选中态 |
| **ACC2-02-02** | When 点击「打字测速」，Then 进入练习页，**键盘不显示**，题面只显示目标文本（无拼音行） |
| **ACC2-02-03** | Given 我用搜狗拼音输入法，When 打出「今晚一起吃饭」并上屏，Then 每个字逐个变绿，无需切换英文输入法 |
| **ACC2-02-04** | When 一次上屏「今晚」两个字，Then **两个字都被校验**（不是只校验末位）；若「今」打错，「今」标红而「晚」仍按实际判定 |
| **ACC2-02-05** | When 打错一个字，Then 该字标红，**输入不中断**，可继续往后打（markOnly） |
| **ACC2-02-06** | Given 文章有分段，When 打到段尾，Then **自动跳到下一段首字**，不要求按回车 |
| **ACC2-02-07** | When 打全角标点「，」，Then 判对；When 打半角「,」，Then 判错并提示一次「中文标点请用全角」 |
| **ACC2-02-08** | When 计时开始，Then 从**第一个按键**开始走秒（不是第一次上屏） |
| **ACC2-02-09** | When 完成一段，Then 显示 **字/分**（不是 WPM），数值 ≈ 正确字数 / 分钟 |
| **ACC2-02-10** | Given 我处于英文输入法态在打中文，When 上屏的是拉丁字母，Then 提示「请切换到中文输入法」，**不判错、不计入用时** |
| **ACC2-02-11** | When 切到英语 Tab，Then **没有**「打字测速」按钮（也不应有任何输入方式按钮） |
| **ACC2-02-12** | Given 英语段落，When 用键盘正常输入，Then 逐字符校验、空格必须打、`WPM` 正确 |
| **ACC2-02-13** | When 从「打字测速」切回「双拼」，Then 仍是小鹤（方案未被重置），键盘重新出现 |
| **ACC2-02-14** | Given 同一篇短文，When 分别用双拼（对码）和打字测速（上屏）打，Then 两种模式的记录**分开统计、不混算**，页面不出现「综合分」 |
| **ACC2-02-15** | When 刷新页面，Then 仍是我上次选的输入方式（`inputTrack` 持久化） |

## 9. 与既有 Spec 的关系

- **落地** 基线 `02` §3 的上屏实战轨（CN-A2 / A2a），但**收窄**为「打字测速」一个功能，不做考试模考、不做 IME 辅助统计、不做速度衰减率。
- **部分推翻** 第一批 `02` §5.2「打字模式 V1 只做对码轨」：本批次新增上屏轨，但**仅限「打字测速」这一选项**。
- **继承** 基线 `02` §4.2 的 `markOnly` 策略（句/文章级默认）。
- **继承** 第一批 `02` §5.1 的「方案必须是显式状态」纪律：`inputTrack` 同样必须显式存储，不得从输入内容反推。
- **不涉及** 对码轨（全拼/双拼）的任何判定逻辑。
