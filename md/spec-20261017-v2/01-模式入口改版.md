## 1. 背景与目标

### 1.1 现状问题

第一批实现的浮层是「箭头 → 白色卡片 → 两行（中文名 + 英文名）」。用户反馈两点：

1. **视觉割裂**：白色 `my-card` 卡片悬在标题下方，与页头右上操作区的按钮语言不一致；箭头本身只是 16×16 的小方块，hover 没有任何反馈，看不出可点。
2. **信息层级混乱**：浮层里同时出现「学习模式 / Qwerty Learner」「打字模式 / Typing Learner」两个名字，用户每次都要读两遍；而**用户真正想知道的是「切过去之后会变成什么样」**——即标题本身。

### 1.2 目标

| # | 目标 | 怎样算成功 |
|---|---|---|
| G1 | 入口看起来像右上角 `StartButton` 那样「一按就展开」 | hover 标题区 → 整块出现浅底 + 阴影，箭头翻转 |
| G2 | 用户**不用看浮层**就知道自己会切到哪个模式 | 标题文字在 hover 浮层项时**实时变成**对应模式的英文名 |
| G3 | 中文模式名**只在 hover 时出现**，不干扰平时的极简页头 | 未 hover 时页头只有 `Qwerty Learner` |
| G4 | 模式选择被记住 | 刷新/重开浏览器后仍在原模式 |
| G5 | 点击标题仍能跳官网 | 点击标题文字跳官网，点击箭头只开合浮层 |

### 1.3 非目标

- ❌ 不把模式切换做成「下拉 + 设置项」的双入口
- ❌ 不改页头右侧功能条
- ❌ 不新增图标库（沿用 `~icons/tabler/*`）

## 2. 结构改版（ENTRY2）

### 2.1 布局骨架

```
<header className="container z-20 mx-auto w-full px-10 py-6">
  <div className="flex ... lg:flex-row">
    ┌─ <div className="mode-block relative">  ← 新增：整块 hover 容器（含 logo + 标题 + 箭头）
    │    <NavLink to="官网">                      点击跳官网
    │      <img logo className="h-16 w-16"/>
    │      <span className="title-text">Qwerty Learner</span>   ← 文字随 hover 项切换
    │      <span className="mode-label">学习模式</span>          ← 仅 hover 时出现
    │    </NavLink>
    │    <button className="arrow">chevron-down</button>          ← 绝对定位在标题下方
    └─ </div>
    <nav>…右上功能条…</nav>
  </div>
</header>
```

**ENTRY2-01（整块 hover 容器）**：新增一个包裹 `logo + 标题 + 箭头` 的容器，作为 `useFloating` 的 **reference**。整个容器 hover 时统一加：
- 背景：`bg-indigo-50 dark:bg-gray-700`
- 圆角：`rounded-xl`（与右上功能条 `rounded-xl` 一致）
- 内边距：`px-3 py-2 -mx-3 -my-2`（用负 margin 抵消，**不改变页头总高度**）
- 过渡：`transition-colors duration-300 ease-in-out`（与 `DictChapterButton`、`StartButton` 同）
- hover 时**可选**加 `shadow-sm`（与 `StartButton` 的 `shadow-lg` 同族但更轻——标题区是页头，不宜太重）

> 🔴 **ENTRY2-02（不得改变页头尺寸）**：负 margin 方案保证「hover 前后 logo/标题的**像素位置**完全不动**，页头总高度差 0**。验收方法与第一批 ACC-01-09 相同（对比截图 + `boundingClientRect`）。

### 2.2 标题文字切换（ENTRY2-03）

| 状态 | 标题文字 |
|---|---|
| 未 hover（常态） | 当前模式的英文名：`Qwerty Learner`（学习模式）/ `Typing Learner`（打字模式） |
| hover 浮层「Qwerty Learner」项 | `Qwerty Learner` + 标签 `学习模式` |
| hover 浮层「Typing Learner」项 | `Typing Learner` + 标签 `打字模式` |
| 鼠标在浮层外、容器内（已展开但未指向某项） | 保持当前模式的文字 |

**实现要点**：

```tsx
const [hoveredMode, setHoveredMode] = useState<AppMode | null>(null)
const displayMode = hoveredMode ?? currentMode
const title = displayMode === 'typing' ? 'Typing Learner' : 'Qwerty Learner'
const label = isOpen ? (displayMode === 'typing' ? '打字模式' : '学习模式') : null
```

**ENTRY2-03-1（切换动效）**：文字切换**不加动画**（避免文字跳动的廉价感）；只让中文标签做 `opacity-0 → opacity-100`（`duration-200`）。理由：英文标题是身份标识，来回淡入淡出会显得闪烁。

### 2.3 中文模式标签（ENTRY2-04）

**位置**：**英文标题之后**，同一行，基线对齐。

```
Qwerty Learner  学习模式
                ↑ text-sm，text-gray-400，ml-2，自底部对齐
```

| 属性 | 值 |
|---|---|
| 字号 | `text-sm`（14px）；小屏 `text-xs` |
| 字重 | `font-normal` |
| 颜色 | `text-gray-400`；hover 容器时 `text-gray-500`（深色模式 `dark:text-gray-400`） |
| 间距 | `ml-2` |
| 出现条件 | **仅 `isOpen === true`**（浮层展开时）。鼠标只是路过标题但未展开（< 80ms）时**不出现** |
| 出现动效 | `opacity-0 → opacity-100`，`duration-200`；**不改变布局宽度**（用 `absolute` 定位到标题右侧，或用固定宽度的占位），避免标题因标签出现而左移 |
| 文案 | `学习模式` / `打字模式`（**不带括注、不带英文**） |

> 🔴 **ENTRY2-04-1（不得抖动）**：标签出现/消失不得引起标题横向位移。实现建议：标签绝对定位在标题右缘外侧（`left-full ml-2`），容器 `relative`；或给容器一个足够宽的 `min-w` 但**不加** `justify-between`（否则 logo 与标题会拉开）。

### 2.4 浮层重做（ENTRY2-05）

**改前**（第一批 ENTRY-04）：`my-card rounded-xl bg-white p-1`，每行「模式名 + 英文名」，宽 224px。

**改后**：

```
┌──────────────────────────┐
│  Qwerty Learner          │  ← 只放英文名（图标区 + 文字）
│  Typing Learner        ● │  ← 当前模式右侧实心点
└──────────────────────────┘
```

| 属性 | 值 | 依据 |
|---|---|---|
| 容器 | `my-card rounded-xl bg-white p-1 dark:bg-gray-800`（**保留**，与右上卡片同族） | 与页头视觉一致 |
| 宽度 | `w-52`（208px，比原 224 略窄，因为去掉了中文名） | — |
| 条目 | `rounded-lg px-3 py-2 text-lg`，英文名作主文案 | — |
| 当前项 | 左侧 `h-1.5 w-1.5 rounded-full bg-indigo-500`（**小圆点**，不再是「实心/空心」双态） | 更克制 |
| hover 项 | `bg-indigo-400 text-white`（**与 `DictChapterButton` 的按钮 hover 完全一致**） | 全站统一 |
| 位置 | `placement: 'bottom-start'`，`offset(8)`（比原 5 略大，让浮层离 hover 区更远一点，减少「拖影」感） | — |
| 出现动效 | `opacity` + `translate-y-[-4px] → 0`，`duration-150` | 比原 100ms 更从容 |

**ENTRY2-05-1（为什么浮层不再放中文名）**：
- 中文名已经由「标题右侧的标签」承担（用户 hover 到某项时标题旁直接出现「学习模式」）；
- 浮层里再放一次就是**同一信息出现两次**，反而拥挤；
- 保留英文名是因为**浮层项必须能被「读出来」**（a11y 需要可读文案），且英文名与标题文字一致，形成「标题 ↔ 浮层项」的视觉对应。

### 2.5 箭头（ENTRY2-06）

| 属性 | 改前 | 改后 |
|---|---|---|
| 尺寸 | `h-4 w-4` 按钮 | `h-5 w-5`（热区放大到 `h-8 w-8`，`p-1.5`） |
| 颜色 | `text-indigo-500` | `text-indigo-500`，hover 容器时 `text-indigo-600` |
| hover 反馈 | `hover:bg-indigo-100`（只对箭头自身） | **跟随整块容器**（不再单独有背景） |
| 展开态 | `rotate-180` | `rotate-180` + `text-indigo-600` |
| 位置 | `absolute left-1/2 top-full`（标题正下方居中） | 保持 |

> **ENTRY2-06-1（点击冲突，继承 ENTRY-06）**：箭头必须是**独立 `<button>`**（不是 `NavLink` 的子节点事件），点击时 `preventDefault + stopPropagation`，只开合浮层。标题文字与 logo 仍包在 `NavLink` 内，点击跳官网。

## 3. 交互参数（继承 + 微调）

| 参数 | 第一批 | 本批次 | 理由 |
|---|---|---|---|
| `delay.open` | 80ms | **60ms** | 整块标题区已够大，误触概率低；缩短让「移到就开」更跟手 |
| `delay.close` | 200ms | **150ms** | 浮层离得更远（offset 8），需要更快收起避免挡视线 |
| `offset` | 5 | **8** | 见 ENTRY2-05 |
| `placement` | `bottom-start` | `bottom-start`（`flip` + `shift` 保留） | — |
| 触发区 | 仅箭头 | **整个标题容器**（logo + 标题 + 箭头） | 用户需求「整块标题区」 |

**ENTRY2-07（触发区边界）**：hover 判定绑定在**新增的整块容器**上，而非 `<header>`。因此：
- 鼠标移到右上功能条时，浮层**收起**（不因为还在 header 内就保持展开）；
- 鼠标在 logo / 标题 / 箭头 / 浮层之间移动，**不收起**。

**ENTRY2-08（键盘可达，继承 ENTRY-07 并简化）**：
- `Tab` → 焦点进入箭头按钮（`aria-haspopup="menu"` / `aria-expanded`）
- `Enter` / `Space` → 开合浮层
- `↓` / `↑` → 在两项间移动并 `focus`
- `Enter`（在项上）→ 切换
- `Esc` → 关闭，焦点回箭头
- ⚠️ 键盘路径**不需要**「标题文字跟着变」——因为焦点移动时可直接用项的 `aria-label` 播报。但为一致起见，**焦点所在项也更新标题预览**（复用 `hoveredMode`，在 `onFocus` 里同时置位）。

## 4. 模式记忆（ENTRY2-09）

**需求**：「模式选择要存浏览器缓存，切换过重新打开不用重新切」。

第一批已经实现（`appModeAtom` 写 `localStorage['appMode']`），但**存在一个实际问题需要本批次修掉**：

| 现状 | 问题 | 本批次处理 |
|---|---|---|
| 用户切到 `/typing` 后，刷新 `https://site/`（不带路径） | 落到 `/`（学习模式），而不是上次的 `/typing` | ✅ **新增**：应用启动时（`src/index.tsx` 或 `App` 顶层）读取 `appMode === 'typing'` 且当前路径为 `/` → **自动 `replace` 到 `/typing`** |
| 用户手动输入 `/` 想回学习模式 | 会被上面的逻辑弹回 `/typing` | ⚠️ **不能无脑重定向**。规则见下 |

**ENTRY2-09-1（重定向规则，必须精确）**：

```
仅在「应用首次挂载」（非路由跳转）时执行一次：
  if (pathname === '/' && appMode === 'typing') navigate('/typing', { replace: true })
```

- 判定「首次挂载」：用一个模块级 `let hasRestoredMode = false`，只在第一次执行，之后路由变化不再干预。
- 用户在 `/typing` 点「学习模式」→ 显式写入 `appMode='learn'` → 之后手动访问 `/` 不再被弹走。
- **不得**在 `/typing/gallery` 等子路由上做重定向（它本身就是打字模式的一部分）。

**ENTRY2-09-2（当前模式高亮的判断来源）**：仍以**路由**为准（第一批 MODE-04），`appModeAtom` 只服务「首次落地重定向」这一处。

## 7. 验收标准

| # | Given / When / Then |
|---|---|
| **ACC2-01-01** | Given 在 `/`，When 鼠标移入标题区（logo 或标题文字），Then 整块出现 `bg-indigo-50` 浅底 + 圆角，且浮层展开 |
| **ACC2-01-02** | When 鼠标移到右上功能条，Then 浮层收起、浅底消失 |
| **ACC2-01-03** | When 浮层展开，Then 标题右侧出现「学习模式」（当前模式），`text-sm text-gray-400` |
| **ACC2-01-04** | When hover 浮层里的「Typing Learner」，Then 标题立即变为 `Typing Learner`，右侧标签变为「打字模式」 |
| **ACC2-01-05** | When 鼠标离开浮层但仍在标题区，Then 标题恢复为当前模式的文字 |
| **ACC2-01-06** | When 未展开浮层，Then 页头**只有** `Qwerty Learner`（无中文标签） |
| **ACC2-01-07** | When hover 前后对比，Then logo 与标题的 `boundingClientRect` 完全不变（±0px），页头总高差 0 |
| **ACC2-01-08** | When 点击标题文字，Then 跳官网；When 点击箭头，Then **不跳转**，只开合浮层 |
| **ACC2-01-09** | Given 我在 `/typing` 并刷新，Then 仍在 `/typing`（`appMode` 记忆生效） |
| **ACC2-01-10** | Given `appMode === 'typing'`，When 打开浏览器访问站点根路径 `/`，Then 自动跳到 `/typing` |
| **ACC2-01-11** | Given 我在 `/typing` 点了「学习模式」（此时 `appMode='learn'`），When 再手动访问 `/`，Then 停在 `/`（不被弹回） |
| **ACC2-01-12** | When 用 `Tab` 聚焦箭头 + `Enter`，Then 浮层打开；`↓` + `Enter` 可切到「Typing Learner」；`Esc` 收起并回到箭头 |
| **ACC2-01-13** | When 切深色模式，Then 浅底、标题、标签、浮层均清晰可读，无深底深字 |
| **ACC2-01-14** | When 打字模式练习中点击「学习模式」，Then 出现非阻塞确认条（不因入口改版而丢失） |
