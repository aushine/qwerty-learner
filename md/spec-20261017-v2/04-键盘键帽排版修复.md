# 04 · 键盘键帽排版修复

**日期**：2026-10-17（第二批）
**批次**：`spec-20261017-v2`
**对应需求**：用户需求 ④（K/L/S 韵母溢出、字母可以小一点、SHIFT/CTRL/BACKSPACE 字号过大、Win 键换成微软图标）
**上游**：第一批 `02` `04`（`TypingKeyboard` 三区布局 KB-01）、`基线 A1` §2.2（键位事实）

> 🔴 本批次**只改排版**，**不改**任何键位事实（韵母归属）与高亮规则。`FLYPY_KEY_LABELS` 一行不动。

---

## 1. 背景与目标

### 1.1 现象（用户反馈 + 代码核对）

| # | 现象 | 根因（代码） |
|---|---|---|
| 1 | `K` `L` `S` 键里的韵母**溢出键帽** | `faceFinal()` 把双韵母用 `/` 拼成一个**不换行的字符串**：`ing/uai`（7 字符）、`iang/uang`（9 字符）、`ong/iong`（8 字符）。字号固定 `text-[11px]` 且 `leading-none`，在 `40px` 键宽内 9 字符等宽字 ≈ 59px → **必然溢出** |
| 2 | 字母偏大（用户希望小一点） | 主字母固定 `text-lg`（18px），在 `36~40px` 键内占比过大，加上韵母行显得拥挤 |
| 3 | `Backspace` / `Shift` / `Ctrl` 字号过大、文字超出键面 | 功能键复用同一 `text-lg`，但 `Backspace`（9 字符）放在 2u（80px）键里，`text-lg` 等宽 ≈ 9×10.8 = 97px → **溢出** |
| 4 | Win 键显示为 `⊞`（像「田」） | `ROWS` 里硬编码 `fn('MetaLeft', '⊞', 1.5)`，是字符而非图标 |

### 1.2 目标

| # | 目标 |
|---|---|
| G1 | **27 个被标注的键，韵母在任何密度档下都不溢出**（含 `iang/uang`） |
| G2 | 主字母略缩小，视觉重心回到「韵母」（打字模式要看的是韵母） |
| G3 | 功能键（`Backspace/Shift/Ctrl/Alt/Tab/Caps/Enter`）字号封顶，长标签缩字 |
| G4 | Win 键显示**微软四色方块图标**（不引入图标库，用 CSS 内联四格） |
| G5 | **不改变键帽尺寸与整块键盘占地**（否则整页布局会连锁偏移） |

## 2. 主字母与韵母的自适应（KB2-01 ~ KB2-05）

### 2.1 主字母缩小（KB2-01）

| 属性 | 改前 | 改后 |
|---|---|---|
| 主字母字号 | `text-lg`（18px，固定） | **`text-[15px]`**（`md` 以上 `text-[16px]`） |
| 字重 | `font-medium` | 保持 `font-medium` |
| 行高 | `leading-none` | `leading-none`（与韵母紧贴） |

> **为什么只缩 2~3px**：缩太多会让键帽「空」，反而降低可读性。目标只是给韵母腾出 2px 垂直空间。

### 2.2 韵母的自适应缩字（KB2-02，**本条是修复溢出的核心**）

**规则：按韵母字符数分级设定字号**（等宽字体下，字符数 × 0.6 × 字号 ≈ 实际宽度）：

| 韵母字符数 | 示例 | 字号 | 估算宽度（0.6 系数） |
|---|---|---|---|
| 1 | `a` `e` `u` `i` `o` | **11px** | 6.6px |
| 2 | `iu` `ei` `uo` `un` | **11px** | 13.2px |
| 3 | `uan` `ing` `uai` `ong` `iao` | **10px** | 18px |
| **5** | `ing/uai`（K） | **8px** | 24px |
| **6** | `ong/iong`（S） | **8px** | 28.8px |
| **8** | `iang/uang`（L） | **7px** | 33.6px |

- 键内可用宽度 ≈ `keyU - 8px`（左右各 4px 内边距）。`keyU=40` → 32px 可用。
  - `iang/uang` 在 7px 下 = 33.6px，**仍略超** → 触发 KB2-03 的换行。

### 2.3 双韵母分两行（KB2-03，**L 键的解决方案**）

字符数 **> 6** 时（即 `iang/uang`、`ong/iong` 在更小密度档下），把 `/` 拆成两行：

```
┌──────────┐        ┌──────────┐
│    K     │        │    L     │
│  ing/uai │   →    │  iang    │
└──────────┘        │  uang    │
                    └──────────┘
```

| 参数 | 规格 |
|---|---|
| 拆行阈值 | 韵母字符串长度 ≥ 7（`iang/uang` = 9，`ong/iong` = 8 在 mini 密度也拆） |
| 行高 | `leading-[1.05]` |
| 主字母与第一行的间距 | `-mt-0.5`（保持紧凑） |
| 两行总高 | 2 × 7px × 1.05 ≈ 15px，仍小于 `keyU` 的一半 |

> 🔴 **KB2-03-1（必须两行显示，不能截断）**：用户学双拼必须知道 `L` 同时承载 `iang` 和 `uang`。**禁止**用 `…` 截断、**禁止**只显示第一个。

### 2.4 单韵母键的三区对齐（KB2-04）

`V` / `I` / `U` 三键同时有声母角标与韵母，垂直空间最紧：

```
┌──────────┐
│ zh       │  ← 10px，absolute 左上
│    V     │  ← 15px
│    ui    │  ← 11px
└──────────┘
```

- 声母角标 `text-[10px]` **保持**（不参与缩字，因为只有 1~2 字符）；
- 主字母 + 韵母用 `flex-col items-center justify-center`，整体 `pb-1`（给底部状态条留位）；
- 若 `density === 'mini'`（`keyU <= 34`），声母角标降为 `text-[9px]`、主字母降为 `text-[14px]`。

### 2.5 密度档与字号联动（KB2-05）

`keyU` 由现有 `density` 决定（`normal 40 / compact 36 / mini 32` 量级），字号按比例微调：

```ts
const scale = keyU / 40                    // 1 / 0.9 / 0.8
const letterSize = Math.max(12, Math.round(15 * Math.min(1, scale + 0.15)))
const finalSize = (len: number) => {
  if (len >= 7) return Math.round(9 * scale)   // 两行模式，字号略大
  if (len >= 5) return Math.round(8.5 * scale)
  if (len >= 3) return Math.round(10 * scale)
  return Math.round(11 * scale)
}
```

> **KB2-05-1**：所有字号必须 `Math.max(9, …)` 兜底，**不得小于 9px**（再小就无法辨认，宁可压缩键高）。

## 3. 功能键字号（KB2-06 ~ KB2-07）

### 3.1 规则

| 标签 | 键宽 | 原字号 | 新字号 | 处理 |
|---|---|---|---|---|
| `Tab` `Caps` | 1.5u / 1.75u | `text-lg` | **12px** | 常规 |
| `Shift` | 2.5u | `text-lg` | **12px** | 常规 |
| `Ctrl` `Alt` | 1.5u | `text-lg` | **11px** | 常规 |
| **`Backspace`** | 2u | `text-lg`（溢出） | **10px + `tracking-normal`** | 长标签 |
| `Enter` | 2.25u | `text-lg` | **11px** | 常规 |

**KB2-06（统一实现）**：功能键标签统一改为 `text-[11px]`，并加 `px-1`；对 `Backspace` 单独 `text-[10px]`。

**KB2-07（文字不得换行）**：功能键标签一律 `whitespace-nowrap` + `overflow-hidden`，并且**通过缩字而不是截断**保证完整可读。验收方法：用 `scrollWidth > clientWidth` 检测溢出（见 §5）。

## 4. Win 键图标（KB2-08）

### 4.1 改前

```tsx
fn('MetaLeft', '⊞', 1.5)   // U+229E 的方形加号，视觉上像个「田」字
```

### 4.2 改后

用**内联 CSS 四格**画微软徽标（**不引入图标库、不使用官方 SVG 资源以规避商标素材问题**，仅用四个色块表达）：

```tsx
const WindowsKeyIcon = ({ size = 12 }: { size?: number }) => (
  <span
    aria-hidden="true"
    className="grid grid-cols-2 gap-[1px]"
    style={{ width: size, height: size }}
  >
    <span style={{ background: '#F25022' }} />
    <span style={{ background: '#7FBA00' }} />
    <span style={{ background: '#00A4EF' }} />
    <span style={{ background: '#FFB900' }} />
  </span>
)
```

| 属性 | 规格 |
|---|---|
| 尺寸 | `12×12`（`keyU>=40`）/ `10×10`（更小档），等比 |
| 间隙 | `1px` |
| 颜色 | 微软四色：`#F25022` / `#7FBA00` / `#00A4EF` / `#FFB900` |
| `aria-label` | `Windows`（父键 `role`/`aria-hidden` 保持现有规则——功能键本身 `aria-hidden`，故图标也 `aria-hidden`） |
| 深色模式 | 不改颜色（徽标是品牌色），背景保持键面的 `gray-700` 即可 |

> **KB2-08-1（合规）**：本项目为独立第三方工具，使用「四色方块」表达 Windows 键位属于**通用指代**，不复制微软官方 LOGO 的透视/图形细节（官方 LOGO 是四格带透视的窗口形状）。**若维护者认为仍有风险**，降级为纯文字 `Win`（`text-[10px]`）。**本批次采用四色方块 + 注释留痕。**

### 4.3 macOS 场景

`MetaLeft/Right` 在 macOS 上是 `⌘`（Command）。因此：

```tsx
const metaLabel = IS_MAC_OS ? '⌘' : <WindowsKeyIcon />
```

`⌘` 用 `text-[13px]`（单字符无需缩字）。**`IS_MAC_OS` 已存在于 `src/utils/index.ts`，直接用。**

## 5. 溢出检测（KB2-09，验收方法）

**不能用肉眼判断**，必须用可复现的检测：

```js
// 在浏览器控制台执行（或用现有 probe-typing-keyboard.cjs 扩展）
[...document.querySelectorAll('[data-keycap]')].forEach((el) => {
  const overflowX = el.scrollWidth - el.clientWidth
  const overflowY = el.scrollHeight - el.clientHeight
  if (overflowX > 0 || overflowY > 0) {
    console.warn('溢出', el.dataset.keycap, { overflowX, overflowY })
  }
})
```

**KB2-09-1**：给每个键帽加 `data-keycap={def.code}`（便于检测与 E2E）。

**验收阈值**：

| 场景 | 允许溢出 |
|---|---|
| 全部 27 个标注键 × 3 个密度档 | **0px** |
| 全部功能键 × 3 个密度档 | **0px** |
| `1280 / 1024 / 900 / 768` 四档宽度 | **0px** |
