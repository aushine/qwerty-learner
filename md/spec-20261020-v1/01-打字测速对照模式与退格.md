# 01 · 打字测速对照模式与退格

**日期**：2026-10-20
**负责成员**：析客
**文档性质**：需求定义，不含代码实现。
**对应需求**：批次需求 1（`00-README.md` §二 #1）。

---

## 一、背景与目标

打字测速（上屏轨，`spec-20261017-v2/02`）当前形态为「目标文本逐字内联上色」：用户上屏的字直接在原文行上把对应字符染绿/染红，游标只进不退、**不支持退格**。需求提出方反馈两个问题：

1. 打错（或上屏多字时中间夹了错字）无法退格修正，只能错到底；
2. 内联上色的题面在长文下「原文」与「我打的」混在一起，缺少「对照」的清晰感。

**本批次改为「对照模式」**：题面呈现为**一行原文 + 一行横线**，用户在横线上逐字上屏，已上屏的字按位显示在横线上并**变绿（保留现有绿色正确反馈）**，错字红；支持**退格**删除最近上屏的字符并回退该位状态。

**成功标准**：对照题面单屏不滚动；退格从文末一路可退到题首；已上屏多字可逐字退；绿色/红色判定、跳过换行、标点提示、候选回显、首键计时、完成判定等既有行为全部保留。

## 二、功能需求

### REQ-101 双行对照题面

- 题面每个可视行渲染为**上下两行**：
  - **原文行**：目标文本原字符，正常色（`text-gray-600 dark:text-gray-50`，沿用 `UpstreamTarget` 现色板，LAY-04 纪律：不另造颜色）；
  - **对照行**：与原文行**逐列同宽对齐**的输入行。每个字符位渲染：
    - 未输入位：一条**横线**（下划线，浅灰，`border-b` 或等价实现）；
    - 已输入且正确位：该字符**绿色**（`text-green-600 dark:text-green-400`，与现行 `correct` 色一致）+ 横线消失或弱化；
    - 已输入且错误位：该字符**红色**（`text-red-600 dark:text-red-400`）+ 横线消失或弱化；
    - 游标位（下一个待判定位）：原文行该位加浅色游标底（沿用现行 `bg-indigo-50 dark:bg-indigo-900/40`），对照行该位横线高亮（如 indigo 色）以示落点。
- 对照行字符与原文行字符使用同一字体、同一字距度量，保证逐列对位（中文按 1em 槽位；英文按等宽或按槽位表对齐，见 REQ-105）。
- **可视窗口**：双行结构使单屏可容纳行数减半，窗口行数由现行 10 行调整为约 5 组（上下两行算一组），保持「单屏不滚动 + 当前组高亮、其余组淡化」的既有窗口策略（LAY-06）；当前组判定基准由「游标所在行」改为「游标所在组」。

### REQ-102 退格支持

- 退格对象 = **最近一个已上屏（已提交）字符**：
  - 该位状态由 `correct / wrong` 回退为 `normal`（横线重新出现）；
  - 游标左移一位；
  - 统计计数（正确数 / 已提交数）同步回退一个单位（`onProgress` 重新上报）。
- 可一路退到题首（游标 0 位）；题首位再退为无操作。
- 一次上屏多字时，退格**每次只退 1 个字符**（与「逐字提交」的粒度一致）。
- **组合期（拼音未上屏）退格由输入法自行处理**，不触发对照行回退——退格只作用于已提交字符。
- 退格后在同一位置重新上屏，按正常判定流程处理（可再判对/判错）。
- 退格不改变「首键计时」已开始的事实（SPEED2-08 保持）。

### REQ-103 保留行为清单（逐条不得回归）

以下既有行为全部保留，仅承载形态从「内联题面」变为「对照题面」：

| 行为 | 出处 | 保留要求 |
| --- | --- | --- |
| 打出字变绿（正确）/ 变红（错误） | 需求原文「打出来的字变绿这个保留」 | 保留，落点改到对照行 |
| 一次上屏多字**逐字全部校验** | v2-02 SPEED2-05 | 保留 |
| 换行与中文排版空格**自动跳过**，不要求用户输入 | v2-02 SPEED2-05-2 | 保留（跳过位在对照行渲染为「已跳过」弱化态，沿用现行 `skipped` 色板） |
| 全角正确、半角判错并归「标点格式」，首次出现提示一次 | v2-02 SPEED2-05-1 / SPEED2-11 | 保留 |
| 输入法候选回显（compositionupdate 仅回显不校验） | v2-02 SPEED2-04 / SPEED2-09 | 保留，回显位置改到对照行下方 |
| 英文态误输入提示（检测到纯拉丁字符提示切换中文输入法） | v2-02 SPEED2-04 | 保留 |
| 首键计时（从第一个按键开始，不是首次上屏） | v2-02 SPEED2-08 | 保留 |
| 完成判定（游标到达文本末尾 → onFinished） | v2-02 SPEED2-05 | 保留；退格后离开末尾再重新到达末尾时**不得重复触发**完成（需去重：仅首次到达时触发） |
| 字/分指标口径（正确字数 / 用时） | v2-02 SPEED2-07 | 保留，随退格同步回退计数 |
| 「按任意键开始 / 继续」遮罩、失焦暂停 | 页面层既有 | 保留 |

### REQ-104 与一命模式的交互

- 一命模式（见 `02-一命模式.md`）开启时，**判定发生在「上屏提交」时刻**：提交中出现错字即触发整章重开；
- **退格不能撤销一命判定**（提交即既成事实），重开后从题首重新开始；
- 一命关闭时，退格为纯修正操作，无任何副作用。

### REQ-105 英文素材适配

- 英文素材（`effectiveTrack === 'ime'` 且语言为英语）同样使用对照题面；
- 槽位粒度 = **字符**（含空格）：空格位在对照行渲染横线（可降低不透明度以避免视觉噪音），保证与原文行词位对齐；
- 断行策略沿用现行「尽量在空格处断行，避免切开单词」；一组双行的两行使用相同断行点。

## 三、交互 / UI 说明

题面结构示意（以「今天天气不错」为例，「天气」已上屏、「不错」未打）：

```
今天天气不错            ← 原文行（正常色；游标在「不」位，该位浅色游标底）
___天气______            ← 对照行（已上屏字变绿；未打位为横线；空格位弱化横线）
```

状态与边界：

| 状态 | 表现 |
| --- | --- |
| 未开始（isTyping = false） | 「按任意键开始 / 继续」遮罩覆盖题面（现行行为） |
| 组合期 | 对照行下方回显输入法候选内容（现行 `composing` 回显位） |
| 暂停（失焦 / 模式切换确认条） | 题面冻结，遮罩提示 |
| 完成 | 现行结算流程（TypingResultScreen） |
| 一命重开（`02`） | 对照行整体重置为全横线、原文行重置游标到题首 |

## 四、数据与接口

- `UpstreamCharState` 类型不变（`normal / correct / wrong / skipped`），新增语义：退格把 `correct/wrong` 复位为 `normal`。
- `UpstreamPanel` 内部状态：`states[]`（长度 = 文本长）、`cursor`（语义 = 已提交长度，退格时递减）、`composing`、`hasStartedKey` 不变；新增 `finishedRef`（完成判定去重，见 REQ-103）。
- `UpstreamInputHandler`：退格走隐藏 textarea 的原生 `keydown`（Backspace）——**注意**该组件当前 `onChange` 为 no-op 且提交后即清空 textarea，退格事件天然可被捕获；实现时只需把 Backspace 的默认行为（在空 textarea 上无副作用）转为「通知面板回退一位」的回调，**不得**让退格触发浏览器后退或其他副作用（`e.preventDefault()`）。
- `onProgress(correct, submitted)` 语义不变，退格后以最新计数重新上报。
- 页面层（`TypingLearner/index.tsx`）无需改动接口。

## 五、验收标准

1. 中文素材进入打字测速：题面为「原文行 + 横线对照行」双行结构，逐列对齐；未打位为横线，打对变绿，打错变红。
2. 退格：连续退格可把「已上屏 N 字」逐字退回到 0；每退一位，该位横线重现、绿/红消失、游标左移、指标计数同步减一。
3. 一次上屏「abc」三字后按一次退格，只退「c」。
4. 拼音组合期按退格：只影响输入法候选，对照行不变。
5. 退格到题首后继续按退格：无操作、无报错。
6. 完成全文后：结算正常；中途退格后再打完：不重复弹结算。
7. 英文素材：对照行按字符槽位对齐，空格位有横线（弱化），断行不切开单词。
8. 回归：跳过换行、全角/半角标点提示、英文态提示、候选回显、首键计时、按任意键开始 —— 全部与改版前一致。
9. 一命模式开启时上屏错字 → 立即整章重开；重开后按退格无异常。
