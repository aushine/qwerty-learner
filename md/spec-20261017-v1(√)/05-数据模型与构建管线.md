## 1. 背景与目标

### 1.1 背景

现有词典的**数据形状**是「学习模式专用」的：

```jsonc
// public/dicts/CET4_T.json（现有）
{ "name": "abandon", "trans": ["v. 放弃"], "usphone": "ə'bændən", "ukphone": "ə'bændən" }
```

打字模式需要的是：「**一个目标编码 + 对应的一段汉字**」。基线已裁定（D3）**编码在构建期预计算并烘进 `name`**，运行时零拼音库。本批次**完全沿用**这个决策，只是额外补三个元数据字段。

### 1.2 目标

| # | 目标 |
|---|---|
| G1 | 不改动 380 个既有词典的任何字段（零迁移、零回归） |
| G2 | 打字模式词典与学习模式词典**在同一份注册表里**，但用 `appMode` 字段区分，互不干扰 |
| G3 | 第一版**不引入任何运行时拼音依赖**（`pinyin-pro` 等只在 devDependency / 一次性脚本里） |
| G4 | 数据量在第一版可控（16 个素材、约 6000 条），构建时间 < 30s |
| G5 | 所有素材可**逐条溯源**（`source` 字段），满足 `基线 A2` 的合规举证 |

## 2. 数据模型（DATA-01 ~ DATA-08）

### 2.1 类型定义（`src/typings/typing.ts` 新增）

```ts
export type AppMode = 'learn' | 'typing'          // 已在 01 定义，此处集中声明
export type TypingLanguageTab = 'zh' | 'en'
export type TypingSchemeId = 'quanpin' | 'flypy'   // 第一版仅这两种可用
export type TypingSchemeIdAll = 'quanpin' | 'flypy' | 'mspy' | 'zrm' | 'sogou' // 保留未来
export type TypingMaterialType = 'zi' | 'ci' | 'chengyu' | 'duanju' | 'wenzhang' | 'paragraph' | 'article'

export type TypingMaterialResource = {
  /** 唯一 id，命名规范见 DATA-03 */
  id: string
  /** 卡片标题，如「常用 500 字」 */
  name: string
  /** 一行描述，我方自撰 */
  description: string
  /** 语言 Tab */
  languageTab: TypingLanguageTab
  /** 编码方案；英语素材为 'en' */
  schemeId: TypingSchemeId | 'en'
  /** 素材类型（决定落在哪个胶囊下） */
  materialType: TypingMaterialType
  /** 分组标题（「中文·输入法练习」/「文章练习」），沿用基线 04 §12.2 */
  category: string
  /** 胶囊标签（用于分组内的 tag 切换） */
  tags: string[]
  /** 词典 JSON 路径 */
  url: string
  /** 条目数（字/词/句/篇） */
  length: number
  /** 每章条目数（中文默认 10，成语 8，句 8；文章为 1） */
  chapterSize: number
  /** 章节数（由 length/chapterSize 计算，写入时固化以便 UI 直接读） */
  chapterCount: number
  /** 语料来源（合规举证） */
  source: string
  /** 许可标识 */
  license: string
  /** 若该素材只在其他方案下有文件，指向可用方案（用于 03 GAL-12 的回落） */
  fallbackSchemeId?: TypingSchemeId
}
```

**DATA-01（不复用 `Dictionary` 类型）**：`TypingMaterialResource` **必须是独立类型**，不得往现有 `Dictionary` / `DictionaryResource` 上加可选字段。理由：`Dictionary` 被 `Gallery-N`、`store`、`WordPanel`、`Analysis` 等 20+ 处消费，加字段的回归面远大于新建类型的成本。

### 2.2 词典 JSON 形状（沿用现有 `Word` 结构）

```jsonc
// public/dicts/zh/flypy-zi-500.json
[
  { "name": "vs",   "trans": ["中"], "usphone": "", "ukphone": "", "notation": "中" },
  { "name": "ni",   "trans": ["你"], "usphone": "", "ukphone": "", "notation": "你" },
  { "name": "ms",   "trans": ["米"], "usphone": "", "ukphone": "", "notation": "米" },
  { "name": "ai",   "trans": ["爱"], "usphone": "", "ukphone": "", "notation": "爱",
    "acceptedCodes": ["ai", "ad"] }
]
```

| 字段 | 语义（打字模式） | 说明 |
|---|---|---|
| `name` | **目标编码串**（全拼为字母串，双拼为每字 2 键拼接） | 🔴 判定与高亮的唯一依据 |
| `notation` | **汉字原文** | 复用现成字段（`Notation.tsx` 已存在），用于「汉字提示行」 |
| `trans` | **同 `notation` 的字符串数组**（单元素） | 为了让 `WordList` / `ResultScreen` / `Analysis` 等现有组件**不报错**（它们会读 `trans`），同时**UI 上不显示**（见 `02` KEEP-13） |
| `usphone` / `ukphone` | **空字符串** | 现有类型必填；填空避免类型报错，且不触发任何音标渲染分支（`Phonetic` 在打字模式不渲染） |
| `acceptedCodes?` | 兼容编码集合（`acceptedCodes[0]` 为主口径） | 沿用 `基线 04` §3.2 语义；**只在零声母双字母音节（ai/ei/ao/ou/an/en）与少数多音字上出现** |

> 🔴 **DATA-02（`trans` 的陷阱）**：`trans` 填汉字是为了「让老组件不崩」，**不是让 UI 显示**。
> - `WordList`（本章词表）：打字模式**若要保留**，必须由 `TypingLearner` 侧传入新的渲染逻辑，显示「汉字 + 编码」两列，**不得**显示 `trans[0]`（否则会显示成一列只有汉字，看着像 bug）。
> - `ResultScreen` / `Analysis`：会读 `trans` 做展示，需在打字模式侧确认不显示（若无条件显示，则在 CSS 上隐藏该列，**不改组件逻辑**）。

### 2.3 `id` 命名规范（DATA-03）

```
zh-<scheme>-<type>[-<variant>]        中文
en-<type>[-<variant>]                 英语

scheme : quanpin | flypy
type   : zi | ci | chengyu | duanju | wenzhang
variant: 500 | 3500 | 1000 | medical | computer | shi | 200 | 10 | para | essay
```

| 示例 | 释义 |
|---|---|
| `zh-quanpin-zi-500` | 全拼 · 常用 500 字 |
| `zh-flypy-chengyu-500` | 小鹤 · 500 成语 |
| `zh-flypy-duanju-200` | 小鹤 · 200 短句 |
| `en-article-para` | 英语 · 段落 |

**文件路径**：`public/dicts/zh/<id 去掉 zh- 前缀>.json`（继承 `基线 04` §12.1）。例：`public/dicts/zh/flypy-zi-500.json`。

**DATA-04（为什么要有 `zh-duanju-200` 与 `zh-flypy-duanju-200` 两份）**：短句与文章的**汉字内容相同**，只是编码不同。构建脚本**从同一份语料源生成两个 JSON**（同一份 `src`，两次编码）。卡片侧（`03` GAL-12）按当前方案取对应文件，不重复展示卡片。

## 3. 构建管线（DATA-10 ~ DATA-14）

### 3.1 分两阶段：先「语料源」，后「编码生成」

```
src/corpus/zh/
├── zi-500.txt              # 每行一个汉字（按字频排序）
├── zi-3500.txt
├── ci-1000.txt             # 每行 `词|拼音`（拼音按词读音，人工/半自动标注）
├── ci-medical.txt          # 每行 `术语|拼音`
├── ci-computer.txt
├── chengyu-500.txt         # 每行 `成语|拼音`，无释义
├── duanju-200.txt          # 每行一句（我方原创），拼音由脚本生成
├── wenzhang-shi.txt        # 空行分段：`### 篇名` + 正文
└── wenzhang-baihua.txt

src/corpus/en/
├── para.txt                # 空行分段
└── essay.txt
```

**DATA-10（语料源的格式）**：统一 UTF-8、无 BOM、`\n` 换行。**拼音可有可无**：

| 语料 | 拼音来源 | 理由 |
|---|---|---|
| 单字 | **脚本生成**（用 `pinyin-pro` 一次性批量转，取默认读音；多音字人工抽检 top 500） | 单字多音不影响「打字练习」的正确性（打「行」时 `xing`/`hang` 都是合法编码，接受两者即可，见 DATA-12） |
| 词 / 成语 | **必须人工标注**（`词|拼音`） | 「银行/行走」必须按词读音；`基线 04` §2.4 已列为 L2 主战场 |
| 短句 / 文章 | 脚本生成 + 人工抽检 | 全句多音字错误影响小（用户打的是编码，不是读音） |

**DATA-11（`pinyin-pro` 的位置）**：**只进 `devDependencies`**，只在 `scripts/build-typing-dicts.ts` 里 `import`。**运行时 bundle 不得包含它**（构建后检查 `build/assets/*.js` 不含 `pinyin-pro` 字样）。

### 3.2 编码生成（DATA-12）

```ts
// scripts/build-typing-dicts.ts（示意，非完整实现）
import { pinyin } from 'pinyin-pro'          // devDep
import { flypyEncode } from './schemes/flypy' // 我方按 基线 A1 §2 编写

type Item = { hanzi: string; pinyin: string[] }

/** 双拼：逐字 2 键 */
function encodeFlypy(py: string): string {
  const initial = py.match(/^(zh|ch|sh|[bpmfdtnlgkhjqxrzcsyw])/)?.[0] ?? ''
  const final = py.slice(initial.length)
  return flypyInitialKey(initial) + flypyFinalKey(final)   // 按 A1 §2.1 / §2.2
}

/** 全拼：去声调字母 */
const encodeQuanpin = (py: string) => py.replace(/[1-5]/g, '')

for (const item of items) {
  const codes = item.pinyin.map((py) => scheme === 'flypy' ? encodeFlypy(py) : encodeQuanpin(py))
  const accepted = buildAcceptedCodes(item)   // 零声母双字母 + 多音字
  out.push({
    name: codes.join(''),
    trans: [item.hanzi],
    usphone: '', ukphone: '',
    notation: item.hanzi,
    ...(accepted.length > 1 ? { acceptedCodes: accepted } : {}),
  })
}
```

**DATA-12-1（零声母规则，必须照 `基线 A1` §3.1 实现）**：

| 音节类型 | 规则 | 例 |
|---|---|---|
| 单字母韵母（a/o/e） | 零声母 + 韵母所在键 | 啊 = `aa`、哦 = `oo`、额 = `ee` |
| 双字母（ai/ei/ao/ou/an/en） | **α 口径：保留全拼**（主），β 口径（首字母 + 韵母键）作为 `acceptedCodes[1]` | 爱 = `ai`（主）/ `ad`（兼容） |
| 三字母（ang/eng） | 首字母 + 韵母所在键 | 昂 = `ah`、鞥 = `eg` |
| `er` | ⚠️ **待官方核对（`基线 A1` C-1）** → **暂按 `er` 输出，且该字不入第一版 500 字表** | 儿/二/耳 |

> 🔴 **DATA-12-2**：`er` 相关字（儿、二、耳、而、尔、饵…）**第一版直接排除**，等 `A1` C-1 关闭后再纳入。宁可少 6 个字，不可让用户练错。

**DATA-12-3（多音字策略）**：单字素材中的多音字（如「行」「重」「长」「调」「都」「为」）：

| 方案 | 说明 | 采用 |
|---|---|---|
| ① 只取默认读音 | 简单，但用户若按另一读音打就判错 | ❌ 会让用户困惑 |
| ② **`acceptedCodes` 收纳全部读音** | 编码串长度不同时**无法用单字段表达**（`hang` 2键 vs `xing` 2键，可行；但 `zhong`/`chong` 也可行）——双拼恒 2 键时完全可行 | ✅ **双拼采用** |
| ③ 全拼下长度不同（`hang` 4 vs `xing` 4，恰好同长；`le` 2 vs `yue` 3） | 长度不一致时无法用 `acceptedCodes` | 🟡 **按词读音取主读音，多音字单字素材在全拼下用 `|` 分隔展示备用读音**（显示为 `xing` 主 / `hang` 次，用户打任一均可通过） |

> ⚠️ **DATA-12-4（第一版的简化决策）**：为降低复杂度，**第一版单字素材中的多音字只保留主读音**，并在素材描述里注明「多音字按常用读音练习」。**词/成语素材由人工标注拼音，天然避免了多音字歧义**。这与用户「第一版先跑通」的诉求一致；完整多音字方案随 `基线 04` §7 的黄金用例集一同交付。

| 打字模式的练习记录存哪？ | **沿用现有的 `wordRecords` / `chapterRecords`**，无需新增表、无需新字段 |

| 需要 `version(4)` 吗？ | ❌ **不需要**。`基线 01` CN-J6 规划的 `track` / `schemeId` 字段属于**后续批次**（配合双轨指标），本批次不做 |

**DATA-16-1（为什么不加字段）**：给 `chapterRecords` 加字段需要写 Dexie 迁移；而 `基线 01` CN-J6 的迁移方案**已经规划好了 `track` + `schemeId` 两个字段**。本批次若自行加一套字段，会与后续批次冲突（两套 schema 迁移）。**因此本批次选择「先接受统计混算，把字段留给统一迁移」**。

### 5.1 已知局限（**必须在 Spec 中明示，不得隐瞒**）

| 局限 | 影响 | 缓解 |
|---|---|---|
| 打字模式的章节成绩会进入学习模式的 `chapterRecords` | Analysis 页的「总时长 / 总字数 / 打卡热力图」会包含打字模式的量 | ✅ **打卡热力图合并计算是合理的**（它衡量「今天有没有练」）。⚠️ **但「平均 WPM」会被中文练习拉低/拉高**（口径不同：字/分 vs 词/分） |
| 缓解手段（本批次采用） | ✅ **利用已有字段做只读过滤**，**零 schema 变更** |

> ✅ **DATA-17（已核对，结论确定）**：`src/utils/db/record.ts` 的 `ChapterRecord` **已经存有 `dict: string` 字段**（第 71 行）：

```ts
export class ChapterRecord {
  dict: string          // ← 现成字段，存的就是词典 id
  chapter: number | null
  timeStamp: number
  time: number
  correctCount: number
  wrongCount: number
  wordCount: number
  correctWordIndexes: number[]
  wordNumber: number
  wordRecordIds: number[]
}
```

> **因此实现方案确定为**：
> 1. 打字模式保存记录时，`dict` 写**素材 id**（如 `zh-flypy-zi-500`）—— 这本来就是它的「词典」；
> 2. **不改表结构**，`saveChapterRecord` 的调用方式不变；
> 3. Analysis 页**只加一个筛选维度**：`dict.startsWith('zh-') || dict.startsWith('en-article-')` → 归类为「打字模式」。
> 4. **不得**为此新增 Dexie 字段或提升 schema 版本（把 `track` / `schemeId` 留给 `基线 01` CN-J6 的统一迁移）。
>
> ⚠️ 若 Analysis 页的改动成本高于预期（例如筛选逻辑分散在多处），**允许降级为「不做过滤，加一行小字提示」**，但**不得**为了「让统计干净」而改动 `ChapterRecord` 结构。
