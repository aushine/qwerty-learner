## 📌 TL;DR（一句话版）

在**现有 qwerty-learner（学习模式）完全不动的前提下**，于标题下方新增一个 hover 展开的入口，进入一个**新的并列模式「Typing Learner（打字模式）」**。打字模式沿用现有布局与样式（Header / WordPanel / Speed / 键盘图 / ResultScreen 的位置全部不变），但把「词典切换」换成「语言切换」，把「词库」换成「练习素材（字/词/成语/短句/文章）」，把「方案」换成「输入法（全拼/双拼-小鹤）」，并在练习内容下方**新增一块常驻键盘**，键上标注该键在当前方案下承载的声母/韵母。

**三句话讲清改动边界**：
1. **不是**「在原有页面里加语言分支」，**而是**新增一条独立模式 + 独立路由（`/typing`）。学习模式 `/` 的 380 个词典、发音、释义、默写、错词本**一行行为都不改变**。
2. **样式零自创**：入口下拉复用 `StartButton` 的 `useFloating + useHover` 展开范式；语言切换 Tab 复用 `LanguageTabSwitcher` 的 RadioGroup 下划线样式；素材分组复用 `DictTagSwitcher` 的胶囊按钮；素材卡片复用 `DictionaryWithoutCover`；键盘用现有 Tailwind 色板与 `my-card` 阴影。**只新增组件，不新造视觉语言**。
3. **第一版明确不做语音**：打字模式全站不加载有道发音源、不显示发音按钮、不渲染音标/释义区（替换为键盘区），`ctrl+J` 在打字模式改为「重放当前题目的编码提示」。

## 1. 背景：为什么要加「打字模式」而不是继续加词库

现网的 qwerty-learner 是「**单词学习器**」：`Word` 的数据形状是 `{name, trans, usphone, ukphone}`，页面核心是「看释义 → 打单词 → 记单词」。当把它用于**中文输入法打字训练**时，会出现三个结构性错配：

| # | 错配 | 具体表现 | 本批次的对策 |
|---|---|---|---|
| **1** | **练习单位不同** | 学习模式 = 一个「词」= 一个记忆单元；打字模式 = 一个「码」= 1~2 次击键，字/词/成语/短句的码长差异巨大 | 保留 `Word` 结构，但 `name` 字段语义改为「**该题在当前方案下的目标编码**」；汉字原文放 `notation`（复用现成字段，`Notation.tsx` 已存在） |
| **2** | **核心辅助物不同** | 学习模式最核心的辅助是**发音**（听音记形）；打字模式最核心的辅助是**键位图**（看键记码） | 打字模式用 `TypingKeyboard` 替换 `Phonetic` + `Translation` 的纵向占位 |
| **3** | **选择维度不同** | 学习模式选「哪个词库」（CET-4 / 考研 / 医学英语…）；打字模式先选「哪种语言」，再选「输入法」，最后选「练什么素材」 | 三级选择：语言 Tab（2）→ 方案（全拼/双拼·小鹤）→ 素材（字/词/成语/短句/文章） |

> **为什么不做成同一页面的「语言分支」**：学习模式的页头是 `DictChapterButton`（词典切换 + 章节切换）+ `PronunciationSwitcher`（音色/音标），打字模式需要的是「语言切换 + 输入法 + 素材」，两组控件的数量、层级、语义都不同。硬塞进同一页会让两侧的控件树都变成条件分支，且练习状态（章节 index、计时器、错词记录）无法干净地按模式隔离。**并列两个模式、共用组件，是改动最小、回归风险最低的方案。**

| **输入方式（方案）** | 中文下的编码方案：**全拼 `quanpin`** / **双拼 `flypy`（小鹤）**。第一版只做这两个 |
| **素材（material）** | 打字模式里被练习的内容集合，取代学习模式的「词库」。中文 5 类：字 / 词 / 成语 / 短句 / 文章；英语 2 类：段落 / 文章 |
| **目标编码** | 当前题在当前方案下的应按键序列（双拼恒 2 键/字；全拼 = 该字全拼字母） |
| **题面** | 练习页中央的显示单元 = 目标编码（大字）+ 汉字原文（注音行） |
| **输入键盘** | `TypingKeyboard`，完整 QWERTY + 每键的声母/韵母标注，练习页常驻 |
| **方案键位图** | 基线的 `SchemeKeyboard`，纯字母键面（26 键）用于学方案。**与本批次的输入键盘是两个组件** |
