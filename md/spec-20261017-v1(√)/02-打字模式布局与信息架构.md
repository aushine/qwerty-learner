## 1. 背景与目标

### 1.1 背景

用户明确要求：**「沿用现有学习模式布局、样式，不要自创样式，保持风格统一」**。因此打字模式的页面不是重新设计，而是**对现有练习页做一次「等价替换」**——位置不动、容器不动、间距不动，只把「单词相关的东西」换成「打字相关的东西」。

### 1.2 目标

| # | 目标 |
|---|---|
| G1 | 打字模式页面与学习模式页面的**骨架完全一致**（同样的 Header、同样的中央练习区、同样的指标条、同样的底部） |
| G2 | 学习模式里「为记单词服务」而与打字无关的功能**全部移除**（语音、音标、释义等） |
| G3 | 移除的位置由**键盘**接管，形成「题面在上、键盘在下」的上下结构 |
| G4 | 用户从学习模式切过来**认得出这是同一个产品**（颜色、圆角、阴影、字号、间距全部来自现有类） |

### 1.3 非目标

- ❌ 不新增配色、不改 `tailwind.config.js` 的色板
- ❌ 不引入新的 UI 库（只用现有的 headlessui / Radix / floating-ui）
- ❌ 不重排 Header 右侧功能条的位置顺序（增减项见 §5）

### 3.2 纵向分区与高度分配（**这是本批次最需要注意的布局约束**）

`Layout` 是 `h-screen` 且 `overflow` 默认，页面**不滚动**。学习模式在「48px 单词 + 音标 + 释义」的纵向高度内已占满。加入键盘后必须重新分配：

| 区块 | 学习模式（现状） | 打字模式（目标） | 说明 |
|---|---|---|---|
| Header | 自动高度（~136px） | **相同** | 不动 |
| `Speed` | 自动 | **相同** | 不动 |
| `WordPanel` 中目录预览带 | `h-24 pt-10` | **`h-12 pt-2`**（LAY-02） | 键盘占位后需让出空间 |
| 题面（目标编码） | 48px 单行 | **40px（`text-[40px]`）单行** | 见 LAY-03 |
| 汉字原文行 | 无（原为音标 `Phonetic`） | **`text-lg`（18px）单行** | 复用 `Notation` 的位置 |
| 辅助物（音标+释义） | 音标 + 释义，约 60~80px | **键盘，约 200~220px** | 见 `04` |
| `Progress` | `mb-10 mt-auto` | **`mb-3 mt-auto`** | 让出底部 |
| Footer | 自动 | 相同 | 不动 |

**LAY-01（容器的水平宽度）**：题面与键盘都在 `container` 内居中；**键盘宽度 = `w-[720px]`，小屏按 `max-w-[92vw]`**。不得让键盘宽度超过 Header 的 `container` 可视宽度。

> ⚠️ **为什么是 720px**：QWERTY 的 10 键行在 `h-11 w-11` 且 `gap-1.5` 时总宽 ≈ 10×44 + 9×6 = 494px；加第 1 行（数字行 13 键）会到 ≈ 650px；再加左/右功能键列 → 720px 是「能放下完整键盘且不显得过宽」的值。**具体尺寸见 `04` §3，本节只锁总宽。**

**LAY-02（目录预览带压缩）**：`PrevAndNextWord` 在学习模式是 `h-24 px-12 pt-10`。打字模式下若保留，容器高度降为 `h-12 px-12 pt-2`；若不保留（见 KEEP-09），该容器**置空但保留 12px 高度**以维持垂直节奏（避免题面跳位）。

**LAY-03（题面字号）**：

| 元素 | 类 | 说明 |
|---|---|---|
| 目标编码 | `font-mono font-normal text-[40px] leading-none tracking-[0.08em]` | **必须 `font-mono`**（与 `Letter.tsx` 一致）；双拼每字 2 键，`tracking` 拉开可读性 |
| 汉字原文 | `text-lg text-gray-400 dark:text-gray-50` | 复用 `Letter` 的 `normal` 态色值；**不得用 `text-2xl` 以上**，否则与 40px 编码抢视觉层级 |
| 已完成/未完成 | 完成 = `text-green-600 dark:text-green-400`；未完成 = `text-gray-600 dark:text-gray-50`；错误 = `text-red-600 dark:text-red-400` | **直接沿用 `Letter.tsx` 的 `stateClassNameMap`**，不自创色值 |

> 🔴 **LAY-04**：题面**逐字符着色**必须复用 `Letter.tsx` 的三态色板（`normal/correct/wrong`），**不得为中文另造一套颜色**。中文与英文同为 `font-mono`，字母间距在中文下不生效（无副作用）。

**LAY-05（多字练习的题面换行）**：成语（4 字 = 8 键）、短句（10-30 字 = 20-60 键）、文章（段落）的编码串会超出一行。

| 素材类型 | 每行最大字符数 | 行高 | 超出处理 |
|---|---|---|---|
| 单字（2 键）/ 词组（2-6 键） | 一行 | 单行 | — |
| 成语（8 键） | 一行 | 单行 | — |
| 短句（20-60 键） | **每行 24 键** | `leading-[1.35]` | `flex-wrap justify-center max-w-[640px]` |
| 文章（段落） | **每行 32 键** | `leading-[1.35]`，字号降为 `text-[28px]` | 最多显示 **6 行**，超出部分进度条与键盘区承载（**不滚动**，见 §7） |

**LAY-06（不滚动原则）**：整个打字模式页面**保持学习模式的「单屏不滚动」**（`h-screen`）。任何素材都必须在 `h-screen` 内显示完：
- 短句/文章的**超出部分不做滚动**，改为「**分段推进**」：当前行固定居中显示，已完成的字向上淡出（`opacity-40`），未开始的字向下淡出（`opacity-40`）。这样任何长度都只占 6 行。
- **不得**给练习区加 `overflow-y-auto`（会与 `Space`/翻页键冲突，且破坏「一屏专注」的现有体验）。

## 5. 打字模式的核心交互差异（与学习模式的关键差别）

### 5.1 题面判定模型（**最重要的一节**）

学习模式：`displayWord` = 单词字母，逐字母比对，**整词输错即回滚重打**。
打字模式：`displayWord` = **目标编码串**（如「中」在小鹤下是 `vs`），逐字符比对，**整题输错即回滚**。

| 规则 | 内容 |
|---|---|
| **判定单位** | **单个编码字符**（= 一次击键）。比对源：`acceptedCodes[0]`（主口径），兼容口径见 `本批次 05` DATA-06 |
| **前进方式** | **打对自动进下一字，不按空格**（基线的既定交互，`基线 02` §1.2） |
| **错误处理** | 打错 → 该题所有已打字符标红 → **300ms 后清空本题重打**（复用现有 `setTimeout(...,300)` 的整词回滚逻辑） |
| **题目完成** | 编码串全部打完 → `isFinished` → `saveWordRecord` → `onFinish`（同现有） |
| **大小写** | **忽略大小写**（`isIgnoreCase` 语义沿用；双拼一律小写输入，但用户若开了 CapsLock 不应判错） |

> 🔴 **LAY-07（关键陷阱）**：**不得用「首键是否等于声母字母」来推断方案**。反例：全拼下「你」= `ni`，小鹤下 `n` 是声母、`i` 是韵母键，同样是 `ni`；全拼「米」= `mi`，小鹤 `ms`。因此**方案（`schemeId`）必须是显式状态**，由 `typingSchemeAtom` 决定用哪份编码，**绝不做运行时推断**。

### 5.2 输入捕获（对码轨）

| 项 | 规格 |
|---|---|
| 捕获方式 | 沿用基线决策（`基线 02` §1.2）：`<input type="password" autocomplete="new-password">` 隐藏元素 + `keydown` 取 `e.code` 映射 `KeyA~KeyZ` |
| 为何是 password | 强制关闭系统 IME；**打字模式的练习目标就是「键位」，不能被候选窗干扰** |
| 接受的键 | **仅 `KeyA`~`KeyZ`**（小鹤不使用分号键，见 `基线 A1` §2.2 的 `;` 行）；其余键**忽略且不报错** |
| 焦点 | 同 `TextAreaHandler` 的焦点管理模式：`isTyping` 时 focus，`onBlur` 自动夺回 |
| IME 误入 | 若检测到 `e.key === 'Process'` 或 `compositionstart`，**非阻塞提示**「请切换到英文输入法」（禁止 `alert`） |

> 🟠 **LAY-08（风险已知，本批次接受）**：上述方案依赖「password 框强制英文态」，属基线 Spike S1 的验证范围。**若 Spike S1 未通过**，本批次的降级方案为：改为 `Tab`/`点击键盘` 输入（键盘组件已规划点击输入，见 `04` KB-16）。

### 5.3 「字/分」口径修正

| 场景 | 现有 `wpm` | 打字模式展示 |
|---|---|---|
| 中文单字素材（1 题 = 1 字 = 1 编码） | `题数/分钟` | 直接等于字/分 ✅ |
| 中文词组/成语/短句/文章（1 题 = N 字） | `题数/分钟` **≠ 字/分** | 🔴 **必须另算**：`字/分 = 已完成字数 / 用时 × 60`，`已完成字数` = 当前题已通过的字数累加（**按 `notation` 的汉字计数，不含标点**） |
| 英语段落/文章 | `题数/分钟` | 单词量按**空格分词**计数 |

**LAY-09**：实现上**不修改**学习模式的 `wpm` getter；在打字模式侧用一个**派生值** `typingCharsPerMinute` 展示。**不得重写 `ChapterRecord.wpm`**（基线 `02` §1.3 明确禁止复用该口径做中文指标）。

### 5.4 开始/暂停（沿用状态机）

直接复用现有行为，不新建状态机：

| 状态 | 进入 | 行为 |
|---|---|---|
| 未开始 | 页面加载 / 暂停 | 题面上覆盖 `backdrop-blur-sm` + 「按任意键开始」文案（**现有实现**，保持） |
| 进行中 | 按任意合法键 / 点 Start | 计时器启动（现有 `TICK_TIMER`） |
| 暂停 | `Esc` / `window blur` / 点 Start | 同上，覆盖层再现 |

> 现有 `Typing/index.tsx` 的「按任意键开始」监听 `window keydown`，打字模式**沿用**；但需把 `'Process'` 加入 `bannedKeys`（基线 `02` §11.2 已提出，本批次在打字模式侧必须生效）。

## 8. 字体与语言标记

| 项 | 规格 |
|---|---|
| 题面 `lang` | 中文素材：`lang="zh"`；英语素材：`lang="en"`。理由：`lang` 影响 CJK 字体回退与标点挤压（基线 CN-J5 已指出） |
| 编码 `lang` | 恒为 `lang="en"`（编码是拉丁字母，避免中文栈把字母渲染成全角观感） |
| 汉字原文 | `lang="zh"`，`text-lg`，行高 `leading-relaxed` |
| 数字 | 指标条复用现有，不做全角处理 |

> **LAY-12**：现有 `Word` 组件给根节点设置了 `lang={currentLanguageCategory !== 'code' ? currentLanguageCategory : 'en'}`。打字模式**新建** `TypingTarget`，按上表自行设置，**不依赖** `currentLanguageCategory`（该字段在本批次不改联合类型，见 `00` §4.2 S-3）。

| 断点 | 行为 |
